# IPO 3기업 B 파일럿

이 폴더는 HD현대마린솔루션·멜콘·디티에스의 공개 투자설명서를 GPT-6.1 Terra로 검토하는 개발용 파일럿이다. 전체 실험 중 B, 즉 순서가 정해진 방식을 구현했다. 세 기업의 실제 답변과 AI 보조 채점 기록을 보존한다. A0·A1, 독립된 사람 채점, 최종 평가 표본의 실행은 아직 하지 않았다.

현재 설정은 `0.2.1-pilot`이다. 멜콘과 디티에스는 이 설정으로 각각 실제 답변을 제출했으며 최종 상태는 `PENDING_INFO`다. [3기업 결과와 세 차례 검증](reports/3기업_파일럿_확장_검증기록.md)에 점수·비용·남은 문제를 정리했다. 기존 HDMS 답변은 아래의 과거 설정 그대로 보존하므로 세 점수를 같은 설정의 통제 비교로 해석하지 않는다.

**GPT-6.1 Terra의 실제 HDMS 답변 한 편을 받아 제출까지 마쳤다.** 최종 버전은 `0.1.4-pilot`, 실행 번호는 `20261111T233807Z_B_2db53c6b`다. [실제 답변](runs/20261111T233807Z_B_2db53c6b/review.md)과 [구조화된 원본 결과](runs/20261111T233807Z_B_2db53c6b/review.json)를 볼 수 있다. 단계별 세 차례 점검과 개발 실패 이력은 [작업기록](reports/작업기록.md), 전체 후속 계획은 [상세계획](../whole%20plan/IPO_후속작업_상세계획.md)에 있다.

처음 읽을 때는 [첫 답변을 쉽게 풀어쓴 설명](reports/HDMS_B_첫답변_설명.md)에서 무엇을 계산했고 어떤 판단과 미확인 사항을 남겼는지 볼 수 있다.

## 어떤 순서로 실행하는가

1. 허용한 투자설명서의 파일 확인값, 공개 날짜와 페이지 수를 확인한다.
2. 이익, 비교기업, 주식수, 사업 구성, 평가가액을 찾는 다섯 검색 문구를 정해진 순서로 사용한다. 각 검색에서 상위 세 쪽과 그 앞뒤 한 쪽을 읽는다. 페이지를 임의로 잘라 보내지 않는다.
3. Terra가 공시의 숫자·단위·기간·원문 위치를 정해진 칸에 적는다.
4. 프로그램이 그 숫자로 주식수와 평가가액을 다시 계산하고, 평균·중앙값·비교기업을 하나씩 제외하는 대안을 계산한다. 대안은 비교용 계산이며 실제 공시 사실과 구별한다.
5. Terra가 적용 이익, 비교기업, 계산 대안, 남은 확인사항을 J1~J4 순서로 검토한다.
6. 제출 형식과 출처 ID 연결을 확인한 뒤 JSON과 사람이 읽을 Markdown을 저장한다. 정보 요청이나 사람 검토 요청은 기록하며 실제 메시지를 보내지는 않는다.

검색과 계산 순서는 Python 코드가 정한다. 로그의 `actor=program_fixed`는 프로그램이 실행한 행동이라는 뜻이다. 모델이 자율적으로 도구를 선택한 것처럼 기록하지 않는다. 보통 모델 요청은 숫자 추출과 검토 의견 작성의 두 번이다. 공통 형식에 문제가 있을 때만 전체 실행에서 한 번 고칠 수 있다. 출처 ID만 문제라면 해당 ID 문자열만, 메모 개수만 문제라면 메모만 수정한다. 나머지 본문·수치·출처 위치·상태는 보존한다. 사실이나 정답을 자동으로 고쳐 주는 과정은 없다.

## 준비와 실행

프로젝트의 `ipo_agent_eval` 폴더에서 PowerShell로 실행한다. Python 3.11 이상이 필요하다.

```powershell
python -m pip install -e ".[test]"
python -m pytest -q
python -m ipo_eval.runner
```

마지막 명령은 기본 사례인 HDMS의 무료 사전 점검이다. API를 호출하지 않는다. 다른 등록 사례를 선택할 수 있다.

```powershell
python -m ipo_eval.runner --case-id MELCON-DEV-01
python -m ipo_eval.runner --case-id DTS-DEV-01
```

실제 답변은 OpenAI API 키가 준비된 뒤 다음 명령으로 받는다.

```powershell
python -m ipo_eval.runner --case-id MELCON-DEV-01 --live
python -m ipo_eval.runner --case-id DTS-DEV-01 --live
```

인증값은 현재 프로세스의 `OPENAI_API_KEY`, `ipo_agent_eval/.env`, 프로젝트 최상위 `.env` 순서로 확인한다. `.env`에는 `OPENAI_API_KEY` 이름으로 값을 등록한다. Windows에서는 사용자·시스템 환경변수의 같은 이름도 확인한다. 키를 코드·문서·채팅에 붙이거나 저장소에 넣지 않는다. `.env`는 Git 추적 대상에서 제외하며 키는 로그에 저장하지 않는다. 현재 채팅의 답변이나 Codex 로그인 정보를 실험 응답으로 사용하는 기능도 없다.

계정이 `gpt-6.1-terra`를 사용할 수 있어야 한다. 최초 키는 인증이 거부되었으나 교체 후 정상 인증과 실제 모델 접근을 확인했다. 모델 접근이 거부되면 오류와 해당 실행 기록을 보존한다. 다른 모델로 자동 변경하거나 실패한 실행을 지우지 않는다.

## 저장되는 내용

실행마다 `runs/날짜_B_고유번호/` 폴더를 만든다. 날짜는 UTC이며 한국시간과 아홉 시간 차이가 난다.

| 파일 | 담는 내용 |
|---|---|
| `config.json`, `input_hashes.json` | 실행 설정과 코드·입력 파일을 식별하는 값 |
| `events.jsonl` | 검색·열람·계산·형식 확인·실패를 실제 발생한 순서대로 저장한 기록 |
| `source_packet.json` | 그 실행에서 모델에게 전달할 공개 문서와 실제로 읽은 페이지 |
| `01_extract_request.json` 등의 요청 파일 | 실제 API에 보내는 지시와 공개 입력. 인증값은 저장하지 않는다. |
| `01_extract_response.json` 등의 응답 파일 | 모델 이름, 응답 ID, 사용량을 포함한 API 원본 응답 |
| `extraction.json`, `calculations.json` | 모델이 찾은 입력과 프로그램이 계산한 결과 |
| `review.json`, `review.md` | 유효한 제출을 받았을 때만 만드는 검토 답변 |
| `summary.json` | 실행 여부, 제출 상태, 호출 횟수와 사용량 기준 비용 추정 |

API 키가 없으면 `NOT_STARTED_MISSING_API_KEY`로 기록한다. 이때 모델 호출과 비용은 0이고, 최종 검토 상태는 정하지 않는다. 무료 점검은 `PREFLIGHT_COMPLETE`다. 이 둘은 실험 답변도, 모델 실패 사례도 아니다. 실제 모델 실행이 시작된 뒤 유효한 제출을 받지 못한 경우에는 `FAILED`로 남긴다.

`READY`는 필요한 형식을 갖추고 완료를 막는 요청을 표시하지 않았다는 뜻이다. 답이 맞다는 뜻은 아니다. 사실과 판단의 품질은 이후 규리가 별도로 채점한다.

## 입력을 어떻게 제한하는가

프로그램은 `config/cases.json`에서 선택한 공개 폴더의 지정된 세 목록 파일과 `manual.md`만 입력으로 읽는다. HDMS는 기존 `data/public`, 신규 사례는 `data/cases/<case_id>/public`을 사용한다. 임의 경로는 선택할 수 없다. 검색은 해당 사례에 등록되고 자료 마감 전에 공개된 공시 안에서만 한다. PDF 원본의 SHA256도 확인한다. 실행 중 인터넷 검색, 채점표 열람, 기존 대화 전달, 다른 파일을 찾는 기능은 없다. 최신 DART 화면에 붙어 있는 사후 공시 링크도 입력으로 전달하지 않는다.

신규 두 사례의 공통 방법서는 `data/methods/IPO_PER_B_v0.2.md`다. 기존 HDMS 입력과 실행 원본을 보존한 상태에서 `scripts/prepare_case.py --case-id ...`로 새 사례를 준비한다. 이 준비 도구는 기존 출력과 다른 내용을 덮어쓰지 않는다. 과거 `prepare_hdms.py`는 역사적 준비 스크립트이며 기존 HDMS 입력을 다시 만들 목적으로 임의 재실행하지 않는다.

표는 PDF의 페이지 전체를 글자로 추출했다. `page`는 첫 장부터 세는 실제 PDF 쪽 번호이고, `printed_page`는 문서 바닥에 인쇄된 번호다. 글자의 색과 굵기는 텍스트에서 사라진다. 정정 전·후 구분, 표의 단위와 앞뒤 페이지를 모델이 읽어야 하며, 이 단계의 추출 정확성을 보장하는 것은 아니다.

## 비용과 실행 상한

`config/B.json`에 모델과 검색 문구, 제한을 저장한다. 현재는 모델 호출 16회, 도구 호출 40회, 누적 입력 목표 160,000토큰, 누적 출력 16,000토큰, 600초를 넘기지 않도록 제어한다. 새 답변을 받기 전 멜콘 원문 크기에 따라 입력 목표만 변경했으며 [변경 이유와 적용 범위](reports/pilot_multicase_budget_change.md)를 남겼다. 출력에는 추론 토큰도 포함된다. 입력량은 전송 전에 `o200k_base`로 추정하고 실제 사용량이 돌아오면 그 값으로 누적한다. 이 추정기가 Terra의 실제 토큰 수와 정확히 같다는 보장은 없다.

형식을 고치는 호출에 입력 16,000토큰을 따로 남겨 둔다. 형식수정 때에는 원문 전체를 다시 보내지 않고 수정할 부분과 허용 경로·ID 등 필요한 정보만 보낸다. 한 실행의 사전 비용 제한은 0.30달러이며, 환산값은 예산용 1달러=1,400원을 쓴다. 원본 요약의 일반 입력 가정 견적과 별도로 캐시 쓰기·읽기를 반영한 사후 비용을 [사용비용](reports/사용비용.md)에 계산했다. 최종 성공 한 건은 약 237원, 사용량이 확인된 개발 실패까지 포함한 합계는 약 983원이다. 청구서 금액은 아니며 인증 실패 한 요청의 사용량은 미확인으로 남겼다.

현재 요금과 모델·출력 형식은 [Terra 공식 문서](https://developers.openai.com/api/docs/models/gpt-6.1-terra)와 [구조화된 출력 문서](https://developers.openai.com/api/docs/guides/structured-outputs)를 2026-11-13 재확인했다. 위 사용비용 문서의 수치는 기존 HDMS 개발 실행 범위다. 새 두 실행의 캐시 반영 비용은 3기업 검증 기록에서 별도로 집계한다. 전체 연구 예산은 변경된 입력 목표와 실제 사용량을 반영해 최종 평가 전에 다시 산정한다.

## 남은 일

세 개발 사례의 실제 답변과 AI 보조 채점까지 진행했다. 다음은 주식수 구성의 의무인수·추가인수·옵션 포함 여부를 별도 입력으로 표현하고, 서술과 자동 계산의 충돌을 제출 전에 검증하는 일이다. 이후 고정 검색에서 빠진 자료의 추가 열람과 공시값·파생 계산값 구분을 보완한다. 이때 기존 답변과 점수는 덮어쓰지 않고 새 개발 버전으로 비교한다. 회귀 테스트 146개와 원문·계산 대조는 개발 점검이며 최종 평가나 독립 사람 채점을 대신하지 않는다.

2026년 11월 13일 사용자 요청으로 R001의 AI 대행 채점을 별도로 마쳤다. 사실 5/5, 계산 3/3, J1~J4 각 2점이며 현 기준의 방법론적 검토 충족률은 100%다. [대행 채점 결과](grading_exports/HDMS_R001_대행채점결과.docx)와 [세 차례 검증 기록](reports/R001_대행채점_검증기록.md)을 남겼다. 원본 답변과 기준은 보존했고, 규리의 직접 채점·확정이나 눈가림 채점으로 집계하지 않는다.
