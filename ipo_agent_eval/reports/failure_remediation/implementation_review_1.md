# 실패 보완 구현 1차 검토

검토자: root. 2026-11-13. 실 API 재실행 전 검토와 그 뒤 발견을 구분한다.

- compact 변환은 키·그룹·이미 열람한 chunk의 중복 좌표를 줄인다. 사실·선택·판단은 생성하지 않는다.
- B의 고정 경로와 A0의 모델 선택은 같은 gateway와 상한을 사용한다. A0에 상태별 다음 도구 지시나 자동 등록을 추가하지 않았다.
- 실제 등록된 UNRESOLVED selection으로 missing_inputs를 제한한다. 빈 목록은 업무 완료 판정이 아니다.
- 전체 JSON 재작성 대신 제한된 형식 patch를 적용한다. 수치·결론·상태·출처와 배열 변경을 거절하고 전체 한 번의 수정 한도를 유지한다.
- 관찰 예약에 envelope·현재 상태·상태 증가 예상 여유를 포함한다. 원문 페이지는 자르지 않으며 실제 요청 직전에 다시 검사한다.
- 일시적 HTTP 500/502/503/504만 같은 요청을 한 번 재시도한다. 각 시도를 기록하고 미확인 사용량의 입력·최대 출력·비용을 별도 예약한다.
- 초기 전체 377 tests 통과. 추가 경계 검증과 최종 수치는 후속 기록을 따른다.
- 기존 증거 1,847개와 수정 전 source snapshot 67개의 보존 검사에 위반은 없었다.

사전 검토는 실제 성공을 보증하지 않는다. DIAG_v040에서 MELCON B의 비교기준 표현 오류, A0의 등록 이후 입력 예산 부족, ALT B의 동적 스키마 공유 참조 결함이 추가로 드러났다. 특히 마지막 결함은 모델의 출처 조작이 아니라 실행기 오류였다. v0.4.0 사전 검토만으로 완료 판정할 수 없으며 v0.4.1 수정과 실제 재검증이 필요하다.

v0.4.1 수정: 동적 enum의 대상 leaf를 새 객체로 교체해 다른 문자열 schema와 분리했다. B도 fatal 격리 오류 직후 추가 repair API 없이 종료한다. 비교 가능한 CONTEXT의 정확한 표기와 DERIVATION 출력만의 선언을 공통 예시로 설명하고, 입력 80만·회당 최대 1.25달러의 새 조건을 별도 기록한다. 실제 값·비교 기준이 다르면 동일 표기를 강제하지 않는다.

v0.4.1 진단 4회는 등록·계산·민감도·제출까지 통과했지만, 전체 재검증에서 두 경계가 추가로 드러났다. MELCON A0는 한 번의 REGISTER_BATCH 생성에서 3,500토큰을 소진했다. MELCON B는 계산 결과 자체는 정상이었으나 USE와 unresolved=true를 함께 제출해 거절됐다. 진행 중인 요청을 완료한 뒤 배치를 중단했으며 실제 실행 5회와 미실행 7회를 구분해 보존했다.

v0.4.2에서는 탐색 한 응답 상한을 기존 B 추출과 같은 9,000으로 늘린다. 전체 출력 24,000·입력 800,000·회당 1.25달러 상한은 유지한다. USE/REJECT의 기존 불변조건을 생성 스키마에 명시해 모순된 조합을 생성 전에 막는다. 모델이 어떤 계산을 사용할지와 업무상 미확인 판단은 유지하며, 이미 받은 답안의 boolean이나 사실을 자동 수정하지 않는다. 새로운 전체 12회 실행에서 재검증해야 한다.

같은 중단 배치의 DTS B는 제출에는 성공했으나, 직접·파생 분모를 모두 등록하고 주당 계산용 share_count 선택은 하지 않아 주당 계산이 불가했다. 계약 설명에 이 역할을 명시한다. 추가 코드 검토에서는 canonical 선택이 실제로 있어도 별도 alias 선택과 함께 세어 무시하는 결함을 찾았다. exact field의 명시 선택을 우선하고, 명시 선택이 미해결이면 그대로 미해결로 남긴다. exact 선택이 없을 때는 기존의 모호성 검사와 fallback을 유지한다. 프로그램이 fact를 새로 고르거나 과거 DTS 답변을 고쳐 쓰는 변경이 아니다.

**v0.4.2 사전 구현 1차 판정: PASS.** root는 계산 선택 분기, 공유 leaf를 바꾸지 않는 세 가지 생성 분기, 동일 총예산을 유지한 탐색 한도 변경을 코드와 교차 검토했다. `schema_probe_v042.json`의 실제 API 호환성 검사도 완료됐다(기업 자료 없는 synthetic 한 건, 입력 330·출력 62, 미확인 사용량 없음). 이는 제출 schema 수용 검증이며 기업 검토 성공 횟수에 포함하지 않는다. 전체 6기업 × 2조건의 실제 완료와 마지막 세 차례 종합 검토는 별도 단계다.

v0.4.2 전체 검증도 실제 시작 4회 뒤 중단했다. HDMS B는 제출했지만 반복 작성된 비교기준의 서로 다른 자유문구 때문에 핵심 주당 계산·민감도가 INVALID였고, MELCON B는 검토에서 추출 claim ID를 재정의하여 제출에 실패했다. 실제 3제출·1실패와 미실행 8회를 분리 보존했다. 성공한 두 A0 답안을 전체 배치의 성공으로 대신하지 않는다.

v0.4.3 코드 검토: compact_v2는 groups에 모델이 직접 선언한 기준일·범위·기준·공시 시점을 두고 context가 g로 참조한다. adapter는 네 문자열을 그대로 복원하고, unit·period·원래 레코드·수치·근거를 유지한다. 원래 CONTEXT의 정확히 같은 tuple만 encoder에서 공유하며, 유사 문구나 실제 다른 기준은 합치지 않는다. 유효한 미참조 group과 임의 group 이름은 raw wire에 보존하고 logical v2 동일성의 범위와 구분한다. 기존 엄격한 계산 검증은 유지한다.

최종 사실 선언은 기존 등록 claim ID와 충돌하지 않는 REVIEW_ 또는 REVIEW2_ 등의 접두어를 생성 schema에 명시한다. 모델은 처음부터 새 ID를 작성한다. evidence 참조·주장 본문·수치·판단을 자동 변경하지 않으며, 공용 S/ID schema에 패턴이 전파되지 않게 leaf를 교체한다. B/A0 runner와 gateway가 동일 wire 버전을 쓰는지, synthetic 예시가 같은 logical payload를 복원하는지 확인했다. 새 전체 테스트와 2·3차 검토 후 12회 실제 실행으로 다시 검증한다.

**v0.4.3 사전 구현 1차 판정: PASS.** 그룹 어댑터·runner·gateway·접두어 생성 분기와 원문 비교기준을 자동 추론하지 않는 경계를 검토했다. 독립 검토의 원자성·형식수정·예산·격리 검사도 확인했다. 테스트 도우미의 구형 method signature와 wire fixture를 수정한 뒤 전체 검사를 다시 수행하며, 이 도우미 실패를 실제 API 실패나 생산 결함으로 집계하지 않는다. 실제 6기업 × 2조건 결과와 정량 내용 검토는 별도로 남긴다.
