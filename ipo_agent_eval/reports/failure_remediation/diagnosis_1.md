# 실패 원인 1차 검토

검토자: root. 2026-11-13. 보존된 v032 실행과 raw usage, 응답, tool event를 검토했다.

1. B 6회는 추출 출력 한도 5,000에 도달했다. ALT·MILLIE에는 긴 공백 반복도 있었다. 스키마가 API에서 금지된다는 근거는 없으며, 공백 반복의 모델 내부 원인은 단정하지 않는다.
2. A0 6회는 검색·열람 후 입력 예약 한도에서 최종화됐고 등록·계산은 없었다. 모델에는 누적 입력·시간·비용·최종화 예약을 포함한 상태가 충분히 전달되지 않았다. 모델이 검색을 선택한 내부 이유와는 구분한다.
3. 빈 snapshot에는 등록된 UNRESOLVED 의존성이 없는데 최종 답변이 업무상 미확인을 missing_inputs에 넣어 검증에 실패했다. 다른 미확인은 unknowns·요청에 남겨야 한다.
4. 긴 답안 전체를 2,500토큰으로 다시 쓰는 형식수정도 절단됐다. 사실·결론을 바꾸지 않는 부분 수정이 필요하다.
5. HTTP 500은 서비스 오류이며 잔액 부족을 보여주는 insufficient_quota 오류는 확인하지 못했다. 네트워크 실패 요청의 사용량은 미확인으로 보존한다.

조치 방향은 공통 계약 압축, 정확한 상태 제공, 동적 제출 계약, 의미 불변 patch, 기록되는 제한 재시도와 새 공통 상한이다. 기존 실험 결과·gold는 보존한다. 변경 효과는 새로운 개발 조건의 결과로만 해석하고, 최종 비교·정답 성능은 실제 실행으로 별도 확인한다.
