# A0 예비실험 3폼과 보정 4폼 준비 점검

2026-11-24. 최초 예비실험은 원본·카나리·정상 대조로 3개 세션을 만든다. 보정은 원본·카나리 1·카나리 2·정상 대조로 4개 세션을 만든다. 두 구성을 각각 합성한 신고서와 공통 후보 근거 PDF 한 벌로 검증했다. 모델 호출과 실제 기업 자료 제출은 모두 0회였다.

| 점검 | 확인한 항목 | 결과 |
|---|---|---|
| 1. 자료 적격성 | 공개시점과 선공개 증빙, 해시, 구성 누락·초과, 중복 경로·바이트·추출 본문, 카나리 대상·하위 유형 충돌을 확인 | 합성 테스트 16건 통과 |
| 2. 입력 격리 | 3폼과 4폼에서 기업 자료·문서 ID·주소·프롬프트·매뉴얼·모델 설정의 동일성 확인. 바뀌는 파일은 신고서 PDF와 그 문서·본문 색인뿐. 명시적 시험 표식과 보관 자료 변조 탐지 | 합성 테스트 6건 통과 |
| 3. 실행·재개 | 자료마다 새 세션 사용, 재개 시 기존 결과 재사용, 같은 입력을 사용한 기술적 실패 재시도 상한, 키 미설정 시 중단과 기록 확인 | 합성 테스트 5건 통과 |

네트워크 소켓을 차단하고 기존 A0 실행기와 설치된 토크나이저로 기본 CLI를 구성별 두 번 실행했다. 첫 실행은 각각 3/3, 4/4를 완료했고, 두 번째 실행은 각각 같은 실행 ID 3개와 4개를 재사용했다. 이때 씨앗값 77의 예비실험 순서는 정상 대조 → 카나리 → 원본, 보정 순서는 카나리 2 → 정상 대조 → 원본 → 카나리 1이었다.

운영자 매니페스트의 `forms`에서 예비실험은 `original`, `canary`, `control`을, 보정은 `original`, `canary_1`, `canary_2`, `control`을 사용한다. 각 항목은 파일 경로와 SHA-256을 갖는다. 보정 카나리는 같은 하위 유형의 서로 다른 대상에 배정한다. 매니페스트에 배정을 기록할 때는 두 카나리에 서로 다른 `target_id`와 동일한 `subtype`을 넣는다. 이 값은 운영자 매니페스트에만 보관한다. 사용자가 PDF의 표·본문·각주에서 배정 내용과 가림 상태를 확인한 뒤 해시를 고정한다.

사례명·발행사·공개 마감·순서 씨앗값, 공통 후보 근거의 경로·해시·출처·공개시점도 기록한다. 실행기는 폼 순서와 입력 해시를 고정하고, 세션마다 같은 중립 ID로 해당 폼과 공통 근거만 등록한다. 같은 날 자료의 선공개 증빙은 운영자가 보관한다. 이미 준비한 예비실험은 기존 매니페스트·저장 폴더로 재개한다. 보정에는 새 저장 폴더를 사용한다.

재현 명령은 `ipo_agent_eval`에서 실행한다.

```powershell
python -m pytest -q tests/test_a1_a0_preparation.py::TestProvenance
python -m pytest -q tests/test_a1_a0_preparation.py::TestIsolation
python -m pytest -q tests/test_a1_a0_preparation.py::TestExecution
python -m scripts.prepare_a1_a0 --help
python -m scripts.prepare_a1_a0 --manifest <운영자-매니페스트> --output <세션-저장-폴더>
```
