# HDMS 첫 B 프로그램을 준비하고 확인한 기록

2026년 11월 13일 추가: 사용자 요청으로 R001의 AI 대행 채점과 세 차례 검증을 별도 수행했다. [대행 채점 결과](../grading_exports/HDMS_R001_대행채점결과.docx)는 사실 5/5, 계산 3/3, J1~J4 각 2점이다. [검증 기록](R001_대행채점_검증기록.md)에 근거와 한계를 남겼다. 아래 11월 12일의 실행 기록은 당시 상태를 보존한 것이며, 이번 결과를 사람 평가자의 직접 채점·확정으로 바꾸어 기록하지 않는다.

작성일은 2026년 11월 12일, 한국시간이다. 사용자가 요청한 범위는 HDMS 원문을 준비하고, 정해진 순서로 검토하는 B 프로그램을 만든 뒤, GPT-6.1 Terra의 실제 답변 한 편을 받는 데까지다. 이후 사람 채점과 다른 기업의 실험은 이번 범위에 넣지 않았다.

**HDMS의 실제 Terra 검토 답변 한 편을 받아 제출까지 마쳤다.** 최종 실행은 `20261111T233807Z_B_2db53c6b`, 버전은 `0.1.4-pilot`이다. 모델 요청 두 번과 프로그램 기능 호출 15번을 사용했고, 형식수정 없이 123.509초에 끝났다. 모델과 프로그램이 정한 상태는 모두 `READY`다. [실제 답변](../runs/20261111T233807Z_B_2db53c6b/review.md), [원본 구조화 결과](../runs/20261111T233807Z_B_2db53c6b/review.json), [실행 요약](../runs/20261111T233807Z_B_2db53c6b/summary.json)을 보관했다.

처음 등록한 키는 인증이 거부되었으나 사용자가 교체한 뒤 정상 연결되었다. 개발 중 출력 분량과 제출 형식, 입력 구성 문제로 중단된 네 실행도 보존했다. 그 기록을 지우거나 성공한 실행으로 바꾸지 않았다. 실제 답변의 정식 점수 채점은 다음 단계다.

## 지금까지 만든 것

HDMS의 2024년 4월 24일 정정 투자설명서 PDF를 보관했다. 원문은 638쪽이며, 미리 기록된 SHA256과 일치했다. DART 접수번호와 정정 이력, PDF 정정표와 청약기간을 대조해 청약 시작 전에 공개된 버전임을 확인했다. 모든 쪽을 글자로 추출하여 검색할 수 있게 만들었고, 중요한 표와 주석이 있는 여덟 쪽은 이미지로도 확인했다.

B는 이익, 비교기업, 주식수, 사업 구성, 평가가액을 찾는 다섯 검색 문구를 정해진 순서로 사용한다. 각 검색에서 상위 세 쪽과 앞뒤 한 쪽을 읽는다. 중복을 빼면 현재 HDMS 입력에는 30쪽이 들어간다. 모델이 숫자와 출처를 추출하면 프로그램이 다시 계산하고, 모델은 그 결과와 원문을 보고 J1~J4 검토 의견을 적게 되어 있다.

계산은 소수 계산을 위한 Decimal을 사용한다. 주식수 합계, 공시 평가액을 주식수로 나눈 가격, 이익과 표시 배수를 곱한 가격, 비교기업의 평균·중앙값 등을 계산한다. 구주매출을 새 주식처럼 더하지 않는다. 표시된 숫자로 계산한 차이를 자동으로 공시 오류라고 판정하지 않는다. 대안 계산에는 무엇을 바꿨는지와 기준 가격을 함께 남긴다.

모델 요청, 원본 응답, 계산, 근거, 정보 요청, 사용량을 실행별 폴더에 저장한다. 채점표나 이 채팅의 내용은 모델에게 전달하지 않는다. 정보 요청과 사람 검토 요청은 기록만 하며 회사나 사람에게 메시지를 보내지 않는다. 유효한 제출을 실제로 받았을 때에만 `review.json`과 `review.md`를 만든다.

## 점검 중에 바꾼 부분

처음에는 숫자 칸에 빈 문자열이나 `NaN`이 들어가도 형식 검사를 통과할 수 있었다. 이제 유한한 십진수 문자열인지, 각 칸이 백만원·배·원·주 중 지정된 단위를 사용하는지 확인한다. 값이 없는 경우에는 왜 없는지와 어느 추가 확인 요청에 연결되는지를 요구한다. 숫자가 공시와 같은지는 이후 채점할 내용으로 남긴다.

판단에 `REQUEST_INFO`나 `ESCALATE`라고 적고 실제 요청을 비워 두는 경우도 막았다. 요청에 연결된 판단 ID와 해결 근거를 확인한다. 완료를 막는 미해결 사람 검토 요청이 있으면 `HUMAN_REVIEW`, 미해결 정보 요청이면 `PENDING_INFO`로 프로그램이 상태를 정한다. 이 상태는 정답 여부와 별개다.

형식을 고칠 때 원문 전체를 다시 보내면 입력 예산이 부족할 수 있었다. 수정 호출에 16,000토큰을 남겨 두고, 그 호출에는 이전 출력·구조 오류·출처 위치 목록만 보내도록 바꿨다. 새로운 사실을 찾아 채우는 단계로 만들지 않았다.

사업 구성 검색에서는 넓은 표현만 쓰면 다른 문맥이 먼저 나올 수 있었다. 기업명이나 정답 숫자를 검색어에 넣는 대신, 공시에 일반적으로 쓰는 ‘비교회사’, ‘주요 사업’, ‘매출구성’, ‘매출비중’, ‘제품’으로 문구를 구체화했다. 검색 문구와 순위 규칙은 파일에 남겨 이후 비교에서도 확인할 수 있게 했다.

사람이 읽을 Markdown에도 판단의 근거와 반대 근거를 모두 넣었다. 계산 항목마다 입력의 단위·기간·출처를 연결하여, JSON 안에서 계산과 원문을 함께 따라갈 수 있게 했다.

## 실제로 실행한 검사

`python -m pytest -q`에서 현재 **103개 테스트가 통과**했다. 계산 검사 39개, 식별자 수정 검사 22개, 비용 검사 16개와 실행 연결 검사 26개다. 자료 제한·형식·상태·실행 순서·실패 보존·예산·SDK 요청 구성·`.env` 읽기도 확인한다. 모의 API는 임시 시험 폴더 안에서만 사용하며 실제 HDMS 결과 폴더에 가짜 답변을 남기지 않았다.

Python 컴파일 확인도 통과했다. Ruff의 실행 오류 관련 검사 `E9,F63,F7,F82`도 통과했다. 외부의 넓은 스타일 설정을 적용한 별도 검사에서는 import 정렬과 광범위한 예외 처리 같은 스타일 지적이 있었으므로, 모든 스타일 규칙을 통과했다고 주장하지 않는다.

공개 자료 묶음의 전송 전 추정은 약 39,262토큰이었다. 최종 실제 실행에서 API가 반환한 누적 사용량은 입력 **93,434토큰**, 출력 **10,554토큰**이다. 출력에는 추론 토큰이 포함된다. 두 수치를 혼동하지 않는다.

캐시 쓰기·읽기까지 반영한 최종 성공 한 건의 견적은 **0.169561달러, 약 237.39원**이다. 사용량이 확인된 개발 실패 네 건을 포함하면 **0.70233635달러, 약 983.27원**이다. 원화는 예산용 환율 1달러=1,400원이며 청구서 금액은 아니다. 인증 실패 한 요청은 사용량이 반환되지 않아 별도 표시했다. [사용비용](사용비용.md)에 응답별 계산과 전체 합계, 세 차례 검산을 남겼다. 기존 실행 요약의 일반 입력 가정 견적은 원본 그대로 보존하고 캐시 반영 견적을 별도로 계산했다.
