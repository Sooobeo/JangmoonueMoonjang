# 계산 기능을 확인한 기록

작성일: 2026-11-12

이 기록은 첫 B 프로그램에서 사용할 계산 기능을 개발하면서 스스로 확인한 내용이다. AI 답변을 채점한 결과나 연구의 평가자 수에 포함되는 검토가 아니다. 실제 HDMS 답변에 필요한 숫자는 실행 중 AI가 공개 자료에서 찾아 전달해야 한다. 아래 확인에는 별도로 만든 가상의 숫자만 사용했다.

대상 파일은 `ipo_eval/calculations.py`와 `tests/test_calculations.py`다. 외부 자료를 읽거나 모델을 호출하지 않으므로 이 확인에 API 비용은 들지 않았다.

## 첫 번째 확인: 계산식과 단위가 맞는가

입력 금액은 백만원, 주식수는 주, 결과 가격은 주당 원으로 구분했다. 따라서 주식가치나 이익을 주식수로 나누어 가격을 구할 때는 백만을 곱한다. 예를 들어 가상의 이익이 50백만원이고 배수가 12배이며 주식수가 100만 주라면 가격은 600원이어야 한다. 이 예시로 단위 변환을 확인했다.

평가에 쓰는 주식수는 기존 주식, 새로 발행하는 주식, 희석을 고려해 추가하는 주식의 합으로 계산했다. 구주매출은 이미 발행된 주식의 소유자만 바뀌므로 더하지 않는다. 합계에 필요한 숫자가 빠져 있으면 0으로 대신 채우지 않는다.

비교기업 표에 적힌 배수의 평균과 시가총액을 이익으로 나누어 다시 구한 배수의 평균을 따로 계산했다. 공시된 가격과 계산한 가격의 차이도 숫자로 남긴다. 표시 자리수 때문에 차이가 생길 수 있으므로 차이가 있다는 사실만으로 공시 오류라고 판정하는 기능은 넣지 않았다.

민감도 계산의 기준은 **공시에 표시된 적용 배수로 다시 계산한 가격**이다. 그 기준과 비교기업 배수의 평균, 중앙값, 기업 한 곳을 제외한 평균을 각각 비교한다. 공시 가격 자체와 비교한 차이인 것처럼 보이지 않도록 결과 설명에 기준을 적었다. 어느 대안이 옳은지 추천하지 않고 계산상 가정임을 표시한다.

결과: 계산식, 단위, 비교 기준을 확인했다. 40자리 Decimal 연산을 사용하며 결과를 원 단위 정수로 미리 반올림하지 않는다. 연산 자리수와 반올림 방식은 각 결과에 함께 저장한다.

## 두 번째 확인: 빠지거나 잘못된 숫자를 안전하게 처리하는가

0인 주식수, 음수 주식수, 소수로 적힌 주식수, 0이나 음수 배수, 숫자가 아닌 값, 무한대, 0인 비교기업 이익, 잘못된 쉼표, 비어 있는 비교기업 목록을 넣어 보았다. 계산할 수 없는 경우 결과를 만들지 않고 `UNAVAILABLE` 또는 `INVALID`와 이유를 반환하는지 확인했다. 정상적인 천 단위 쉼표는 읽을 수 있게 했다.

일부 비교기업의 배수가 없거나 잘못되어도 그 기업을 조용히 빼고 평균을 내지 않도록 확인했다. 같은 이름의 비교기업이 중복되는 경우도 평균을 계산하지 않는다. 비교기업이 한 곳뿐이면 그 한 곳을 제외하는 대안은 만들 수 없다는 이유를 남긴다.

검토 중 구주매출 주식수가 음수여도 합계에서 제외되기 때문에 문제가 드러나지 않는 경우를 확인했다. 구주매출 주식수가 제공되었다면 음수나 소수가 아닌지 확인하도록 고쳤다. 구주매출 값 자체가 없을 때는 합계에 필요하지 않으므로 다른 세 항목만으로 주식수를 계산할 수 있다.

실행한 명령:

```powershell
cd ipo_agent_eval
python -m pytest tests/test_calculations.py -q
```

결과: 수정 후 **39개 테스트가 모두 통과**했다. 이는 매개변수별 실행을 포함한 개수다. 누락 입력을 0으로 바꾸지 않는지, 출력이 JSON으로 저장되는지, 함수가 입력을 변경하지 않는지도 포함했다.

## 세 번째 확인: 다른 계산 방법과 비교해도 결과가 같은가

가상의 사례 200개를 난수 시드 `20261112`로 만들었다. 이익, 주식수, 배수를 달리하면서 Python의 `Fraction`으로 분수를 그대로 계산한 결과와 비교했다. Decimal 코드와 다른 계산 방법을 사용해, 같은 구현을 복사한 테스트가 되지 않도록 했다.

이익과 배수로 계산한 가격, 비교기업 배수의 평균과 중앙값, 시가총액과 이익으로 다시 구한 배수의 평균, 기업 한 곳을 제외한 네 가지 가격을 비교했다. 모두 합해 **1,600개 비교가 통과**했다. 반복 소수는 40자리 연산에서 생길 수 있는 끝자리 차이만 허용했다. 가격과 평균 비교에는 상대 오차 `10^-38`, 기업별 제외 가격에는 `10^-37`을 사용했고, 1보다 작은 값에는 절대 오차로 같은 기준을 적용했다.

외부 코드가 Decimal의 기본 자리수나 반올림 방식을 바꿔도 이 모듈의 결과가 바뀌지 않는 테스트도 통과했다. 각 계산 안에서 연산 설정을 정하고, 결과를 문자열로 저장하기 때문이다.

마지막으로 소스 코드를 구문 분석해 `eval`, `exec`, 파일 열기, 동적 코드 실행이 없음을 확인했다. 모듈에는 사례 식별자나 HDMS의 정답 숫자를 넣지 않았으며, 파일·네트워크에 접근하는 기능도 없다. 빈 입력의 모든 계산에 누락 이유가 남고, 결과 전체가 엄격한 JSON으로 저장되는 것도 다시 확인했다.

결과: 계산 기능 자체의 세 차례 확인은 끝났다. 실제 공개 자료에서 올바른 숫자를 찾았는지, 그 숫자의 근거를 맞게 연결했는지, B 프로그램의 최종 답변에 계산 결과가 제대로 들어가는지는 실행기를 연결한 뒤 별도로 확인해야 한다.

## 실행기에서 사용하는 방식

`calculate(inputs)`는 `calculations` 배열과 `notes`를 반환한다. 배열의 각 항목은 계산 이름, 식, 사용한 입력값, 결과, 단위, 상태, 계산하지 못한 이유를 담는다.

`sensitivity(inputs)`는 `baseline`, `scenarios`, `notes`를 반환한다. 각 대안에는 적용 배수, 기준 가격과의 원 단위 차이, 비율 차이, 제외한 기업이 있을 경우 그 이름을 담는다. 기준 가격을 계산할 수 없으면 대안 가격이 계산되더라도 차이를 만들지 않는다.

숫자의 문서·페이지·표 위치는 호출하는 프로그램이 보관한다. 계산 기능은 받은 숫자를 임의로 수정하거나 출처를 만들어 내지 않는다.
