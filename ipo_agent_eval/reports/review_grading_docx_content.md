# 채점용 Word 문서의 내용 확인 기록

확인일: 2026년 11월 12일

대상 문서: `grading_exports/HDMS_R001_답변_채점자료.docx`

대조한 실제 실행: `20261111T233807Z_B_2db53c6b`

최종 확인 파일의 SHA-256: `24d5e1967f4de50173f74c9c196532f786a7a09fb6b5669829356b333a3d07c6`

이 기록은 채점 자료에 실제 질문과 답변, 숫자, 출처, 채점할 항목이 빠짐없이 들어갔는지 확인한 내용이다. AI 답변에 점수를 매기거나 정답이라고 판정한 기록은 아니다. Word 문서의 XML과 표를 읽었으며, 문서를 직접 수정하지 않았다. API 호출이나 인증정보 열람도 하지 않았다.

문서 작업용으로 지정된 관리형 Python과 `zipfile`, `lxml`, `python-docx`를 사용했다. 일반 시스템 Python이나 사용자 설치 LibreOffice를 사용하지 않았고 렌더링을 직접 시도하지 않았다. 내용 검사 이후에는 렌더링 담당자가 만든 `render_v3`의 41~65쪽을 원본 해상도로 직접 열어 시각 확인했다. 최종 `render_v4`의 같은 25쪽은 각 PNG의 파일 내용이 완전히 같음을 SHA-256으로 별도 확인했다. 그 결과를 아래에 추가했다. 1~40쪽의 시각 확인은 다른 담당자의 검토 범위다.

## 첫 번째 확인은 실제 답변이 보존되었는지였다

실행 폴더의 `review.json`에서 범위, 판단별 결론, 사실 문장, 미확인 사항, 다음 행동, 정보 요청의 질문과 이유, 사람 검토 요청의 문구, 메모를 읽었다. 이 가운데 실제로 존재하는 필드별 문자열 42개가 모두 문서에 들어 있었다. 비교할 때 문단 나눔과 공백만 무시했으며, 문장의 단어나 숫자를 바꾸어 같다고 인정하지 않았다.

실제 API 요청 파일 `01_extract_request.json`과 `02_review_request.json`의 과제 문장도 각각 완전히 보존되어 있었다. 두 요청의 공통 지시문도 모두 대조했다. 과제 두 개와 공통 지시문 두 개, 총 네 번의 문자열 대조가 통과했다.

최종 문서에는 추출 단계의 문서 버전 설명과 추출 한계 다섯 항목도 모두 들어 있다. 숫자만 보여 주면서 AI가 적은 조건이나 한계를 빼지 않았는지 확인하기 위한 점검이다.

## 두 번째 확인에서 찾은 빠진 값과 잘못된 안내를 보완했다

처음 검사한 파일에는 기업 한 곳씩을 제외하는 네 대안의 계산 가격과 차이는 있었지만, 그 계산에 쓴 적용 PER 값이 빠져 있었다. 문서 작성 담당자에게 해당 네 값을 알렸고, 담당자가 민감도 표에 적용 PER 열을 추가했다. 최종 파일에서는 네 값이 원래 계산 결과의 문자열 그대로 들어 있는 것을 다시 확인했다.

채점기준을 옮기는 과정에서 원래 기준표의 내부 절 번호가 남은 부분도 있었다. 현재 문서에 없는 `7절`과 `4.4절`을 찾아가라고 안내하는 문장이어서, 현재 문서의 계산 부분과 실제 부록 페이지를 가리키도록 보완을 요청했다. 최종 파일에서는 이전 절 번호가 사라지고 실제 위치를 안내하는 것을 확인했다.

F1의 원문 안내에는 적용 이익의 기간과 귀속에 관한 주석이 이어지는 PDF 332쪽도 필요했다. 최종 파일의 F1 안내는 인쇄 329~330쪽, PDF 331~332쪽으로 확장되었다. 이 수정은 답변의 내용을 고친 것이 아니라 채점자가 찾아갈 위치를 정확하게 표시한 것이다.

숫자는 천 단위 쉼표만 제거해 원래 값과 비교했다. 계산 결과 40개는 단순히 반올림한 값이 비슷한지를 본 것이 아니라, 저장된 Decimal 결과의 전체 문자열이 문서에 있는지 확인했다. 여기에는 기본 계산 15개, 민감도의 기준 가격 1개, 여섯 대안의 적용 배수·가격·가격 차이·차이 비율 24개가 포함된다.

실제 답변의 출처 38개는 문서 ID, PDF 물리 쪽수, 표 또는 문단 위치, 주장 ID를 한 묶음으로 대조했다. 문서에는 기계용 `chunk_id` 문자열을 반복하는 대신 사람이 찾을 수 있는 `HDMS-PROS-01 PDF ○쪽` 형식으로 표시되어 있다. 모든 출처가 같은 문서와 페이지를 가리키며, 표·문단 위치와 주장 ID도 그대로 들어 있다.

부록의 페이지 목록은 실제 `source_packet.json`의 30쪽과 순서까지 일치한다. 문서 안의 그림도 30개이며, ZIP 구조의 무결성 검사에 문제가 없었다. 이 확인은 부록 페이지가 빠지거나 순서가 바뀌지 않았다는 뜻이다. 그림 속 표와 작은 글씨의 시각적 가독성까지 이 검사만으로 확인한 것은 아니다.

## 점수를 미리 정하거나 실행 조건을 드러내는 문구가 있는지도 확인했다

F1~F5와 K1~K3의 판정란에는 선택되지 않은 체크칸이 있고, 답변 위치·공시 위치·판정 이유를 적는 공간이 남아 있다. J1~J4에도 0점·1점·2점·기준표 판정 불가의 선택지가 비어 있다. 체크된 표시나 실제 점수가 미리 채워진 흔적은 발견하지 못했다. 기준표에 있는 점수 예시는 채점 방법을 설명하는 예시이며 R001에 부여한 점수와 구분되어 있다.

본문과 문서 내부 XML·관계 파일에서 실제 실행 ID가 노출되지 않는 것을 확인했다. 실제 조건 B의 표기, 설정 버전, 실행 비용, 자가검토나 검산 통과를 알리는 문구도 본문에 없다. 평가 대상은 R001로 표시한다.

공통 기본 모델이 GPT-6.1 Terra라는 설명은 연구 배경에 한 문장으로 들어 있다. 이는 비교하는 실행 방식 전체에 공통인 정보이며, R001이 어느 방식에서 나온 답변인지 이름을 붙여 공개한 문장은 아니다. 실제 과제 문장과 작업 설명 자체는 요청대로 보존되어 있으므로, 이 검사는 조건 이름을 가렸는지에 관한 확인이다. 읽는 사람이 작업 순서에서 방식을 전혀 추론할 수 없다는 보장은 하지 않는다.

최종 파일의 내용 검사에서는 앞서 발견한 값 누락과 잘못된 내부 안내가 해소되었다. 실제 답변이나 질문을 고쳐 옮긴 부분은 발견하지 못했다.

## 최종 보완본을 다시 확인한 결과

마지막으로 메모의 글머리표, 상태 표시, F2·F3 기준표의 줄 배치와 민감도 요약표를 보완한 DOCX를 다시 읽었다. 실제 답변의 필드별 문자열 42개와 두 요청의 과제·공통 지시문이 모두 그대로 보존되었다. 추출 숫자와 설명문 21개, 문서 버전 설명·추출 한계 5개, 계산 원값 40개, 출처 묶음 38개도 모두 다시 통과했다. 위에 적은 최종 SHA-256은 이 보완본의 값이다.

새로 추가한 짧은 민감도 표에는 여섯 대안의 적용 PER, 가격, 가격 차이, 차이 비율이 소수점 둘째 자리까지 표시되어 있다. 원래 계산값을 Decimal로 읽어 둘째 자리까지 반올림한 값과 각 행을 대조했다. **24개 값이 모두 일치**했다. 짧은 표를 추가하면서 원래 40개 계산값이 삭제되지는 않았으며, 원값을 담은 상세 표도 그대로 남아 있다.

문서에는 모델이 보고한 `READY` 상태와 그 의미가 남아 있다. 점수와 구분해 읽도록 설명되어 있으며, 프로그램의 형식 통과를 근거로 답변이 옳다고 미리 판단하는 문구는 없다. 실제 조건 B, 실행 ID, 실행 비용을 노출하지 않았고 채점칸에도 선택된 체크나 점수가 없다.

최종 `render_v4/page-41.png`부터 `page-65.png`까지 각각의 SHA-256을 앞서 원본 해상도로 직접 확인한 `render_v3`의 같은 페이지와 비교했다. **25개 모두 파일 내용이 완전히 같다.** 따라서 이 범위의 최종 이미지에는 앞의 페이지별 시각 확인 결과가 그대로 적용된다. 같은 이미지를 다시 렌더링하거나 원본 문서를 수정하지 않았다. 변경된 앞부분의 시각 확인은 다른 담당자가 최종 이미지로 진행한다.
