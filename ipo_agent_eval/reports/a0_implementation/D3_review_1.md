# D3 1차 검토 — 공통 게이트웨이와 제출 계약

검토일: 2026년 11월 13일 (Asia/Seoul)  
검토자: Codex preservation_review (게이트웨이 구현 담당)  
범위: `tool_gateway.py`, `validation_v2.py`, `tests/test_gateway_v2.py`

판정: **게이트웨이 단위 검증 통과**. D3 전체 통과에는 공통 예산·B 고정 조회·실행 기록과의 통합 검토가 추가로 필요하다.

공통 도구 일곱 개를 strict object 스키마로 제공하며, calculate의 operation별 계약은 `request.anyOf` 안에서 구분한다. 최종화에서는 COMMIT 하나만 노출한다. 외부 경로·다른 사례·마감 이후 자료는 격리 위반으로 종료하고, 일반 형식 오류·너무 큰 열람·예산 부족은 서로 다른 오류 코드로 남긴다.

검색 발췌는 열람으로 계산하지 않는다. 실제 반환한 전체 페이지만 `read_chunks`에 기록하며, 예산 검사에 실패한 페이지·등록 묶음은 상태에 반영하지 않는다. 재열람은 도구 호출과 페이지 소비에 다시 계상한다. 정상·오류 반환은 call ID, 도구명, 결과, 오류, 사용량 차이를 가진 공통 봉투다.

원장은 동일 ID 재등록을 멱등 처리하고, 변경에는 새 버전과 이유를 요구한다. 마지막 목록에서 누락한 기존 OPEN 항목을 유지한다. RESOLVED에는 실제 열람 근거가 필요하며, CANCELLED도 이유와 변경 이력을 보존한다. 실제 외부 메시지는 보내지 않는다.

첫 COMMIT은 원장 동기화 두 번과 제출 한 번을 소비한다. 형식수정 재제출 한 번까지 총 네 번을 먼저 예약한다. 양쪽 원장 프리뷰를 통과한 뒤 동기화하며, 재제출은 이미 동기화된 요청 내용을 바꾸지 않는다. 구조화 계산 USE는 현재 스냅샷과 유한 Decimal 결과가 일치해야 하며, 과거 계산은 이유 있는 REJECT로 남길 수 있다.

검토 중 JSON Schema가 `1.0`을 integer로 인정할 수 있다는 root의 지적을 반영했다. `top_k`, `neighbor_pages`, `page`, `version`에는 실제 정수 타입 검사를 추가해 bool·float·음수를 거부한다.

```text
python -m pytest -q tests/test_gateway_v2.py

```

검사에는 실제 열람 없는 인용, 다른 문서 접근, 원자 등록·원장 실패, 중복 페이지·과대 열람, 관찰 결과 예약 실패, 누락 OPEN, 형식수정 포함 마지막 네 호출, 스냅샷 불일치, Decimal 10/10.0 동등성, 파생 가능 직접값 부재, 새 실행 격리, 의미적으로 틀린 결론을 자동 교정하지 않는 조건을 포함했다.
