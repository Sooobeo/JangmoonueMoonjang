# D4 3차 독립 검토 — 전체 실행과 실패 기록

검토일: 2026년 11월 13일 (Asia/Seoul)  
검토자: Codex preservation_review  
범위: `agent_loop.py`, `runtime_v2.py`, `runner_v2.py`, 예산·게이트웨이 통합

판정: **수정 후 통과**.

3차 검토에서 형식수정 후 제출이 성공한 경우 `context.json`에 수정 도구 결과가 저장되지 않는 기록 누락을 발견했다. 원본 모델 요청·응답과 events는 이미 보존되었지만, 저장된 전체 컨텍스트가 마지막 수정 결과를 포함하지 않았다. 모델 원본 출력 직후, 형식수정 결과 직후, 루프 종료 시 컨텍스트를 저장하도록 수정했고 관련 단언문으로 확인했다.

2차 독립 검토에서 발견한 탐색 중 형식수정의 최종화 예약도 함께 대조했다. `EXPLORATION_REPAIR`는 형식수정 한도를 소비한 상태에서 남은 최종 입력·8,500 출력·모델 1회·제출 도구 3회·120초를 계속 예약한다. 최종화에서 예산 오류가 나면 새로운 최종 답변을 반복 요청하지 않고 실패를 보존한다.

직접 확인한 전체 경로:

- A0가 검색→열람→부분 등록→계산→재검색→PREPARE→COMMIT을 선택하고, function call ID 및 reasoning 항목을 이어 보낸다.
- A0 초기 컨텍스트에는 사례 메타데이터·공통 방법·도구와 한도만 들어간다. 반복 실행의 초기 컨텍스트는 새로 생성된다.
- B는 같은 계약과 게이트웨이에서 프로그램이 순서를 정하며, 정상 경로의 실제 도구 22회와 모델 2회를 기록한다.
- 탐색 예산이 없으면 추가 탐색 없이 예약된 최종화로 전환한다.
- 도구 없는 종료, 거부, 불완전 응답, 사용량 누락, API 오류를 이유별로 보존한다. 사용량을 모르는 요청의 총비용을 0으로 보고하지 않는다.
- 형식수정은 전체 한 번이며 도구 접근 없이 기존 사실·숫자·결론·상태를 유지한다. 잘못된 근거 claim ID 연결만 고쳐 성공하는 경로를 확인했다.
- 비공개 정답표 표식이 요청·응답·결과 기록에 섞이지 않는다.
