# 첫 실제 실행에서 출력 배분을 바꾼 이유

2026년 11월 12일, 한국시간에 확인했다.

`20261111T232308Z_B_b3fe2173`은 GPT-6.1 Terra에서 숫자 추출 응답을 받았고 프로그램의 계산까지 마쳤다. 다음 검토 의견 요청은 출력 한도 5,500토큰에 도달해 끝부분이 잘렸다. API의 상태는 `incomplete`, 이유는 `max_output_tokens`였다. 사람 검토를 통과한 답변처럼 취급하지 않고 원본 응답과 `FAILED` 기록을 보존했다.

이 문제는 답의 좋고 나쁨을 보고 다시 실행하기로 한 것이 아니다. 정해진 제출 형식 전체를 받을 만큼 출력 공간을 배정하지 못한 개발 단계의 문제다. 아직 최종 평가 설정을 고정하지 않은 HDMS 파일럿이므로, 출력 배분을 바꾸고 새 실행 번호로 다시 시도한다. 이전 실행은 분석과 비용 기록에서 제외하지 않는다.

원문, 검색 문구, 계산식, 모델, 추론 설정과 검토 지시문은 그대로 사용한다. 이미 받은 추출 답안을 새 실행에 넣지 않고 같은 공개 자료에서 새로 시작한다. 형식수정은 계속 한 번까지이며, 적은 분량 안에서 수정하지 못하면 실패로 남긴다. 형식수정으로 사실을 새로 채우거나 답변을 개선시키지 않는다.

세 차례 확인한다. 첫째, 원본 API 응답의 중단 이유와 실제 출력 토큰 수를 확인했다. 둘째, 별도 검토자가 같은 실패 원인과 실패 기록 보존 여부를 확인했고 새 배분의 합계가 16,000인지 검사한다. 셋째, 기존 자동 검사를 거친 뒤 새 실제 실행에서 원본 응답과 최종 제출의 저장 여부를 확인한다. 세 번째 실제 확인 결과는 최종 작업기록에 남긴다.

## 두 번째 실행에서 확인한 출처 식별자 연결 문제

`20261111T232645Z_B_e3ab1569`에서는 검토 의견의 본 응답을 끝까지 받았다. 그러나 사실 항목 안 출처가 다른 주장 ID를 가리키거나, 판단의 출처 항목에서 선언하지 않은 ID를 사용하여 공통 형식 검사를 통과하지 못했다. 이 규칙을 지시문에 충분히 설명하지 않은 점이 원인 후보로 확인되었다.

이 실행은 허용된 한 번의 형식수정을 시도했다. 전체 검토 의견을 다시 출력하도록 했기 때문에 수정 응답이 2,500토큰 한도에서 잘렸고, 원본과 `FAILED` 상태를 보존했다. 답변 전체를 받은 것과 실험에서 정한 제출 형식까지 완성한 것을 구분한다.

`0.1.2-pilot`에서는 공통 지시문에 식별자 규칙을 명시했다. 형식 오류가 출처의 주장 ID에만 있으면, 수정 호출은 전체 답변을 다시 쓰지 않고 지정된 경로의 ID 문자열만 반환한다. 숫자, 문장, 문서 ID, 페이지, 원문 위치, 선언한 주장 ID, 판단·요청 상태는 변경할 수 없다. 허용 경로와 기존 ID 목록을 벗어나는 변경은 프로그램이 거부한다. 적용 뒤 전체 형식을 다시 검사한다.

형식수정은 여전히 전체 실행에서 한 번까지이고 출력 배분과 총량은 `0.1.1-pilot`과 같다. 이 규칙은 B·A0·A1에 공통으로 적용할 제출 형식 처리다. 원문이 주장을 실제로 뒷받침하는지 판단하거나 정답을 고쳐 주는 기능은 아니다. 개발 기록과 원본을 남기고 같은 공개 자료에서 새 실행을 시작한다.
