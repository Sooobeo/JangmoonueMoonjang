# HDMS 원문과 검색 자료 준비: 세 차례 확인한 기록

확인일: 2026-11-12. 이 기록은 자료를 준비한 프로그램과 공개 원문을 점검한 기록이다. AI의 검토 답변을 채점한 결과가 아니다.

## 첫 번째 확인: 같은 공시인지, 검토할 수 있는 시점의 자료인지 확인했다

대신증권 공개 주소에서 투자설명서 PDF를 내려받았다. 파일 크기는 8,442,692바이트이며, SHA256은 `9f563a7e2af8c39a96567e83268321b0a40cf334abe94e7377b00ca0351f31ab`로 사전에 기록된 원문과 일치했다. PDF는 638쪽이었다.

DART 접수번호 `20240424000222`의 공식 접수 화면을 HTTP로 직접 읽었다. 문서 제목은 `HD현대마린솔루션/투자설명서/2024.04.24`였고, 이력에는 2024.04.17 최초 투자설명서와 2024.04.24 정정 투자설명서가 표시되었다. 같은 접수번호의 DART 정정 본문도 읽어 정정일과 정정 이유를 PDF와 대조했다. 웹 검색 도구에서는 접수 화면을 열지 못했지만, HTTP 요청은 정상 응답했으므로 읽지 못한 화면을 확인했다고 처리하지 않았다.

PDF 물리 3쪽의 정정표에는 2024년 4월 24일과 공모가액 확정에 따른 정정 이유가 있다. 물리 54쪽 표지의 청약기간은 2024년 4월 25일~26일이다. 따라서 이 문서는 자료 마감인 2024년 4월 24일 말까지 공개된 정정 투자설명서로 분류했다. 실제 공개 시각은 날짜보다 자세히 확인하지 못했으므로 `available_at`은 `2024-04-24`, 시간 정밀도는 `DATE`로 기록했다. 초·분 단위 공개 시각을 만들지 않았다.

발견한 주의점도 남겼다. PDF의 최초제출일에는 `2023년 04월 17일`이라고 적혀 있으나 DART 공식 접수 이력은 `2024.04.17`이다. PDF 글자는 고치지 않고 그대로 보존했으며, 문서 정보에는 공식 접수 이력을 사용한 이유를 적었다. 증권사 다운로드 주소의 폴더 이름을 당시 공시 날짜로 해석하지 않았다.

결과: 원문 식별, 정정 버전, 청약 시작 전 자료라는 조건을 통과했다. 정확한 공개 시각과 최초제출일 표기의 차이는 문서 정보에 남아 있다.

## 두 번째 확인: 숫자와 표의 맥락이 텍스트에 남아 있는지 확인했다

PDF 물리 3, 54, 329, 330, 331, 332, 424, 425쪽을 이미지로 만들고 직접 열어 보았다. 원문 이미지의 표 제목, 열 순서, 단위, 날짜, 주석을 추출한 글자와 대조했다. 이미지 파일은 `data/public/inspection/`에 있으며 원문 PDF를 수정한 것은 아니다.

물리 329~330쪽은 비교회사 기준주가 표가 두 쪽으로 이어진다. 첫 쪽에는 회사명과 통화 단위, 날짜별 가격이 있고, 다음 쪽에는 발행주식수, 기준시가총액, 환율 주석이 있다. 표의 뒷부분만 읽으면 열 이름과 단위가 빠질 수 있으므로 앞뒤 쪽을 함께 읽어야 한다는 안내와 이전·다음 쪽 ID를 각 자료 조각에 넣었다.

물리 331~332쪽에서는 비교회사 PER 표, 적용 순이익과 배수, 평가시가총액, 신주·구주·희석가능 주식, 주당 평가가액의 연결을 확인했다. PER 표의 네 회사와 열의 순서가 추출문에 남아 있으며, 평가시가총액 표가 다음 쪽으로 이어진다는 점도 확인했다. 주당 평가가액 106,113원과 확정 공모가액 83,400원은 원문에서 다른 항목이다. 둘을 합치거나 하나로 바꾸지 않았다.

물리 424~425쪽은 연결 포괄손익계산서의 앞뒤 쪽이다. 기간과 원 단위가 있는 표 제목은 앞쪽에, 순이익과 귀속 항목은 뒤쪽에 있다. 2023년 지배기업 소유주 순이익 151,116,175,331원의 숫자와 귀속 행을 원문 이미지에서 확인했다. 이 확인 결과를 별도의 정답 설명으로 검색 자료에 추가하지는 않았다.

텍스트 추출에는 PyMuPDF의 위치 정렬 기능을 사용했다. 원문의 빨간 글자와 굵은 글씨는 일반 텍스트에 남지 않기 때문에, 정정 전·후 표시와 본문을 읽어야 한다는 한계를 자료마다 안내했다. 전체 표의 모든 칸을 사람이 확인했다고 주장하지 않는다. 이미지로 대조한 범위는 위의 여덟 쪽이다.

결과: 이번 검토에서 중요한 표와 주석의 내용은 추출문에 남아 있었다. 페이지를 넘겨 이어지는 표와 글자 색의 한계를 기록했다.

## 세 번째 확인: 전체 자료와 모델에 넘길 범위를 점검했다

프로그램으로 638개 자료 조각의 ID가 중복되지 않는지, 물리 페이지가 1~638까지 빠짐없이 있는지, 각 조각의 글자가 원문 PDF에서 다시 추출한 글자와 같은지 확인했다. 빈 페이지는 없었고, 글자가 깨졌을 때 나타나는 대체 문자 `U+FFFD`도 없었다. 검색할 본문은 총 1,198,640자다.

PDF 첫 두 장은 목차이므로 인쇄 페이지를 `null`로 기록했다. 나머지 636장은 바닥글의 `Page` 숫자를 직접 읽었으며, 모두 물리 페이지에서 2를 뺀 값과 일치했다. 파일에 적힌 `page`는 물리 페이지이고 `printed_page`는 인쇄 페이지다. 두 값을 섞지 않았다.

모든 조각의 문서 ID, 공개 날짜, 자료 마감 전 여부를 확인했다. 공통 방법서 `manual.md`는 `phase1/IPO_PER_검토방법서.md`와 바이트 단위로 같았다. 공개 자료 폴더에는 채점표 파일을 넣지 않았고, 준비 프로그램도 채점표나 기존 AI 답변을 읽지 않는다. DART의 현재 접수 화면에는 자료 마감 후 관련 공시 링크가 있으므로 그 화면 전체 파일은 남기지 않았다. 확인에 사용한 과거 접수번호·제목·정정일의 발췌와 원 응답의 해시만 `provenance/receipt_verification.json`에 보관했다.

실행기에서 정한 다섯 가지 검색 문구로 단순 출현 횟수 검색도 시험했다. PER·주식수·평가가액 검색에서는 해당 산정표가 검색되었다. 이익을 찾는 넓은 문구는 다른 재무 문맥도 먼저 찾을 수 있다는 점을 실행기 담당자에게 전달했다. 특정한 정답 금액이나 채점표 설명을 검색어에 추가하지 않았다. 실제 실행기의 순위 규칙과 검색 결과는 실행기 점검에서 따로 확인한다.

마지막으로 저장된 PDF와 접수 확인 기록을 다시 사용해 준비 프로그램을 한 번 더 실행했다. 네 입력 파일(`chunks.jsonl`, `documents.jsonl`, `case_manifest.jsonl`, `manual.md`)의 실행 전·후 SHA256이 모두 같았다. 같은 원문으로 같은 검색 자료가 생성되는 것을 확인했다.

결과: 전체 페이지, 인쇄 페이지 연결, 공통 방법서 복사, 채점 자료와의 분리, 반복 생성 결과를 확인했다. 실제 모델 실행과 답변의 품질 평가는 이 기록에 포함하지 않는다.

## 생성한 자료

- `data/public/raw/HDMS-PROS-01.pdf`: 내려받은 원문 그대로다.
- `data/public/chunks.jsonl`: 쪽 전체의 글자와 출처, 페이지 번호, 앞뒤 쪽 ID가 있다.
- `data/public/documents.jsonl`: 원문 해시, 버전 확인 근거, 공개 날짜의 한계가 있다.
- `data/public/case_manifest.jsonl`: 사례 이름, 자료 마감, 허용 문서 목록이 있다.
- `data/public/manual.md`: 이미 작성된 공통 검토 방법서다.
- `data/public/provenance/`: 접수 확인 근거와 생성 결과 요약을 보관한다.
- `scripts/prepare_hdms.py`: 원문 다운로드와 자료 생성을 다시 수행하는 프로그램이다.
