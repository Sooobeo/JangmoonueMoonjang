# IPO 검토자 페르소나 원문 확인 시간

2026-11-26 KST. 공식 Terra 선별 비교의 이관 목록 6쌍에 필요한 모든 항목을 측정했다. 개발에서는 작업 전체 경과의 합이 양쪽 각각 **50.744초**였다. 검증에서는 L3-규칙 **106.282초**, A1 **146.296초**였다. 이관 건수는 개발 각 2건, 검증 각 4건으로 같았다. 이 기록에서 A1의 Codex 대행 검토 시간 절감은 관측되지 않았다. [공식 이관 목록과 시간 집계](timing.json)

가상의 국내 증권사 IPO 인수심사팀 검토자에게 실제 최초 신고서의 검토 항목을 배정했다. 경력 3년 수준을 가정한 새 Codex 세션이 매 항목에서 공시 주장 식별, 원문 근거 대조 또는 수치 검산, 판단·후속 확인 메모 작성을 순서대로 수행했다. 결과에 인용한 문구 또는 표 행은 제공된 물리 쪽에서 다시 확인했다. [실행기](../../../scripts/current_persona_time.py)

## 작업 배정과 가림

- 개발·검증 6곳의 규칙·AI 운영 목록에서 이관 항목의 합집합을 만들었다. 기존 Codex 선별 목록으로 먼저 시작했고 Terra 순위 파일이 생기면 새 항목을 추가했다. 파일별 해시와 측정에 사용한 항목집을 남겼다. [배정 기록](task_set.json)
- 기업과 항목이 같으면 원문과 질문이 같은 새 세션 한 번을 실행해 경과시간을 양쪽 목록에 공통 적용했다. 후보마다 공시 질문과 허용된 PDF 물리 쪽에서 추출한 원문만 전달했다. 배정 출처, 모델 순위·이유, 사전 채점표는 전달하지 않았다. 처리 순서는 모델 순위와 무관한 고정 해시로 정했다.
- 검토자는 항목별로 원문 주장을 식별하고, 기간·단위·귀속 또는 사업 기준을 확인한 뒤 정확한 인용과 후속 확인점을 남겼다. 확인할 수 있는 근거가 부족하면 유보할 수 있다. PDF 뷰어의 클릭·스크롤, 회의와 자료 회신 과정은 이 실행에 포함되지 않았다.

## 시간의 범위

| 시간 | 실제 측정 구간 |
|---|---|
| 원문 준비 | 작업 시작부터 원본 버전 확인, 해당 쪽 추출과 입력 묶음 준비 완료까지 |
| Codex 검토 세션 | 실행기에서 새 세션을 호출하고 답을 돌려받는 경과시간. 프로세스 시작, 전송, 모델 응답 및 있을 경우 재시도를 포함 |
| 증빙 검증 | 받은 인용을 현행 입력과 대조하고 도구 사용 여부를 확인하는 시간 |
| 작업 전체 | 작업자가 시작된 때부터 결과·증빙 확인이 끝날 때까지의 단조 시계 경과. 대기열에서 기다린 시간은 별도 미측정 |

동시 실행한 개별 작업 시간을 더해 각 목록의 일감을 비교했다. 그 합은 한 조건을 일렬로 실행해서 별도로 잰 달력 시간과 차이가 있다. 세션별 네트워크 지연만의 시간과 모델이 실제로 판단에 집중한 시간은 분리할 수 없다. 실제 사람의 능동 확인 시간·검토시간과 비용은 미측정이다. 코드에서 해당 필드는 `null`로 유지한다. [시간 정의와 집계](timing.json)

## 세 차례 점검

1. 운영 목록의 원본 해시, 항목 ID와 원문 버전을 확인했다. 조건 위치를 바꿔도 공통 항목의 합집합과 처리 순서가 유지되는지 확인했다.
2. 인용의 물리 쪽이 제공 범위 안에 있고, 공백을 정규화한 문구가 그 쪽에 그대로 있는지 확인했다. 제공하지 않은 쪽 번호와 맞지 않는 인용이 출력 검증에서 거부되는지 확인했다.
3. 시간 필드는 측정 구간과 원 실행 기록을 대조했다. 공통 항목의 관측값을 같은 시간으로 두 조건에 합산했다. 증빙이 빠진 항목은 시간을 0으로 바꾸지 않고 미측정으로 표시했다. 최종 12개 작업의 입력·응답·시간 파일 해시를 모았다. [최종 증빙 해시](timing.json)
