# L1·L2·L3 전달 형식 탐색 비교

2026-11-26 KST. 개발 2곳과 분리된 검증 4곳에서 A1에게 전달하는 형식만 바꿨다. 회사별 원본 항목, A0·C의 판정, 공통 B 사실과 검사 결과, 원본 대안의 가격 영향, 중대 기준, 공통 필수 검토와 추가 검토량 `K=1`을 공유했다. 회사·조건마다 새 Codex CLI 세션을 사용했다. 지정 모델은 `gpt-6.2-astra`, 추론 수준은 `medium`이다. 순위기 입력에는 채점표가 들어가지 않았고 모든 조건에서 추가 원문 조회를 껐다. [실행 전 고정 기록](freeze.json)

| 조건 | 기존 응답 전달 방식 |
|---|---|
| L1 | 항목 ID와 두 판단만 제공 |
| L2 | L3와 같은 판단, 이유, 남은 조건, 사실, 근거 방향, 출처 ID·위치를 문장으로 제공 |
| L3 | L2와 같은 내용을 구조화된 필드로 제공 |
| L3-규칙 | 같은 라벨과 가격 영향에서 유효 인용을 붙인 문제 제기, 미확인 포함, 나머지 순으로 정렬. 각 묶음에서는 가격 영향 내림차순, 결측 후순위, 항목 ID 순으로 결정 |

개발 코호트에는 기존 API의 A0와 멜콘 C를 사용했고, HD현대마린솔루션 C는 수정 자료로 별도 Codex에서 실행했다. 검증 코호트는 역할 A0·C가 각각 가림 범위에 맞춰 받은 Codex 응답을 사용했다. 코호트별 결과를 볼 때 이 입력 차이를 고려한다. [개발 원판정](../proxy/labels_dev_mixed.json) · [검증 원판정](../validation_roles/proxy/labels.json)

## 세 차례 점검

| 점검 | 확인 내용 |
|---|---|
| 1차 · 입력 | 회사별 원본 항목 ID 전수를 대조하고 공통 입력을 해시로 고정했다. L1에서 역할별 근거를 제거했다. L2 문장의 각 인용 구간을 다시 해석해 L3의 원래 값과 뜻을 이루는 순서까지 일치하는지 검사했다. |
| 2차 · 실행 | 각 요청의 지시문과 모델 이름이 동일하고 추가 조회·채점표 필드가 없는지 대조했다. 별도 세션의 도구 실행 기록과 제출 계약을 확인했다. |
| 3차 · 순위 | 항목의 누락·중복, 제공된 ID 밖의 인용, 점수 내림차순과 동률 항목 ID 처리, 공통 필수와 추가 1건의 합을 검사했다. 모델 순위와 규칙 순위는 평가자가 독립적으로 채점할 수 있게 보존했다. |

순위 교체 건수에는 중대 쟁점 여부를 반영하지 않았다. 중대 쟁점의 상향과 누락은 순위 밖에서 독립 기준표로 채점한다.
