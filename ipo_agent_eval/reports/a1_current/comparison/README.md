# A1 Codex 대행 선별 비교와 평가 가능성

2026-11-26 KST. 개발 두 곳과 사전 지정 검증 네 곳에서 순위 및 운영 목록을 비교했다. 본 평가 후보 가운데 남은 8곳의 순위나 판정은 열지 않았다. [기업별 집계](metrics.json) · [운영 목록 원문 대조](operating_proxy_reviews.json)

## 지표 계산

- 순위 일치도는 기업별 공통 필수 밖의 확정 중대 쟁점과 확정 기타 항목을 한 건씩 짝짓는다. 중대 쟁점이 앞서면 1, 동률이면 0.5다. 동률은 ID를 붙여 정렬하기 전 기준이다. 기업마다 같은 가중치를 적용한다. 한 부류가 없는 기업은 순위 일치도를 미산출하되 K 비교와 운영 분모에 남긴다.
- 같은 K 비교는 공통 필수와 전체 순위 상위 추가 1건을 쓴다. 운영 목록은 코드에서 이관 적격으로 표시한 항목에만 추가 1건을 배정한다. 검토 대기, 자료 요청 및 보관에 남은 중대 쟁점도 운영 누락에 포함한다. AI 이관에서 새로 빠진 중대 항목과 대체로 들어온 항목을 각각 표시한다.
- 판정 유보는 주 분석에서 제외한다. 각 유보 항목을 중대 또는 기타로 배정할 수 있는 경우를 대조해 양쪽 순위 차이와 누락 차이의 범위를 구한다. 중대 쟁점이 0건이면 회수율의 분모가 0이므로 값을 비워 둔다. 모델 출력·순위·근거가 아직 없는 경우에는 원인을 남긴다.

## 운영 목록 원문 확인

양쪽 운영 목록의 합집합에서 같은 기업·항목을 한 번만 확인했다. 실행 순서는 항목 ID의 고정 해시로 섞었다. 별도 Codex에는 목록의 출처, 순위, A0·C·A1 의견과 채점표를 가렸다. 사전 확정 항목 질문과 허용된 최초 신고서 물리 쪽만 주고 모든 인용을 실제 제공 텍스트와 대조했다. 공통 항목은 양쪽에 같은 실제 경과시간을 적용한다. 전체 처리의 시간 합계나 사람의 원문 확인 시간으로 환산하지 않는다.

### 개발 두 곳

HDMS는 양쪽이 H02를 이관해 확정 중대 1건을 목록에 올렸다. Codex 원문 대조는 15.61초였다. 멜콘은 양쪽이 M03을 이관해 확정 중대 2건 중 1건을 목록에 올렸다. Codex 원문 대조는 19.61초였고 50% 요건의 세부 매출 분류는 미해결이었다. 두 목록 모두 M01을 이관하지 않았다. 규칙에는 대기, A1에는 자료 요청으로 남았다.

이 두 기업의 순위 일치도 차이(A1−규칙)의 평균은 +0.01389였다. 같은 K 목록은 각 2건이고 실제 이관은 각 2/22였다. 두 조건 모두 확정 중대 쟁점 3건 중 1건을 놓쳤다. 공유 이관 항목을 한 번씩 확인한 시간은 양쪽 각각 35.22초다. 실제 사람 시간과 독립 사람 판정은 측정하지 않았다. 이 결과는 Codex 대행 선별 경로의 작동 관측이다. [개발 기업 기준표](../grading/rubrics.json) · [운영 목록 대조](operating_proxy_reviews.json)

순위 일치도 차이의 평균은 지표를 산출할 수 있는 검증 2곳에서 +0.14375였다. 참고용 95% 짝 t 구간은 −0.41215~+0.69965이고, 같은 기업에서 유보 판정을 바꿨을 때의 범위는 −0.00417~+0.15483이다. 이 결과로 합의 점검의 독립 기여나 검증 대상 밖의 효과를 판단하기 어렵다.

### 실행 비용 기록

6곳의 서로 다른 이관 항목 10개를 한 번씩 확인했다. 자료 요청의 실제 회신 대기시간과 사람의 원문 확인 시간은 측정하지 않았다. A1 조회·선별 성공 실행의 경과시간 합계는 516.74초다. 조회에서 요청한 PDF 쪽 10개 가운데 5개의 텍스트가 이미 입력에 있었다. 공백을 정규화해 원래 입력의 모든 원문 값과 대조하고 동일 페이지의 별칭과 전체 텍스트가 같은 경우를 따로 표시했다. 마녀공장의 첫 조회는 180초 제한으로 끝났고 사용량을 회수하지 못했다. 이 실패와 후속 성공 시간은 별도로 기록했다. 순위·이관 기록의 Codex 대행 호출에는 청구 비용을 집계할 자료가 없다. ## 입력 형식 탐색 비교

추가 원문 조회를 끈 Codex 선별로 L1·L2·L3을 6곳에서 각각 실행했다. 확정 중대 쟁점만 분모에 둔 K=1 회수 건수다. [조건별 K=1 결과](format_k1.json)

| 사례 | L1 판정 | L2 자유서술 근거 | L3 구조화 근거 | L3-규칙 |
|---|---:|---:|---:|---:|
| 개발 2곳 | 1/3 | 2/3 | 2/3 | 2/3 |
| 검증 4곳 | 0/2 | 2/2 | 2/2 | 0/2 |

L2와 L3의 검증 목록에는 마녀공장의 판정 유보 항목 1건도 들어갔다. 두 형식의 확인된 K=1 결과는 같았다. 입력 형식 탐색의 결과를 합의 점검의 효과와 합산하지 않았다.

## 본 평가 규모

검증 기준표 4곳 중 공통 필수 밖에 두 부류가 모두 있는 곳은 기가비스와 트루엔 2곳이다. 마녀공장과 필에너지는 확정 중대 쟁점이 0건이다. 검증 기업에서 관측한 산출 가능 비율은 50%이고 이항 정확 95% 구간은 6.8~93.2%다. 소표본이며 원접수 순으로 뽑은 표본이므로 모집 비율의 가정으로만 활용한다. [검증 기준표](../validation/codex) · [계산 결과](metrics.json)

| 가정한 표준화 짝 차이 | 필요한 유효 기업 | 유효율 70%에서 총 모집 | 유효율 50%에서 총 모집 | 8곳이 모두 유효할 때 검정력 |
|---:|---:|---:|---:|---:|
| 0.5 | 34 | 55 | 79 | 23.2% |
| 0.7 | 19 | 32 | 46 | 40.1% |
| 0.8 | 15 | 25 | 37 | 49.6% |
| 1.0 | 10 | 18 | 26 | 68.1% |
| 1.2 | 8 | 14 | 21 | 82.8% |

유의수준은 양측 5%, 목표 검정력은 80%다. 총 모집은 가정한 유효율에서 목표 유효 기업 수를 확보할 확률이 90% 이상이 되도록 구했다. 예약된 8곳이 전부 유효해도 80% 검정력이 되는 효과는 약 1.16부터다. 8곳만으로 기존 규모의 확증 평가를 시작하는 근거는 부족하다. 예약 기업의 평가 자료를 열기 전에 검출 목표와 허용 검토량을 결정하고 새로운 독립 기업을 확보할 수 있는지 확인한다. ## 세 차례 확인

1. **입력 계약.** 원본 항목·공통 필수 ID, 전체 순위, 동률 키, 고정 K 및 운영 배정을 코드에서 대조했다. 사전 지정 6곳만 허용한다. 후속 확인은 가림된 질문과 원문만 사용했고, 자료 요청을 실제 이관으로 집계하지 않았다.
2. **산식 확인.** 동률에 0.5점을 주는 예, 비교 부류가 없을 때의 미산출, 두 목록에서 새로 빠지거나 추가된 중대 항목, 유보 지정에 따른 상·하한을 각각 검산했다. 검증 규칙은 현재 확보한 자료를 기준으로 계산했고 설계의 34·24·19·15·10 유효 기업 규모를 재현했다.
3. **증빙 대조.** 실행별 원문 인용과 경과시간, 출력 해시 및 비용 범위를 대조했다. HDMS H08의 221,711백만원과 221,682백만원 차이는 원문 물리 251·269쪽에서 사후 확인됐다. 최초 Codex 기준표는 이 비중대 차이를 놓쳤다. 순위에 접근한 뒤 확인한 내용이라 동결 기준표는 유지했다. 수용과 비중대가 모두 기타에 들어가므로 이 차이는 중대 이분 지표를 바꾸지 않는다. [HDMS 최초 신고서 251쪽](../../../data/a1_pilot/HDMS/filing/20240325000947.pdf#page=251)

SciPy가 설치된 환경에서 `ipo_agent_eval` 폴더의 `python -m scripts.current_evaluate`로 저장된 결과를 재계산할 수 있다. `--review`는 해당 이관 항목의 Codex 대행 로그를 찾아 재사용하고, 로그가 비어 있으면 원문 확인을 실행한다.
