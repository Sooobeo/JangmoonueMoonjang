## 01 먼저, 이 프로젝트는 무엇인가

### 두 AI가 공모가 산정에 동의했을 때 무엇을 다시 확인할까?

AI가 IPO 공시의 숫자와 산식을 확인하고 판단의 근거를 남깁니다. 기존 개발에서는 고정 절차 B와 자율 검토 A0를 비교했습니다. 다음 단계는 최초 증권신고서의 판단 가운데 **사람이 다시 볼 항목을 더 잘 고를 수 있는지** 평가합니다.

**현재는 사용자 요청으로 중단한 상태입니다.**  
B·A0 구현과 실패 보완의 코드 수정을 마쳤고, 최신 개발 검증 12회 중 2회 완료·2회 중단·8회 미착수입니다. 재개 요청 전에는 다음 기업을 실행하지 않습니다.

| 구분 | 범위 | 내용 |
| --- | --- | --- |
| 검토할 자료 | **국내 비금융 IPO의 실적 PER 공시** | 다음 평가에서는 최초 증권신고서와 그 공개 시점까지의 자료를 사용합니다. 후속 정정은 사후 대조에 씁니다. |
| 맡길 업무 | **숫자 → 계산 → 판단 → 다음 행동** | 공개된 가격 산정 근거를 다시 확인하고, 확인 범위를 밝히기 |

### 기존 개발 질문 · A0와 고정 절차 B 비교

AI가 다음 검색과 계산을 스스로 고르면,  
**정해진 순서보다 검토가 좋아지는가?**

### 본 평가 질문 · 독립 검토에 카나리를 더한 효과

같은 수의 실제 항목을 사람이 검토할 때, **두 AI가 함께 놓친 시험 결과를 반영하면 목록 밖 중대 쟁점이 줄어드는가?**

**최종적으로 얻을 답** 어떤 검토를 AI와 도구에 맡길 수 있고, 어디서 추가 자료나 사람의 확인이 필요한지 근거로 설명합니다.

## 02 전체 프로젝트는 이렇게 구성됩니다

기존 공통 도구와 A0 위에 검증을 더합니다. A1은 원문 대조·재계산 결과, 독립 검토자 B의 판단, 카나리 결과에 따른 검토 우선순위를 A0 원본 보고서에 연결합니다.

입력 → 검토 시스템 → 출력

| 단계 | 구성 | 내용 |
| --- | --- | --- |
| 입력 | 시점이 고정된 공시 | 문서 버전·자료 마감<br>기업별 허용 원문<br>공통 검토 방법서 |
| 검토 시스템 | A0 원본 + 추가 검증 | 사실·계산 검사, 주관사 선택을 가린 독립 재구성, 카나리 탐지 기록 |
| 출력 | A0 보고서와 검증 기록 | 원문 위치·재계산값·수정 제안, 양쪽 판단·가격 영향·사람 검토 우선순위 |

| 방식 | 상태 | 진행 방식 | 내용 |
| --- | --- | --- | --- |
| 고정 절차 B | 구현 완료 | 순서를 프로그램이 결정 | 정해진 검색·추출·계산·검토 순서를 따릅니다. A0와 같은 자료·7개 도구·출력 계약·예산을 사용합니다. |
| A0 | 구현 완료 | 다음 행동을 AI가 결정 | 중간 결과를 보고 검색·열람·등록·계산·민감도·제출을 고릅니다. 실제 모델의 선택과 호출을 기록합니다. |
| A1의 독립 검토자 B | 설계 | 선택을 가리고 산정근거 재구성 | 후보별 포함·추가 검토·제외와 근거를 남기고 적용 이익과 배수 집계 방식을 제안합니다. |
| A1 | 설계 · 미구현 | A0 원본에 검증 결과 연결 | 실행 중 중대 불일치와 합의 지적은 공통 필수 검토로, 공동 수용과 유효 시험의 공동 미탐은 우선순위 상향으로 처리합니다. |

별도의 평가 과정

### 검토 결과 + 사례별 채점 기준표

사람은 원본만 보고 수용 가능·비중대 쟁점·중대 쟁점·판정 유보를 기록합니다. 기준표는 모델과 카나리 제작에서 분리하고, 검토 목록 밖 항목도 같은 기준으로 채점합니다.

- 사실·계산의 정확성
- 같은 검토량에서 목록 밖에 남은 실제 중대 쟁점
- 유형별 공동 미탐·정상 대조본 오경보
- 사람 검토량·모델 호출·토큰·실행 시간

예를 들어 이익의 기간이 맞는지, 비교기업의 사업 차이가 배수 선택에 반영됐는지, 가정을 바꾸면 결과가 얼마나 달라지는지를 봅니다. 완료라고 제출한 답에 오류가 남았는지, 불필요하게 검토를 미뤘는지도 함께 평가합니다.

### 연구 전체의 진행 순서

개발 → 고정 → 새로운 기업에서 평가

| 단계 | 진행 내용 | 설명 |
| --- | --- | --- |
| 01 | **문제·기준 설계** | 검토 범위와 채점 규칙 |
| 02 | **3기업 파일럿** | 자료·B 실행·채점 시험 |
| 03 · 현재 | **사례 확장·B/A0 검증** | 구현·실패 보완 후 실제 검증 중단 |
| 04 | **A1 파일럿** | 최초 신고서로 작동 확인 후 3기업 보정 |
| 05 | **새 기업 본 평가** | 규칙 고정 후 같은 검토량의 두 목록 비교 |
| 06 | **분석·최종 보고** | 자연 쟁점을 기업별로 짝지어 비교하고 평가용 심은 쟁점은 별도 보고 |

개발 기업에서 문제를 찾고 고친 뒤, 설정을 고정하고 보지 않은 평가 기업에서 효과를 확인합니다. 마지막에는 결과표·실행 기록·분석 코드·한계를 담은 보고서를 남깁니다.

### 문서·코드·자료는 어디에 연결되어 있나

제안서·설계서·프로토콜·할 일 목록이 목적과 비교 규칙을 정합니다. 후속 설계는 [A1 설계 v4](../update%20plan/A1_설계플로우_일치자격검사_v4.md)를 기준으로 삼습니다.

## 03 이 전체 흐름에서, 우리는 여기까지 왔습니다

현재 위치 · 03단계 구현 후 실제 검증

### B·A0를 구현하고 실패 원인을 보완했습니다. 6기업 전체 재검증은 중단 상태입니다.

초기 3기업 파일럿 뒤 개발 사례를 **6기업**으로 늘렸습니다. 최초 B/A0 비교에서 드러난 전송·예산·출력 계약 문제를 고쳐 **v0.4.3-dev**까지 진행했습니다. 최신 HDMS 두 실행은 등록·계산·민감도·제출을 통과했지만, 전체 배치와 최종 검토는 아직 끝나지 않았습니다.

**완료**: B·A0 구현, 공통 계산·근거 계약, 실패 진단·구현 각 3회 검토

**남음**: 중단 실행 처리·나머지 개발 검증, 실행·종합 각 3회 검토, A1·본 평가

| 현황 | 설명 |
| --- | --- |
| **2개 방식** | B·A0 구현 · A1 미구현 |
| **6 + 12기업** | 개발 입력 준비 + 평가 후보 분리 |
| **2 / 12회** | 최신 검증 완료 · 중단 2·미착수 8 |
| **3회씩** | 실패 진단·최신 구현 검토 완료 |

12회는 최신 개발 검증 FIX_v043의 계획 횟수입니다. 과거 버전·진단 실행과 합쳐 완료율을 계산하지 않습니다. 평가 후보 12기업은 최종 입력·기준표 준비 전이며, 평가 답변은 요청하지 않았습니다.

### 현재 단계에서 확보한 것

#### 연구 방법과 채점 기준을 만들었습니다

연구 제안서·설계서·실험 프로토콜, 공통 검토 방법서와 기업별 기준표를 준비했습니다. 사실·계산·판단을 나누어 평가합니다.

#### B와 자율 선택 A0를 연결했습니다

같은 공개 자료·도구·계약 위에서 B는 고정 순서, A0는 모델 선택으로 실행합니다. 새 실행마다 원본 요청·응답·호출 주체·사용량·실패를 남깁니다.

#### 개발 6기업과 평가 후보 12기업을 분리했습니다

개발용은 HDMS·멜콘·디티에스·신성에스티·에이엘티·밀리의서재입니다. 전체 공개 입력과 분리된 기준표를 준비했고, 평가 후보는 적격성과 원문을 확인했습니다.

#### 사실·선택·계산·근거를 연결했습니다

공시 직접값·파생값·미확인·0, 주식수 포함·제외와 적용 분모를 구별합니다. 계산에 쓴 입력 상태를 고정하고 최종 답변이 실제 계산 결과를 사용했는지 검증합니다.

#### 실제 실패를 재현하고 공통 실행기를 고쳤습니다

API 응답 재전송, 탐색·최종화 예산, 출력 절단, 공유 스키마 오염, 명시 분모 선택, 비교기준 중복 표기와 주장 ID 충돌을 보완했습니다. 기존 답변과 실패 원본은 보존했습니다.

#### 최신 HDMS 두 실행의 실제 경로를 확인했습니다

B·A0 모두 입력 등록 후 현재 상태의 일반 계산 24개와 민감도 7개가 OK였습니다. 최종 제출·근거·요청 원장·사용량 검사도 통과했습니다.

현재 실험 응답 모델은 GPT-6.1 Terra, 추론 수준 medium입니다. Codex는 구현·자료 정리·AI 보조 검토를 지원했습니다. 독립된 사람 채점, A1 구현, 최종 평가 설정 고정과 새로운 기업의 본 평가는 남아 있습니다.

## 04 최신 버전은 어디까지 실행했나

FIX_v043 · 0.4.3-dev  
6기업 × B/A0 각 1회, 총 12회 계획입니다. 사용자 중단 요청이 전달될 때 다음 기업인 멜콘은 자동 대기열에서 이미 시작된 상태였습니다. 실행 프로세스를 종료하고 아래 상태로 보존했습니다.

| 개발 기업 | B · 고정 절차 | A0 · 자율 선택 | 현재 확인한 범위 |
| --- | --- | --- | --- |
| **HD현대마린솔루션** | 제출·실행 검사 통과<br>SUBMITTED / PENDING_INFO | 제출·실행 검사 통과<br>SUBMITTED / PENDING_INFO | 각 일반 계산 24개 OK<br>각 민감도 7개 OK<br>최종 계산 사용·제출·근거·원장 검사 통과 |
| **멜콘** | 사용자 요청으로 중단<br>모델 요청 1회 시작, usage 응답 0회 | 사용자 요청으로 중단<br>모델 요청 10회 시작, usage 응답 9회 | 두 실행 모두 최종 답변 없음<br>진행 중이던 요청 각 1개의 사용량·비용 미확인 |
| **디티에스** | 미착수 | 미착수 | 사용자 중단으로 실행하지 않음 |
| **신성에스티** | 미착수 | 미착수 | 사용자 중단으로 실행하지 않음 |
| **에이엘티** | 미착수 | 미착수 | 사용자 중단으로 실행하지 않음 |
| **밀리의서재** | 미착수 | 미착수 | 사용자 중단으로 실행하지 않음 |

완료 2 + 중단 2 + 미착수 8 = 계획 12회입니다. 중단 실행을 모델 실패나 성공으로 바꾸지 않았고, 미착수 실행의 점수는 미산정으로 남깁니다. 상태의 최신 근거는 [사용자 중단 기록](../ipo_agent_eval/reports/failure_remediation/FIX_v043_user_stop.json)입니다.

**제출 성공과 검토 업무의 완료는 구분합니다.**

HDMS 두 답변은 모두 추가 정보 대기(PENDING_INFO)입니다. 핵심 계산과 실제 실행 경로는 통과했지만 환율 변환의 계약 범위, 공시 표시 전 정밀도 등의 확인사항이 남았습니다. 이 한 기업의 결과로 B/A0의 우열이나 전체 보완 성공을 판단하지 않습니다.

### HDMS에서 이번에 확인한 개선과 남은 한계

v0.4.2 B는 같은 평가표의 비교기준을 서로 다른 문구로 선언해 주당 계산과 민감도가 INVALID였습니다. v0.4.3에서는 모델이 공통 비교기준을 선언해 참조하도록 표현을 바꿨고, 이번 B·A0 모두 핵심 수치 계산에 성공했습니다. 엄격한 기준 검사는 유지했습니다.

## 06 최종 보고서까지 남은 일

### 1. A1을 연결하고 작동과 채점 기준을 보정

**W11 · 사실·계산 검사, 독립 검토, 카나리**

A0 원본에 등록값 재계산과 독립 원문 대조 결과를 따로 연결합니다. 채점 가능한 시험 응답의 목표 근거 누락은 미탐, 원본 응답의 누락은 미확인입니다. 필수 자료가 없거나 응답 계약을 어기면 채점 불가로 기록합니다.

한 기업에서 작동을 확인한 뒤 개발 기업 세 곳에 각각 원본 1건·같은 세부 유형의 서로 다른 현실적인 카나리 2건·정상 대조 1건을 준비합니다. 보정은 A0 12회와 B 3회입니다. 유효 카나리 짝 5/6건 이상, 유효 정상 대조본 3/3건, 어느 한쪽이라도 근거 없는 경고를 낸 정상 대조본 1/3건 이하, 공동 미탐과 한 명 이상 탐지 각각 1건 이상을 점검합니다. 적어도 한 기업·세부 유형에서 유효 짝이 2개 이상이고 공동 미탐률이 50% 이상인 신호로 추가 K 목록이 실제로 바뀌어야 합니다. 본 평가 가능성은 자연 중대 쟁점 빈도, 제작·검토 시간과 비용에서 별도로 판단합니다. 반복 실행은 변동성을 진단합니다.

### 2. 평가 후보의 최초 신고서 입력과 사람 기준표를 완성

**W09 후속 · 개발 6 / 평가 후보 12 분리**

기존 후보의 적격성을 최초 신고서에서 다시 확인합니다. 후보별 접수번호·KST 공개시각·해시와 근거 자료를 고정합니다. 당일 공개시각을 확인할 수 없는 자료는 모델 입력에서 제외하고, 후속 정정본은 사후 대조에 씁니다. 허용 입력 목록, 사람 기준표와 포함·제외 근거를 남깁니다.

### 3. 중대 기준·정렬·검토량과 예산을 사전 고정

**W12 · 본 평가 전에 확정**

두 조건에 기업별 공통 필수 검토와 같은 추가 검토 수를 적용합니다. 공통 필수에는 중대한 불일치·합의 지적과 원문에서 확인한 중대 사실·계산 오류가 들어갑니다. 추가 검토 수는 K와 필수 검토를 제외하고 남은 항목 수 중 작은 값입니다. 실행 중 중대 기준, 원본 기준값과 유형별 대안, 가격 영향·동률 정렬, 표본·모드·예산을 동결합니다. 원본의 독립 이중 채점 표본은 기업·판단 유형별로 사전에 정합니다. 두 평가자는 시험 자료·모델·목록을 가린 채 공동 카나리 검증 전에 원본을 채점하고, 해소되지 않은 불일치는 판정 유보로 둡니다.

### 4. 같은 원본에서 두 검토 목록을 비교

**W13 · 본 실행과 채점**

두 목록에 같은 A0 원본 보고서·독립 B 원본 판단·사실과 계산 검사를 사용합니다. 양쪽 응답을 채점할 수 있는 서로 다른 카나리가 해당 기업·세부 유형에 2건 이상이고, 그중 공동 미탐이 50% 이상이면 두 AI가 모두 수용한 해당 항목을 올립니다. 유효 짝이 모자라거나 공동 미탐률이 낮으면 기본 순위입니다. 같은 순위에서는 가격 영향이 큰 항목을 앞에 두고, 영향 미확인은 뒤로 보내며 동률은 항목 ID 순으로 처리합니다. 사람 기준표로 목록 안팎을 채점합니다.

### 5. 기업별 차이·비용·한계를 보고

**W14 · 분석과 보고**

기업별로 목록 밖 자연 중대 쟁점 수의 차이(기본−카나리)를 구해 평균을 주지표로 보고합니다. 누락 비율, 새로 들어간 쟁점과 밀려난 쟁점, 개선·악화·동률 기업 수도 기록합니다. 신호가 없거나 두 목록이 같은 기업도 남기고 적용률을 기록합니다. 자연 중대 쟁점이 너무 적으면 효과 판단을 유보합니다. B 후보군에 사전 포함된 다른 후보를 사용한 평가용 심은 쟁점은 별도 성능으로 보고합니다. 오경보·채점 불가·반복 탐지 변동과 실제 비용, 가능하면 사람 검토 시간도 남깁니다.

### 평가 규모와 비용은 파일럿에서 산정

개발 6곳과 평가 후보 12곳을 확보했습니다. 적격성 재심사, 자연 중대 쟁점 빈도와 K 경계의 교체, 제작 시간·비용을 보고 본 평가 규모를 확정합니다. 아래 표는 후보 12곳을 전부 평가할 경우입니다.

### 현재 실행 설정과 비용에서 확인할 점

B/A0의 모델은 gpt-6.1-terra·medium이고 조건명 외 설정은 같습니다. 실행당 누적 입력 800,000·출력 24,000토큰, 모델 24회·도구 40회, 900초·최대 $1.25입니다. 탐색/추출 한 응답은 최대 9,000, 최종 답변 10,000, 공유 형식수정은 최대 1회·1,500토큰이며 남은 총예산에 따라 탐색 한도를 줄입니다.

최신 HDMS B는 모델 2회·169.28초, A0는 12회·161.418초이며 형식수정은 둘 다 0회입니다. 멜콘 중단 시 진행 중이던 요청 2개의 usage·비용은 미확인입니다. 과거에도 사용량 불명 요청이 있어 전체 비용 총액은 확정하지 않았으며, 미확인 비용을 0으로 더하지 않습니다.

최신 12회 계획의 실행 상한 합계는 $15입니다. 과거 실패·진단·호환성 검사·향후 재실행은 별도입니다. 저장된 usage 비용 추정은 청구서 금액이 아니며, 과거 버전의 누적 원화 수치를 현재 총액으로 재사용하지 않습니다.
