# IPO 당장 할 일

초기 파일럿 실행 기록은 2026년 11월 13일 기준이다. 11월 26일 팀이 합의한 후속 A1 흐름과 작업은 아래에 연결했다. 규리가 담당하고 Codex는 자료 조사·구현·실행·채점을 지원했다.

**승인한 멜콘·디티에스 준비, B 실제 실행, 채점 및 세 차례 검증을 마쳤다.** 기존 HDMS를 포함한 개발용 3기업 파일럿의 입력·기준표·실행·채점 기록이 갖춰졌다. 사람의 직접 채점이나 최종 평가 완료를 뜻하지 않는다.

## 완료한 일

- [x] 기존 HDMS 입력·PDF·실행·채점 등 122개 파일의 SHA256을 기록하고 변경 없음을 확인했다.
- [x] 멜콘 2026-09-29 정정 투자설명서 600쪽과 디티에스 2026-10-12 정정 투자설명서 719쪽을 확보했다. 접수 이력·청약 전 여부·자료 마감을 대조했다.
- [x] 전체 1,319쪽을 사례별 폴더로 분리해 저장하고 본문·표·주석·물리 쪽과 인쇄 쪽을 대조했다.
- [x] 실제 답변 전에 두 기준표를 작성하고 독립 계산을 대조한 뒤 해시를 고정했다. 답변 후 기준표 변경은 없다.
- [x] 등록 사례 선택, 사례별 보고서 제목, 공통 방법서 분리, HDMS 전용 검색 연도 제거를 구현했다.
- [x] 합성 사례 격리·비공개 정답 및 기존 답변 미노출·변조와 페이지 누락/중복 거부 등 회귀 테스트 146개를 통과했다.
- [x] 세 사례를 무료로 점검했다. 새 실제 답변 전에 입력 크기를 근거로 목표를 16만 토큰으로 조정하고 이유와 버전을 기록했다. 실행당 0.30달러·출력 1.6만·600초 제한은 유지했다.
- [x] 멜콘·디티에스의 실제 Terra 답변을 각각 한 편 받아 원본 요청·응답·계산·사용량과 상태를 보존했다. 두 실행은 SUBMITTED / PENDING_INFO다.
- [x] 고정 기준표로 채점하고 별도 AI 재검토로 확정했다. 단계별 경과 시간과 추가 비용 약 472원을 남겼다. 사람 작업시간은 미측정으로 유지했다.

연환산·조정은 이번 버전에서 기존 period·description·J1 사실 필드로 표현했다. 별도 계산 스키마를 새로 만든 것으로 기록하지 않는다. 실제 실행에서 확인한 주식수 구성의 한계는 이후 공통 계산 보완의 출발점이었다.

## 결과와 세 차례 검증

| 사례 | 사실 | 계산 | J1~J4 | 주요 미충족 |
|---|---:|---:|---|---|
| HDMS — 기존 결과 | 5/5 | 3/3 | 각 2점 | 기존 검증 기록 참고 |
| 멜콘 | 5/5 | 2/3 | 각 2점 | 자동 주식수 합계에서 의무인수75,000주 누락, 서술과의 충돌 미해결 |
| 디티에스 | 4/5 | 3/3 | 각 2점 | 구주매출0 확인 누락. 잘못된 자동 합계는 모델이 명시적으로 배제 |

방법론 충족률은 세 사례 모두 `2점인 J 항목 수 / 4 = 100%`다. 전체 정답률이나 모든 계산의 정확성을 뜻하지 않는다. 기존 HDMS는0.1.4, 신규 두 사례는0.2.1 설정이므로 동일 설정의 통제 비교로 해석하지 않는다.

1. **원문 검증:** 접수·정정 이력과 표 이미지를 확인하고 새 원문1,319쪽을 전수 대조했다. 기존122개 파일을 보존했다.
2. **숫자·채점 검증:** 답변 전 독립 숫자검사227개를 통과했고, 답변 후에는 실제 산출물 전체를 항목별 채점하고 별도 재검토했다. 발견한 오답을 고쳐 쓴 뒤 채점하지 않았다.
3. **구현·기록 검증:** 회귀 테스트146개와 실제 실행 후 독립 프로토콜 검사318개를 통과했다. 기준표·코드·입력28개 동결 파일과 원본 실행의 보존을 확인했다.

## 바로 다음 할 일

2026년 11월 26일 합의한 개발 기본안에서는 **수용에 합의한 항목은 TRIZ로 근거를 점검하고, 갈린 항목은 A1이 원문을 대조한다.** A1은 중대 쟁점이 남은 항목을 사람 검토 후보로 올린다. 원본 채점 다음에 워트 한 항목에서 근거 시험을 확인한다. 아래 체크리스트는 기존 v5 문서 단위 실험도 포함한다. [최신 A1 통합 설계](../update%20plan/real%20real%20update.md) · [팀 공유본](../update%20plan/A1_TRIZ_검토결과_및_프로세스_적용안.md) · [실행 체크리스트](../update%20plan/이제%20할%20일.md)

- [ ] 개발 기업 한 곳에서 최초 증권신고서의 접수번호·공개시각과 허용 자료를 확인한다. 사람 기준표를 열람하기 전에 원문 위치를 근거로 항목 ID와 오류 세부 유형의 연결, 평가 기업별 시험 유형 배정을 고정한다. 판단별 재계산 대안도 미리 정한다.
- [ ] A1의 사전 검증 B에 쓸 구조화 입력을 원본 신고서의 표·행·열·주석과 연결한다. AI 호출 전에 공시 버전과 공개 시점, 단위·기간·연결 범위, 주식 수·평가가액 산식과 반올림 범위를 검사해 `통과 / 불일치 / 미확인`과 근거를 남긴다. 계산이 일치해도 출처 행을 확인하지 못하면 `원문 미확인`으로 표시한다. 명백한 오류, 정상 반올림, 원문을 확정할 수 없는 사례로 각각 점검한다.
- [ ] 실제 상장사 자료로 목표 유형의 현실적인 카나리와 정상 대조본을 각각 준비한다. 바뀐 후보·선정 설명·PER·평가가액·연결 표의 정합성과 형식상 단서를 확인한다. 한 사람이 원본 판정을 확정한 뒤 시험 목표를 확인하고 탐지·오경보 채점 근거를 기록한다. [현재 채점 순서](../update%20plan/이제%20할%20일.md)
- [ ] 독립 검토자 C의 후보군은 공개시점의 독립 선별 규칙으로 구성한다. 후보별 자료 양식을 맞추고, 문서명·메타데이터·링크·검색 결과·인접 쪽과 사전 검증 기록에서 주관사 선택과 시험 단서가 가려졌는지 검사한다. 기존 고정 절차 B는 개발 비교 기록에 쓰고, A1의 사전 검증 B는 AI 호출 전 점검에 쓴다.
- [ ] 한 기업에서 원본·카나리·정상 대조본을 A0로 각각 새 세션에서 순서를 섞어 검토한다. 기업당 한 번 실행한 C의 후보군 전체 답변을 고정하고, 채점기가 각 A0 답변에 연결한다. 4회로 작동과 채점 가능성을 확인한다. 카나리 비교에는 동결한 A0 입력과 응답을 사용하고, 두 목록에 같은 사전 검증·원문 대조 결과를 연결한다. 목표 근거 누락·무효 응답·자료 부족은 각각 기록한다.
- [ ] 개발 기업 3곳의 기본 보정 15회에 순서 변경 응답 C2를 기업당 한 번 더해 재시도 전 18회로 잡는다. 기본 응답 C1에서 유효 짝이 2개 이상이고 공동 미탐률이 50% 이상인 신호로 적어도 한 기업의 추가 K 목록이 바뀌는지 확인한다. C2는 같은 A0·원본·K로 공동 미탐률과 추가 목록을 다시 계산하고, 목록이 한 건이라도 바뀌면 원인을 검토한다.
- [ ] 기업별로 공통 필수 검토와 추가량 K를 같게 두고, 사람이 원본 목록 안팎을 채점한다. 유효 짝·오경보·목록 교체로 절차를 확인한다. 자연 중대 쟁점 빈도, 제작 시간과 비용으로 본 평가 가능성을 별도로 판단한다. 본 평가의 주지표는 기업별 자연 중대 쟁점 누락 건수 차이(기본−카나리)의 평균이다.
- [ ] 운영안에서 B 결과를 A0에 전달하는 효과는 같은 신고서·모델·설정으로 B 결과 제공 여부만 바꾼 짝 비교에서 확인한다. 사실·계산 오류, 오경보, 추가 확인량과 시간·비용을 기록한다.
