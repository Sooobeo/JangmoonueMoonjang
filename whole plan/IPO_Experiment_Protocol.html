1. 연구 질문과 주장 범위 고정

1.1 주 연구 질문

공개된 실적 기반 PER IPO 자료를 검토할 때, 에이전트는 적용 이익·비교기업·민감도·추가 확인에 관한 방법론을 실제 근거에 얼마나 충실하게 적용하며, 실패에 대응하는 검증·이관 장치는 새로운 기업에서 품질·완료 범위·비용을 어떻게 바꾸는가?

1.3 허용되는 최종 결론

  • 허용: “선정된 공개 IPO 자료에서 A1은 A0보다 특정 판단 항목의 품질이 높았으나 추가 이관과 비용도 증가했다.”
  • 허용: “수치 검증은 개선되었지만 비교기업 검토에서는 문헌 기반 기준을 충족하지 못한 항목이 남았다.”
  • 허용: “고정 절차 B보다 에이전트 A0의 이득이 확인되지 않았다.”
  • 금지할 과장: “AI가 최적 공모가를 찾았다”, “증권사 실무자를 대체한다”, “실제 발행 성과가 개선된다”, “사람의 검토를 안전하게 생략할 수 있다.”

공모가는 본 과제의 정답이 아니다. 거래소 자료는 가치평가의 합리성을 검토할 업무 근거이며, 최적가격을 제공하지 않는다.R01

3. 실험 단위와 자료 분할

3.1 단위 정의

같은 발행기업의 다른 정정본은 개발과 최종 평가에 나누지 않는다. 관계회사·공통 비교기업 자료의 중첩도 기록한다. 발행기업 분리는 정보누출을 줄이는 설계이며 모든 통계적 독립성이나 사전학습 오염 제거를 보장하지 않는다.R08 R11

3.2 초기 목표 표본

  • 개발: 10개 발행기업. 파일럿 3개는 여기에 포함한다.
  • 최종 평가: 개발과 다른 20개 발행기업.
  • 최종 실행: 20 × 3조건 × 2반복 = 120회.
  • 개발 실행 횟수는 최종 120회에 포함하지 않고 별도 보고한다.
  • 적격 사례 30개가 이미 확보되었다는 뜻은 아니다. 확보 가능한 수를 모집대장에서 확인한다.
  • 20개는 탐색적 자원 목표다. 확증적 우월성·비열등성 검정을 주장하려면 의미 있는 효과 크기와 별도의 표본 설계가 필요하다.R10

3.3 모집·분할 절차

  1. 사례 모집 기간 제안: 2023-01-01부터 2026-10-26까지 공개된 대상 IPO 자료. 상장 성공 여부가 아니라 IPO 관련 공시 존재로 모집한다. 철회 거래도 동일 자료 요건을 만족하면 포함 후보로 기록한다.
  2. DART·KIND에서 후보 목록을 만들고 각 후보를 동일한 포함·제외 기준으로 확인한다. 접근이 쉬운 성공 거래만 임의로 고르는 방식은 피한다.R02
  3. 파일럿 3개는 이미 내용을 검토했으므로 개발용으로 고정한다. 최종 평가 기준표는 규리가 모델 출력 전에 작성·검토해 동결한다.
  4. 선택한 개발 목표를 D(10 또는 6), 평가 목표를 T(20 또는 12)로 둔다. 이미 자세히 분석한 기업 m개를 개발에 고정하고, 나머지 적격 기업 목록에서 고정 난수 seed 20261026으로 개발 D−m개와 최종 평가 T개를 배정한다. 현재 m=3이면 기본안은 개발 7개, 축소안은 개발 3개를 추가한다. m>D이면 계획을 변경하고 기록한다. 배정은 고정 스크립트로 수행한다. 최종 평가 기준표를 모델·검색 인덱스·프롬프트에 넣지 않는다. 구현 담당자가 평가 기준을 겸해서 보는 경우도 기록하고, 최종 출력에 맞춘 수정은 변경 이력으로 남긴다.
  5. 연간·LTM·중간실적 연환산, 국내/해외 peer 여부, 코스피/코스닥 태그의 분포를 기록한다. 층별 수가 너무 적으면 별도 추론 대신 개별 사례를 제시한다.
  6. 이미 팀이 자세히 분석한 기업은 평가에 넣지 않고 개발에 배정한다. 최종 선정 규칙과 예외를 배정 전에 기록한다.
  7. 적격 30개를 확보하지 못하면 기간 연장 또는 규모 축소를 선택하고 사전등록을 갱신한다. 다른 평가방법을 몰래 포함하지 않는다.

이 분할은 보지 않은 기업에 대한 검증이다. 시간 순서에 따른 미래 일반화 검증이라고 부르지 않는다. 미래 일반화는 15절의 별도 전향적 보조 실험에서 다룬다.

3.4 작업량에 따른 규모 선택

기본안은 개발 10개·평가 20개·B/A0/A1·각 2반복으로 최종 120회다. 축소안은 개발 6개·평가 12개·세 조건·각 2반복으로 최종 72회다. 파일럿 3개는 두 안 모두 개발 수에 포함한다.

1주차에 사례당 자료 정리·기준표 작성 시간, 보고서당 채점 시간, 규리의 가용 시간을 기록한다. 예상 사람 작업량은 사례 수에 따른 기준표 작업과 실행 수에 따른 채점 작업을 합쳐 추정한다. 2주차 말에 적격 사례 확보와 가용 시간 안에 들어오는 안을 선택해 사전등록을 고정한다. 다른 규모를 택하면 이유·예상 부담·감소한 분석 범위를 기록한다.

세 조건을 우선 유지한다. 두 조건만 가능하면 A0와 A1을 남겨 개선 전후를 평가한다. 이때 B 대비 이점은 주장하지 않는다. 4주차 동결 시점까지 기준표가 완성되지 않으면 최종 실행을 미루거나 사전 지정 축소안을 적용한다. 최종 모델 성적을 보고 규모를 바꾸지 않는다.

4. 포함·제외 기준과 자료 수집

4.1 포함 기준

모두 만족하는 사례를 핵심 데이터셋에 포함한다.

  • 국내 코스피 또는 코스닥 IPO의 비금융 발행사.
  • 주된 산정이 이미 발생한 실적을 이용한 PER.
  • 적용 이익, 배수 또는 비교기업 자료, 주식수, 산정 설명을 공개 문서에서 확인 가능.
  • 문서 버전과 공개 시점을 확인하고 원문을 보존 가능.
  • 공시값을 이용한 산술 재현과 공개 방법론 기반 판단 기준표 작성이 가능.
  • 핵심 주장의 독립 교차 확인 가능 범위를 기록할 수 있음.

이익 기준 태그: ANNUAL / LTM / ANNUALIZED_INTERIM.
조정 태그: UNADJUSTED / ADJUSTED_HISTORICAL. 두 태그는 별개다. 연환산·조정도 가정을 포함한다.

4.2 제외 기준

미래 추정이익 PER, 주된 EV/EBITDA·DCF 평가, 금융회사·SPAC·REIT, 핵심 문서 접근 불가, 공개 시점 확인 불가, 자연적인 판단 과제가 성립하지 않는 사례. 제외 이유는 기업마다 남긴다.

파일럿의 판단 난이도 기준은 “오류가 존재해야 함”이 아니다. 타당한 근거의 수용·조건부 판단·추가 확인 등 실질적 선택이 있어야 한다. 오류가 없는 문서를 제외하지 않는다.

4.4 자료의 증거 수준

수준 의미 가능한 채점
L1: 공시값 재현 신고서에 적힌 값을 다시 계산 추출·산술·표시 정밀도
L2: 원천 교차 확인 발행사·peer의 원래 공시 등과 대조 범위·기간·회계 항목의 일치
L3: 원천 미확인 유료 단말 등 원래 데이터를 직접 확보 못함 미확인 표시와 제한 설명만 평가

L1을 L2라고 쓰지 않는다. 해외 주가·환율 등의 원천이 무료로 확보되지 않으면 그 값의 독립 진실성을 채점하지 않는다. 해당 값을 전제로 한 산술은 별도 평가할 수 있다. 핵심 판단에 L3가 필수여서 검증 자체가 불가능하면 사례나 판단 항목의 범위를 축소한다.

4.5 시간과 정정본 처리

기업당 대표 문서 선택 규칙: 일반청약 시작 직전에 공개되어 있던 마지막 유효 투자설명서의 산정 내용을 사용한다. 같은 단계의 투자설명서가 없으면 증권신고서를 사용하고 대체 이유를 기록한다. 철회 거래는 철회 공시 직전 마지막 공개 산정 문서를 사용하고 별도 태그를 붙인다. 아직 그 단계에 이르지 않은 거래는 예비 목록에 남긴다. 선정은 모델 성과와 무관하게 수행한다.

대표 문서의 실제 공개일 종료시점을 기본 cutoff로 정한다. 이후 공개된 자료는 입력에서 제외한다. 파일럿 후보 링크는 출발점이며, DART 대조에서 더 적합한 대표 버전이 확인되면 그 버전을 채택한다. 문서 선택 규칙은 파일럿 후 최종 모집·분할 전에 동결한다. 예외는 이유와 영향, 적용 기업을 남기고 같은 유형에 동일 적용한다.

반드시 네 날짜를 분리한다.

  • published_at: 실제 공개 시각 또는 확인 가능한 공개일.
  • document_date: 문서에 적힌 작성·정정 날짜.
  • data_as_of: 주가 기준일 또는 재무기간 종료일.
  • cutoff_at: 연구자가 정한 입력 허용 마지막 시점.

시각을 확인할 수 없으면 date_precision=DATE를 기록하고 해당 날짜의 종료시점까지 공개된 자료를 허용하는 방식으로 통일한다. 장중 시점의 판단을 복원했다고 주장하지 않는다. 주가 기준일 이전의 지식만 필요한 주장에는 그 시점 이전 자료만 사용한다.

정정 투자설명서의 정정 전/후 표는 section_state=BEFORE / AFTER / CURRENT / UNKNOWN으로 구분한다. 현재 검토에는 CURRENT 또는 최신 AFTER의 값을 사용한다. BEFORE는 변경 이력 분석에만 사용한다. 구획을 확정하지 못하면 자동으로 현재값으로 채택하지 않는다.

4.6 문서 가공

  1. 원본 bytes와 SHA-256을 보존한다.
  2. XML·PDF에서 텍스트와 표를 추출하고, 표의 단위·헤더·주석을 함께 저장한다.
  3. 검색 chunk에 문서 ID, 페이지, 표 제목, 구획, 시점, 회사명·연결 범위를 붙인다.
  4. 일반 본문은 약 800–1,200토큰을 초기 목표로 나누되, 표와 주석은 가능하면 분리하지 않는다. 큰 표는 행 묶음으로 나누고 헤더를 반복한다.
  5. 전처리 규칙은 개발 자료에서 결정하고 최종 평가에 동일 적용한다.
  6. 사람은 깨진 OCR·표 구조를 원문과 대조해 고칠 수 있지만, 정답을 암시하는 해설은 입력에 추가하지 않는다. 변경을 모두 기록한다.
  7. 실험 실행 중에는 인터넷을 직접 검색하지 않고 고정된 문서 저장소만 사용한다. 자료 수집 단계의 웹 검색과 모델 실행 단계의 정보 접근을 구별한다.

OpenDART는 공식 원문 확보의 시작점이다. 원문 XML이 있다고 모든 판단 항목이 자동 구조화되는 것은 아니다.R02

6. 규리 한 명을 위한 기준표와 참고자료 카드

6.1 작성과 채점의 기본 원칙

기준표 작성·검토·최종 채점은 규리 한 명이 수행한다. 모든 항목에 읽을 원문 위치, 사례에서 확인할 사실, 점수를 정할 예시를 붙인다. 공통 방법서는 세 시스템에 동일 제공하고 사례별 값·허용 답이 있는 기준표는 숨긴다.

문헌의 원칙과 연구자의 운영규칙을 분리한다. 예를 들어 이익 정의를 일관되게 비교한다는 것은 문헌의 원칙이다. 0·1·2점, 필수 제출 항목, 추가 검토를 요청할 조건은 이 연구의 운영규칙이다. 자료에 없는 ±5%, 특정 국가·업종의 무조건 제외 규칙을 문헌의 결론으로 만들지 않는다.

6.4 C0 사실과 계산 카드

볼 자료: 사례의 산정표·표 주석·주식수 표, R18의 Definitional Tests.

확인 순서: 원문 값과 단위 → 이익 기간·지배주주/전체·연결/별도 범위 → 산식 → 주식수 → 표시 정밀도. 공시값 재계산과 독립 원천 확인은 L1/L2/L3로 나눈다.

  • 충족: 필수 값과 정의를 정확히 추출해 계산하고 결과 차이를 정밀도 규칙에 따라 설명했다.
  • 미충족: 다른 표의 단위를 그대로 섞거나 구주를 신주처럼 더하는 등 재계산이 틀렸다.
  • 판정 보류 예: 원래 시장가격을 확보하지 못했다면 그 값의 진실성은 미확인으로 남기되 공시값의 산술은 평가한다.

이 카드는 사실·계산 지표에 사용한다. J1–J4 판단 점수와 중복해 하나의 종합점수로 섞지 않는다.

연구자 규칙: 공개된 입력만으로 평균·중앙값 또는 peer 한 개 제외처럼 명시된 대안을 계산한다. 이것은 계산 영향을 관찰하는 장치이며 어느 대안이 최적인지 정하는 규칙이 아니다.

점수 판정 예시
2 기본값·대안·변경 이유가 명확하고 계산이 맞으며 변화의 방향·크기와 해석을 설명
1 계산은 맞지만 대안의 근거 또는 결과 해석이 불완전
0 근거 없는 새 숫자를 실제 사실처럼 사용하거나 계산·변화 방향이 틀림

공시가 이미 제시한 대안도 사용할 수 있다. 이 경우 재계산·영향 설명으로 채점하고 새로운 발견으로 포장하지 않는다. 차이가 작다는 결론도 인정하며 임의의 합격 오차를 추가하지 않는다.

6.8 J4 다음 행동 카드

볼 자료: 앞 카드에서 확인된 사실·자료의 부재·계산 영향. 이 카드의 요청·우선순위 판정 규칙은 본 연구가 정의한다.

사례별 미리 기입할 답: 이미 해결 가능한 쟁점, 필요한데 없는 자료, 공개 근거 충돌, 각 쟁점이 막는 결론, 허용 요청의 구체적인 예.

점수 판정 예시
2 확인된 것과 남은 것을 구별하고 관련 자료·다음 검토를 구체적으로 요청. 남은 문제가 없으면 근거 있는 완료
1 관련 요청이 있으나 필요한 이유·대상·우선순위가 불분명
0 일반적인 경고만 나열, 해결 가능한 일을 모두 보류, 중요한 미확인을 확인 완료라고 표시

추가 사람 검토는 동일한 문헌·공시를 더 확인할 필요가 있다는 요청이다. 요청의 필요성을 기준표로 판정할 수 없으면 그 항목을 GOLD_UNRESOLVED로 표시한다. 실제 전문가 필요성이나 실제 해결 성공을 측정했다고 쓰지 않는다.

6.9 작성·고정·채점 순서

  1. 규리가 모델 출력 전에 공통 방법서와 사례별 기준표를 작성한다.
  2. 원문 위치·계산·점수 예시를 스스로 대조한다. 제3자의 확인을 통과 조건으로 두지 않는다.
  3. 개발 자료에서만 판정 예시와 운영규칙을 다듬고 최종 평가 전 고정한다.
  4. 프로그램이 조건명·반복·실행 순서를 무작위 익명 ID로 바꾼 채점 사본을 만든다.
  5. 규리가 카드별로 채점하고 근거·점수 사유를 기록한다.
  6. 익명 ID를 조건과 다시 연결해 집계한다.

조건명을 가려도 규리가 문체·검증 흔적에서 추측할 수 있으므로 완전한 눈가림이라고 부르지 않는다. 평가자 간 일치율·독립 전문가 검증을 보고하지 않는다. 대신 출처 연결과 원문 대조 사유를 공개한다.

새롭고 타당한 지적은 기본 점수와 별도 기록한다. 기준표 오류를 수정하면 모든 조건·반복에 동일 재채점하고 원래 점수·사유·수정 영향을 보존한다. 최종 평가 후 규칙을 넓혀 만든 결과는 보조 분석으로 구분한다.

6.10 점수·판정 불가·핵심 오류

2점은 기준 충족, 1점은 부분 충족, 0점은 미충족이다. 주평가는 2점 항목의 비율이며 부분점수는 별도 진단이다. J1–J4 영역별 결과를 함께 보이고 비용·요청을 가중 합산하지 않는다.

항목별 0·1·2점 채점에서 NA는 GOLD_UNRESOLVED에 사용한다. 통계 지표에서는 분모가 0인 경우에도 NA를 사용하되 사유를 구분한다. 유효 항목이 없는 영역이 있으면 해당 기업의 주평가지표는 모든 조건에서 NA로 처리하며 남은 영역만 재평균하지 않는다. 그 기업도 오류·실패·비용 등 가능한 지표에는 남긴다. 판정 불가 비중과 사유를 함께 보고한다.

핵심 검토 오류는 사례의 필수 결론을 바꿀 수 있고 원문·산식·명시된 기준과 충돌하는 오류다. 존재하지 않는 근거, 정정 전 수치의 현재값 사용, 이익 기간 혼동 등이 해당할 수 있다. 사례별 오류와 영향을 미리 적는다. 이 명칭은 단일 평가자가 참고자료로 판정하는 연구상 분류이며 실무 손실의 확정값이 아니다.

7. 계산 도구와 숫자 허용 오차

7.1 기본 산식

단순화하면 다음과 같다. 실제 사례는 원문이 정의한 항목·조정·주식수를 따른다.

주주지분 평가액(평가 시가총액) = 적용 순이익 × 적용 PER
주당 평가가액 = 주주지분 평가액 ÷ 적용 주식수
희망 공모가 = 주당 평가가액 × (1 − 할인율)

PER로 산정한 값은 주주지분가치이며, 부채 등을 포함한 EV와 구별한다.

신주 발행, 구주 매출, 옵션·전환권, 추가 인수 주식의 반영은 원문과 계약 조건을 확인한다. 구주 매출을 신주 발행처럼 더하지 않는다. 배수 평균의 대상·가중 방식도 원문을 따른다.

7.2 숫자 판정 순서

  1. 단위와 통화, 기간, 이익의 범위부터 맞춘다.
  2. 공개된 원시값이 있으면 그 값으로 계산한다.
  3. 표시된 값만 있으면 반올림·절사 규칙을 확인한다.
  4. 규칙을 알 때 입력의 가능한 정밀도 구간을 전파하여 결과 범위를 구한다.
  5. 규칙을 모르거나 원천값이 없으면 “정밀도 설명 가능/미확인”을 구분하고 즉시 오류라고 단정하지 않는다.
  6. 계산 차이와 경제적 타당성은 별도 채점한다.

예를 들어 최근접 반올림으로 소수 첫째 자리까지 제시된 31.5의 가능한 원래 값은 통상 31.45 이상 31.55 미만이다. 그러나 실제 문서가 같은 반올림 규칙을 사용했다는 확인 없이 이 구간을 절대적인 사실로 쓰지 않는다.

7.3 도구 초기 기능

정확한 소수 연산, 단위 변환, 합계·비율·PER 계산, 공시된 이익 조정 재현, 연환산과 LTM 구분, 표기 정밀도 검사, 공개 peer 배수의 평균·중앙값·제외 민감도.

계산기는 모델이 준 숫자를 정확히 계산할 뿐 그 숫자가 원문에서 맞게 뽑혔는지는 보장하지 않는다. 계산 결과에는 입력 출처 ID도 남긴다.

8.2 B: 고정 절차

다음 순서를 코드로 고정한다.

  1. 문서 목록·버전·기간 확인.
  2. 고정된 질의 묶음으로 가치평가표·주식수·적용 이익·비교기업 자료 조회.
  3. 정해진 추출 양식 작성.
  4. 추출값을 계산 도구로 재계산.
  5. J1–J4 체크리스트 순서로 검토.
  6. 동일 출력 양식으로 제출.

질의는 기업명·문서 제목 등 메타데이터를 채워 만드는 방식으로 고정한다. 모델이 임의로 계획을 바꾸거나 검색을 반복하지 않는다. 내부 도구·산출물은 A0와 같으며 B도 미확인·정보 요청·이관을 보고할 수 있다.

8.3 A0: 기본 에이전트

공통 방법서·과제·도구를 주고 모델이 다음 행동을 선택한다. 사례별 정답 힌트·검사기 피드백을 제공하지 않는다. 공통 형식 검사와 계산 도구는 사용할 수 있으며, 불확실성을 표시하고 정보 요청·이관할 수 있다.

8.6 예산과 공정성

초기값은 사례당 모델 호출 16회, 도구 40회, 누적 입력 토큰 목표 상한 120,000, 출력 토큰 상한 16,000, 600초다. 검사 후 수정은 최대 2회다. 이 값은 파일럿에서 조정할 팀 제안값이며 최종 평가 전에 고정한다.

누적 입력은 대화 이력 재전송을 포함한 실제 API 사용량 기준으로 기록한다. 실행 전 토큰 추정으로 남은 예산을 관리하되 실제 청구 토큰과 차이가 생기면 초과량도 기록한다. 도구 반환 길이 제한과 잘린 자료의 후속 열람 방법은 모든 조건에서 같다.

최종 제출과 공통 형식 수정 1회도 호출·출력 예산에 포함한다. 최소한 최종 제출용 1회와 형식 수정용 1회, 파일럿에서 정한 출력 예산을 예약하고 탐색에 모두 쓰지 않게 한다. A1의 검증용 모델 호출도 같은 전체 상한에 포함한다.

A1 검사·재검토·추가 모델의 비용을 숨기지 않는다. B에 남는 예산을 억지로 소모시킬 필요는 없으나, 같은 자원 상한에서 비교하고 실제 소비량을 함께 보고한다. 모델 snapshot, decoding, API 버전, 캐시 사용과 실행 날짜를 고정·기록한다. 제공자가 seed를 지원하지 않으면 재현이 보장된다고 쓰지 않는다.

9.2 상태를 정하는 규칙

  • READY: 필수 형식을 채워 검토 초안을 제출했고, 실행 당시 중요한 미해결 정보 요청·사람 검토 요청을 표시하지 않은 상태.
  • PENDING_INFO: 중요한 판단에 필요한 정보가 아직 없고 요청이 남은 상태.
  • HUMAN_REVIEW: 해결되지 않은 해석·근거 충돌을 사람이 더 확인하도록 요청한 상태. 정보 요청도 함께 존재할 수 있다.
  • FAILED: 시간·자원 상한, 형식 불가, 실행 실패 등으로 유효한 최종 산출물을 제출하지 못한 상태.

최종 상태는 실행 제어기가 다음 구조적 규칙으로 계산한다.

유효 최종 제출 없음 → FAILED
미해결이며 blocking=true인 사람 검토 요청 있음 → HUMAN_REVIEW
미해결이며 blocking=true인 정보 요청 있음 → PENDING_INFO
그 외 → READY

각 요청·이관에 blocking, resolution_status, related_judgment_ids를 요구한다. blocking은 실행 당시 시스템이 해당 쟁점이 완료를 막는다고 표시한 값이다. 채점자가 사후에 중요성을 다르게 판단해도 final_status를 바꾸지 않고 잘못된 완료 또는 불필요한 보류로 채점한다. 이 실험에서는 실제 후속 응답을 주지 않으므로 정보·추가 사람 검토 요청은 원칙적으로 OPEN이다. 저장소에서 근거를 찾아 해소한 경우만 해결 근거와 함께 RESOLVED로 기록한다. 개별 항목 상태는 그대로 보존한다.

READY는 정답·안전·승인을 뜻하지 않는다. 사후 채점에서 잘못된 답을 READY에서 제외하지 않는다. 완성된 형식 안에 있는 틀린 판단이 바로 잔여 위험이다. 모든 상태의 제출물에 있는 오류를 별도로 집계한다.

조건부 수용이 실제로 중요한 미해결 가정에 의존하면 PENDING_INFO 또는 HUMAN_REVIEW로 표시해야 한다. 근거 없이 READY를 선택하면 잘못된 완료 처리로 채점한다.

10. 실행과 로그

10.1 한 번의 실행

  1. case_id·condition·repeat_id로 run_id 생성.
  2. 프롬프트·문서·도구 설정 해시 검증.
  3. 해당 사례만 접근 가능한 새 세션 시작.
  4. 조건에 따라 도구 실행. 중간 외부 출력과 도구 호출·결과 기록.
  5. 예산 도달 전 최종 제출을 요청. 실패 시 실패 원인을 보존.
  6. 원래 출력과 형식 검사의 결과 저장.
  7. 모델에게는 gold나 채점 결과를 돌려주지 않음.
  8. 실행 기록에서 조건·반복 정보를 제거한 채점용 사본 생성.

모델의 비공개 내부 사고과정을 요구하지 않는다. 평가에는 사용자에게 제시한 근거 요약, 실제 행동, 도구 결과, 최종 산출물을 기록한다.

11. 채점 지표와 분모

11.1 주평가지표: 방법론적 검토 충족률

사례 i, 반복 r, 조건 c에서 각 영역 J1–J4의 유효 기준표 항목 중 2점 항목 비율을 구한다. 네 영역 비율을 동일 가중 평균하여 V(i,r,c)를 만든다.

영역 방법론적 검토 충족률 = 2점 항목 수 / 해당 영역의 유효 필수 항목 수
V(i,r,c) = J1, J2, J3, J4 영역 방법론적 검토 충족률의 평균
기업별 점수 V(i,c) = 두 반복의 V 평균
조건별 점수 = 평가 기업의 V(i,c) 평균

FAILED에서 제출하지 못한 필수 항목은 0점이다. 단, 한 영역이라도 유효 gold 항목이 0이면 해당 기업의 주지표는 모든 조건·반복에서 NA로 처리한다. 나머지 영역만으로 재평균하지 않는다. 조건 비교는 모든 조건에 공통으로 유효한 기업만 사용하고 유효 기업 수와 제외 사유를 보고한다. 이 기업도 오류·실패·비용 등 산출 가능한 다른 지표에는 남긴다. 조건별로 유리한 기업만 분모에 남기지 않는다.

이 지표는 동일한 구성개념인 방법론 적용 품질을 요약한다. 비용·이관·오류를 가중 합산한 종합점수는 아니다. J1–J4별 결과도 반드시 함께 공개한다.

11.3 검사기 자체 평가

개발 및 최종 산출물에서 평가 담당자가 발견한, 각 검사기가 대상으로 삼는 오류를 기준으로 탐지·미탐·오탐을 집계한다. 검사기가 대상으로 삼지 않는 의미적 판단 오류까지 탐지율 분모에 넣지 않는다.

A1에서는 최초 제출 초안과 수정 후 최종본을 모두 저장한다. 수정으로 제거된 오류와 새로 생긴 오류를 기록한다. 이 전후 비교는 A1 내부의 변화이며, A0 대비 전체 효과와 구분한다.

12. 분석 방법

12.1 기본 비교

  1. 같은 기업의 두 반복을 먼저 평균한다.
  2. 실제 실행한 조건에 대해서만 기업별 차이를 계산한다. 세 조건이면 A0−B, A1−A0, A1−B를 계산하고, A0/A1 두 조건이면 A1−A0만 계산한다.
  3. 평균 차이와 기업별 분포를 모두 제시한다.
  4. 기업을 복원추출하는 paired bootstrap 10,000회로 차이의 95% 구간을 계산한다. 같은 기업의 모든 조건·반복은 함께 뽑는다.
  5. 비율 지표는 각 bootstrap 표본에서 분자·분모를 다시 계산한다. 분모 0인 표본의 횟수·비율을 공개한다. 해당 비율이 5%를 넘으면 불안정한 것으로 보고 구간을 제시하지 않는다. 5%는 사전 지정하는 보고 규칙이며 통계적 보장값이 아니다. 원래 분모·점추정·사례 분포는 그대로 보고한다.
  6. 연환산 여부·자료 수준·해외 peer 여부별 결과는 탐색적으로만 제시한다.
  7. 반복 간 판단 상태가 달라진 비율과 점수 차이를 별도 보고한다.

이 분석법과 반복 수는 팀이 사전 지정하는 방법이다. 20개 기업, 편의적 접근 가능 표본, 공통 peer 자료 의존성 때문에 구간을 전체 IPO 시장의 확정적 성능 보증으로 해석하지 않는다. 공통 문서가 집중된 기업 묶음을 제외한 민감도 분석도 함께 보이면 좋지만, 평가 결과를 본 뒤 유리한 제외 규칙을 고르지 않는다.

  • 비용과 실행 시간.
  • 어떤 기업·문서 구조에서 효과가 달랐는지.

실무 허용 수준을 사전 합의하지 못했다면 “배포 가능” 판정을 만들지 않는다. 실무적으로 의미 있는 최소 차이·허용 위험 수준을 정하고 충분한 표본을 설계한 경우에만 별도 우월성·비열등성 검정을 검토한다.R10

14. 사람 참여와 실제 업무 적용 주장

14.1 핵심 연구의 사람 참여

규리 한 명이 기준표 작성·원문 대조·결과 채점을 맡는다. 추가 사람 검토 요청은 시스템의 기록 행동이다. 요청이 기준표와 맞는지를 채점하며, 규리가 채점을 위해 보고서를 읽었다고 요청이 해결된 것으로 집계하지 않는다.

14.2 실제 후속 검토는 별도 모듈

후속 확인을 실제로 수행한다면 요청 시점 출력, 사람이 추가로 확인한 근거, 수정 결과, 소요 시간, 남은 문제를 따로 저장한다. 이 모듈을 하지 않은 핵심 연구에서는 사람 개입 후 품질·시간 절감을 주장하지 않는다. 단일 평가자가 자신이 만든 답을 아는 조건이라는 한계도 기록한다.

14.3 실무 연결 산출물

  • 시험한 자료 구조에서 도구로 재현·검증할 수 있었던 작업.
  • 원문 근거와 한계를 붙여 보조할 수 있었던 해석.
  • 실행 중 관찰 가능한 추가 사람 검토·정보 요청 조건.
  • 문헌과 공개자료로 판단을 확정하지 못한 영역.

이 분류를 실제 결과로 채운다. 사람 요청의 필요성은 본 연구 기준표의 적합성으로 해석하고 독립적인 전문가 판단을 검증했다고 쓰지 않는다.

15. 선택 확장: 후속 공시·전향적 관찰

핵심 평가와 분리한 보조 모듈이다. 2026-11-01부터 11-10 사이에 적격 후속 발표가 있으면 추가할 수 있지만, 현재 해당 기간의 적격 기업 일정이 확보되었다고 가정하지 않는다.

  1. 후속 문서 공개 전에 사례·cutoff·입력·검토 메모·해시를 고정한다.
  2. 사전에 “어떤 판단이 어떤 새 자료로 확인되는가”를 적는다.
  3. 이후 정정, 최종 가격, 후속 재무자료를 별도 저장소에 수집한다.
  4. 검토 항목과 후속 증거를 연결하되, 회사가 수정하지 않은 질문을 자동 오답 처리하지 않는다.
  5. 추가 자료로 해소된 문제와 아직 알 수 없는 문제를 구분한다.

이미 정정 전후 내용이 함께 있는 최종 PDF를 과거 시점 입력으로 사용하지 않는다. 원래 시점의 파일을 확보하는 것이 우선이다. 구획을 제거해 시점을 복원한다면 원본·제거 범위·이유를 남기고 자연 원문 그대로의 실험과 구분한다.

과거 자료를 현재 모델로 실행하면 사전학습으로 이미 내용을 알고 있을 가능성이 남는다. 완전한 비오염을 주장하지 않는다.R08 R11
