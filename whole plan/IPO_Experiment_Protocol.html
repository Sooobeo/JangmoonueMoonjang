1.3 허용되는 최종 결론

같은 검토량에서 실제 중대 쟁점이 목록 밖에 남은 건수와 비율의 차이, 기업별 방향과 처리 비용을 보고한다. 효과가 작거나 불확실하면 표본에서 관찰한 효과 크기와 후속 검증 범위를 함께 제시한다. 카나리 성공을 자동 통과에 사용하는 것은 별도 검증을 거친 후속 결정이다. 연구 대상은 최초 신고서의 산정근거다. R01

3.2 확보 규모와 평가 표본

기존 작업으로 개발 6기업 입력·기준표를 구축했고 평가 후보 12기업의 원문·적격성·배정을 정리했다. A1 평가에는 최초 신고서 기반 입력과 원본 기준표가 필요하다. 카나리 파일럿에서 실제 중대 쟁점의 기업별 빈도와 자료 제작·채점 시간을 측정한 뒤 최종 기업 수를 사전 등록한다. 모집·배정 기록

3.3 모집·분할 절차

  1. 모집대장의 기존 배정과 제외 근거를 사용한다. 추가 모집은 DART·KIND의 최초 신고서로 동일 기준을 적용하고 조사 기간과 입·제외 근거를 기록한다. R02
  2. 팀이 개발에서 자세히 분석한 기업은 개발 묶음에 둔다. 평가 후보는 최초 신고서, 당시 가용 자료, 비교기업 원천과 문서 중첩을 확인한다.
  3. 연간·LTM·중간실적 연환산, 국내·해외 비교기업, 시장 구분을 기록한다. 필요 표본을 정한 이유와 기준표 역할 분리를 평가 출력 생성 전에 확정한다.

3.4 작업량에 따른 규모 선택

12기업 안팎이면 카나리 신호의 독립 기업 수가 제한된다. 파일럿의 자연 중대 쟁점 빈도, 변형 제작 시간, 검토당 모델 비용으로 규모와 운영 모드를 산정한다. 원본에 대한 공통 필수 검토와 동일 추가량 K를 두 핵심 조건에 적용한다. K, 실행 중 중대성 기준, 정렬 규칙 및 평가용 심은 쟁점의 사용 여부를 결과 확인 전에 고정한다.

기존 120회·72회는 고정 절차 B/A0/A1을 반복 비교하던 v2 예산 산식이다. A1은 세 목록 조건과 모델 실행 수를 구별하여 8.6절로 새로 계산한다.

4. 포함·제외 기준과 자료 수집

4.1 포함 기준

모두 만족하는 사례를 핵심 데이터셋에 포함한다.

  • 국내 코스피 또는 코스닥 IPO의 비금융 발행사.
  • 주된 산정이 이미 발생한 실적을 이용한 PER.
  • 적용 이익, 배수 또는 비교기업 자료, 주식수, 산정 설명을 공개 문서에서 확인 가능.
  • 문서 버전과 공개 시점을 확인하고 원문을 보존 가능.
  • 공시값을 이용한 산술 재현과 공개 방법론 기반 판단 기준표 작성이 가능.
  • 핵심 주장의 독립 교차 확인 가능 범위를 기록할 수 있음.

이익 기준 태그: ANNUAL / LTM / ANNUALIZED_INTERIM.
조정 태그: UNADJUSTED / ADJUSTED_HISTORICAL. 두 태그는 별개다. 연환산·조정도 가정을 포함한다.

4.2 제외 기준

미래 추정이익 PER, 주된 EV/EBITDA·DCF 평가, 금융회사·SPAC·REIT, 핵심 문서 접근 불가, 공개 시점 확인 불가, 자연적인 판단 과제가 성립하지 않는 사례. 제외 이유는 기업마다 남긴다.

파일럿의 판단 난이도 기준은 “오류가 존재해야 함”이 아니다. 타당한 근거의 수용·조건부 판단·추가 확인 등 실질적 선택이 있어야 한다. 오류가 없는 문서를 제외하지 않는다.

4.4 자료의 증거 수준

수준 의미 가능한 채점
L1: 공시값 재현 신고서에 적힌 값을 다시 계산 추출·산술·표시 정밀도
L2: 원천 교차 확인 발행사·peer의 원래 공시 등과 대조 범위·기간·회계 항목의 일치
L3: 원천 미확인 유료 단말 등 원래 데이터를 직접 확보 못함 미확인 표시와 제한 설명만 평가

L1을 L2라고 쓰지 않는다. 해외 주가·환율 등의 원천이 무료로 확보되지 않으면 그 값의 독립 진실성을 채점하지 않는다. 해당 값을 전제로 한 산술은 별도 평가할 수 있다. 핵심 판단에 L3가 필수여서 검증 자체가 불가능하면 사례나 판단 항목의 범위를 축소한다.

4.5 시간과 정정본 처리

기업당 대표 문서는 최초 증권신고서다. 최초 신고서가 공개될 당시 확인할 수 있던 자료를 입력으로 고정하고, 기관 수요예측 전에 희망 공모가 산정근거를 검토하는 상황을 재구성한다. 대표 문서의 접수번호·공개 시점과 처음 공개된 버전의 해시를 기록한다. 후속 정정·투자설명서는 별도 사후 자료로 보관한다.

반드시 네 날짜를 분리한다.

  • published_at: 실제 공개 시각 또는 확인 가능한 공개일.
  • document_date: 문서에 적힌 작성·정정 날짜.
  • data_as_of: 주가 기준일 또는 재무기간 종료일.
  • cutoff_at: 연구자가 정한 입력 허용 마지막 시점.

시각을 확인할 수 없으면 date_precision=DATE를 기록하고 해당 날짜의 종료시점까지 공개된 자료를 허용하는 방식으로 통일한다. 장중 시점의 판단을 복원했다고 주장하지 않는다. 주가 기준일 이전의 지식만 필요한 주장에는 그 시점 이전 자료만 사용한다.

기존 개발 문서와 사후 비교용 정정본에서는 section_state=BEFORE / AFTER / CURRENT / UNKNOWN을 보존한다. A1 입력에는 최초 시점 이후 정정본이 혼입됐는지 확인한다.

4.6 문서 가공

  1. 원본 bytes와 SHA-256을 보존한다.
  2. XML·PDF에서 텍스트와 표를 추출하고, 표의 단위·헤더·주석을 함께 저장한다.
  3. 검색 chunk에 문서 ID, 페이지, 표 제목, 구획, 시점, 회사명·연결 범위를 붙인다.

  5. 전처리 규칙은 개발 자료에서 결정하고 최종 평가에 동일 적용한다.
  6. 사람은 깨진 OCR·표 구조를 원문과 대조해 고칠 수 있지만, 정답을 암시하는 해설은 입력에 추가하지 않는다. 변경을 모두 기록한다.
  7. 실험 실행 중에는 인터넷을 직접 검색하지 않고 고정된 문서 저장소만 사용한다. 자료 수집 단계의 웹 검색과 모델 실행 단계의 정보 접근을 구별한다.

OpenDART는 공식 원문 확보의 시작점이다. 원문 XML이 있다고 모든 판단 항목이 자동 구조화되는 것은 아니다.R02

6. 원본 기준표와 참고자료 카드

6.1 작성과 채점의 기본 원칙

규리가 원본 기준표 작성·검토·최종 채점을 담당한다. 모든 항목에 원문 위치, 사례의 사실, 판정 예시를 붙인다. 원본 기준표와 시험 정답은 모델·검색 인덱스·카나리 제작에 제공하지 않는다. 현실적인 카나리는 두 사람이 각자 판정 가능성과 중대성을 확인하며, 여건에 따라 원본 판단의 일부를 독립 2차 확인한다.

문헌의 원칙과 연구자의 운영규칙을 분리한다. 예를 들어 이익 정의를 일관되게 비교한다는 것은 문헌의 원칙이다. 0·1·2점, 필수 제출 항목, 추가 검토를 요청할 조건은 이 연구의 운영규칙이다. 자료에 없는 ±5%, 특정 국가·업종의 무조건 제외 규칙을 문헌의 결론으로 만들지 않는다.

A1은 각 원본 항목에 사실·계산형 또는 판단형, 사전 연결된 오류 유형, 수용 가능·중대 쟁점·판정 유보, 원문 근거와 영향·유보 사유를 기록한다. 규리는 실행 중 중대 판정과 별개로 원문과 결론의 영향을 판정하며, 원본·시험 코딩은 서로 다른 양식에 남긴다.

6.4 C0 사실과 계산 카드

볼 자료: 사례의 산정표·표 주석·주식수 표, R18의 Definitional Tests.

확인 순서: 원문 값과 단위 → 이익 기간·지배주주/전체·연결/별도 범위 → 산식 → 주식수 → 표시 정밀도. 공시값 재계산과 독립 원천 확인은 L1/L2/L3로 나눈다.

  • 충족: 필수 값과 정의를 정확히 추출해 계산하고 결과 차이를 정밀도 규칙에 따라 설명했다.
  • 미충족: 다른 표의 단위를 그대로 섞거나 구주를 신주처럼 더하는 등 재계산이 틀렸다.
  • 판정 보류 예: 원래 시장가격을 확보하지 못했다면 그 값의 진실성은 미확인으로 남기되 공시값의 산술은 평가한다.

이 카드는 사실·계산 지표에 사용한다. J1–J4 판단 점수와 중복해 하나의 종합점수로 섞지 않는다.

6.5 J1 적용 이익 카드

볼 자료: R17 Summary의 이익 정의·정상화 설명. 정상화 가정이 실제 쟁점이면 R19의 규모 변화·회복 시점. 사례의 이익 산정표·조정 주석.

사례별 미리 기입할 답: 적용 기간, 연환산 산식, 조정 항목과 금액, 발행사와 peer의 이익 기준 차이, 해당 공시에 제시된 이유와 미확인 전제.

점수 판정 예시
2 정의·기간·조정을 정확히 구분하고 비교에 주는 영향·제약을 근거로 설명. 필요한 확인을 구체화
1 반기 연환산·조정 사실은 맞지만 그 가정이나 비교상 제약의 설명이 불완전
0 반기·연간·LTM를 같은 값처럼 사용하거나 조정 사실만으로 오류라고 단정

근거 있는 수용도 2점이 가능하다. 모든 기업에 이익 조정을 요구하거나 긴 정상화 시계열을 새로 추정하도록 강제하지 않는다.

6.6 J2 비교기업 카드

볼 자료: R18의 Analytical / Application Tests, R01의 산정·비교기업 검토 부분. 발행사와 peer의 사업·이익·위험 설명.

사례별 미리 기입할 답: 실제로 확인한 유사성과 차이, 배수 비교에 관련되는 이유, 이를 설명하는 원문, 허용할 수용·조건부 수용·추가 정보 요청의 논거.

점수 판정 예시
2 실제 유사성·차이를 제시하고 비교의 제약 또는 보완을 연결한 결론
1 차이를 확인했지만 배수 비교에 미치는 영향이나 필요한 보완이 불완전
0 업종명·국가·회사의 선정 사실만으로 적절·부적절을 단정하거나 사실을 잘못 읽음

특정 peer의 포함·제외를 유일한 정답으로 두지 않는다. 원문과 원칙이 지지하면 서로 다른 결론을 인정한다. 관련 변수의 중요도를 정할 근거가 없으면 임의 가중치를 만들지 않고 미확인으로 남긴다.

6.7 J3 민감도 카드

볼 자료: R17의 central tendency와 R18의 Descriptive Tests. 사례 산정표와 공시된 대안.

연구자 규칙: 공개된 입력만으로 평균·중앙값 또는 peer 한 개 제외처럼 명시된 대안을 계산한다. 이것은 계산 영향을 관찰하는 장치이며 어느 대안이 최적인지 정하는 규칙이 아니다.

점수 판정 예시
2 기본값·대안·변경 이유가 명확하고 계산이 맞으며 변화의 방향·크기와 해석을 설명
1 계산은 맞지만 대안의 근거 또는 결과 해석이 불완전
0 근거 없는 새 숫자를 실제 사실처럼 사용하거나 계산·변화 방향이 틀림

공시가 이미 제시한 대안도 사용할 수 있다. 이 경우 재계산·영향 설명으로 채점하고 새로운 발견으로 포장하지 않는다. 차이가 작다는 결론도 인정하며 임의의 합격 오차를 추가하지 않는다.

6.8 J4 다음 행동 카드

볼 자료: 앞 카드에서 확인된 사실·자료의 부재·계산 영향. 이 카드의 요청·우선순위 판정 규칙은 본 연구가 정의한다.

사례별 미리 기입할 답: 이미 해결 가능한 쟁점, 필요한데 없는 자료, 공개 근거 충돌, 각 쟁점이 막는 결론, 허용 요청의 구체적인 예.

점수 판정 예시
2 확인된 것과 남은 것을 구별하고 관련 자료·다음 검토를 구체적으로 요청. 남은 문제가 없으면 근거 있는 완료
1 관련 요청이 있으나 필요한 이유·대상·우선순위가 불분명
0 일반적인 경고만 나열, 해결 가능한 일을 모두 보류, 중요한 미확인을 확인 완료라고 표시

추가 사람 검토는 동일한 문헌·공시를 더 확인할 필요가 있다는 요청이다. 요청의 필요성을 기준표로 판정할 수 없으면 그 항목을 GOLD_UNRESOLVED로 표시한다. 실제 전문가 필요성이나 실제 해결 성공을 측정했다고 쓰지 않는다.

6.9 작성·고정·채점 순서

  1. 규리가 모델 출력 전에 공통 방법서와 사례별 기준표를 작성한다.
  2. 원문 위치·계산·점수 예시를 검토한다. 할 수 있는 범위에서 두 번째 사람이 원본 판단 일부를 시스템 결과를 가린 채 독립 확인하고, 불일치와 해결 방식을 기록한다.
  3. 개발 자료에서만 판정 예시와 운영규칙을 다듬고 최종 평가 전 고정한다.
  4. 프로그램이 조건명·반복·실행 순서를 무작위 익명 ID로 바꾼 채점 사본을 만든다.
  5. 규리가 카드별로 채점하고 근거·점수 사유를 기록한다.
  6. 익명 ID를 조건과 다시 연결해 집계한다.

조건명을 가려도 규리가 문체·검증 흔적에서 추측할 수 있으므로 완전한 눈가림이라고 부르지 않는다. 출처 연결과 원문 대조 사유를 공개한다. 독립 2차 확인을 하면 확인 범위와 일치·불일치 기록을 함께 보고한다.

새롭고 타당한 지적은 기본 점수와 별도 기록한다. 기준표 오류를 수정하면 모든 조건·반복에 동일 재채점하고 원래 점수·사유·수정 영향을 보존한다. 최종 평가 후 규칙을 넓혀 만든 결과는 보조 분석으로 구분한다.

6.10 점수·판정 불가·핵심 오류

기존 보고서의 보조 채점에서 2점은 기준 충족, 1점은 부분 충족, 0점은 미충족이다. 충족률은 2점 항목의 비율이며 부분점수는 별도 진단이다. J1–J4 영역별 결과를 함께 보이고 비용·요청을 가중 합산하지 않는다.

항목별 0·1·2점 채점에서 NA는 GOLD_UNRESOLVED에 사용한다. 통계 지표에서는 분모가 0인 경우에도 NA를 사용하되 사유를 구분한다. 유효 항목이 없는 영역이 있으면 해당 기업의 방법론적 검토 충족률은 모든 조건에서 NA로 처리하며 남은 영역만 재평균하지 않는다. 그 기업도 오류·실패·비용 등 가능한 지표에는 남긴다. 판정 불가 비중과 사유를 함께 보고한다.

핵심 검토 오류는 사례의 필수 결론을 바꿀 수 있고 원문·산식·명시된 기준과 충돌하는 오류다. 존재하지 않는 근거, 정정 전 수치의 현재값 사용, 이익 기간 혼동 등이 해당할 수 있다. 사례별 오류와 영향을 미리 적는다. 이 명칭은 단일 평가자가 참고자료로 판정하는 연구상 분류이며 실무 손실의 확정값이 아니다.

7. 계산 도구와 숫자 허용 오차

7.1 기본 산식

단순화하면 다음과 같다. 실제 사례는 원문이 정의한 항목·조정·주식수를 따른다.

주주지분 평가액(평가 시가총액) = 적용 순이익 × 적용 PER
주당 평가가액 = 주주지분 평가액 ÷ 적용 주식수
희망 공모가 = 주당 평가가액 × (1 − 할인율)

PER로 산정한 값은 주주지분가치이며, 부채 등을 포함한 EV와 구별한다.

신주 발행, 구주 매출, 옵션·전환권, 추가 인수 주식의 반영은 원문과 계약 조건을 확인한다. 구주 매출을 신주 발행처럼 더하지 않는다. 배수 평균의 대상·가중 방식도 원문을 따른다.

7.2 숫자 판정 순서

  1. 단위와 통화, 기간, 이익의 범위부터 맞춘다.
  2. 공개된 원시값이 있으면 그 값으로 계산한다.
  3. 표시된 값만 있으면 반올림·절사 규칙을 확인한다.
  4. 규칙을 알 때 입력의 가능한 정밀도 구간을 전파하여 결과 범위를 구한다.
  5. 규칙을 모르거나 원천값이 없으면 “정밀도 설명 가능/미확인”을 구분하고 즉시 오류라고 단정하지 않는다.
  6. 계산 차이와 경제적 타당성은 별도 채점한다.

예를 들어 최근접 반올림으로 소수 첫째 자리까지 제시된 31.5의 가능한 원래 값은 통상 31.45 이상 31.55 미만이다. 그러나 실제 문서가 같은 반올림 규칙을 사용했다는 확인 없이 이 구간을 절대적인 사실로 쓰지 않는다.

7.3 도구 초기 기능

정확한 소수 연산, 단위 변환, 합계·비율·PER 계산, 공시된 이익 조정 재현, 연환산과 LTM 구분, 표기 정밀도 검사, 공개 peer 배수의 평균·중앙값·제외 민감도.

계산기는 모델이 준 숫자를 정확히 계산할 뿐 그 숫자가 원문에서 맞게 뽑혔는지는 보장하지 않는다. 계산 결과에는 입력 출처 ID도 남긴다.

8.2 기존 개발의 고정 절차 B

아래는 고정 절차 B의 개발 계약이다. 실행 버전별 구현과 결과는 당시 기록을 참조한다. A1의 독립 검토자 B는 8.4절에서 정의한다.

다음 순서를 코드로 고정한다.

  1. 문서 목록·버전·기간 확인.
  2. 고정된 질의 묶음으로 가치평가표·주식수·적용 이익·비교기업 자료 조회.
  3. 정해진 추출 양식 작성.
  4. 추출값을 계산 도구로 재계산.
  5. J1–J4 체크리스트 순서로 검토.
  6. 동일 출력 양식으로 제출.

질의는 기업명·문서 제목 등 메타데이터를 채워 만드는 방식으로 고정한다. 모델이 임의로 계획을 바꾸거나 검색을 반복하지 않는다. 내부 도구·산출물은 A0와 같으며 B도 미확인·정보 요청·이관을 보고할 수 있다.

8.3 A0: 기본 에이전트

공통 방법서·과제·도구를 주고 모델이 다음 행동을 선택한다. 사례별 정답 힌트·검사기 피드백을 제공하지 않는다. 공통 형식 검사와 계산 도구는 사용할 수 있으며, 불확실성을 표시하고 정보 요청·이관할 수 있다.

검토 실행과 개별 API 호출을 구별한다. 모델·도구 호출, 누적 입력·출력 토큰과 캐시, 실행 시간과 비용, 불명 사용량을 조건별로 기록한다. 운영 비용이 높으면 같은 비용의 A0 반복 실행을 보조 기준선으로 둔다. 모델·API 버전, 설정, 실행 일시와 자료 해시를 보존한다.

9.2 상태를 정하는 규칙

  • READY: 필수 형식을 채워 검토 초안을 제출했고, 실행 당시 중요한 미해결 정보 요청·사람 검토 요청을 표시하지 않은 상태.
  • PENDING_INFO: 중요한 판단에 필요한 정보가 아직 없고 요청이 남은 상태.
  • HUMAN_REVIEW: 해결되지 않은 해석·근거 충돌을 사람이 더 확인하도록 요청한 상태. 정보 요청도 함께 존재할 수 있다.
  • FAILED: 시간·자원 상한, 형식 불가, 실행 실패 등으로 유효한 최종 산출물을 제출하지 못한 상태.

최종 상태는 실행 제어기가 다음 구조적 규칙으로 계산한다.

유효 최종 제출 없음 → FAILED
미해결이며 blocking=true인 사람 검토 요청 있음 → HUMAN_REVIEW
미해결이며 blocking=true인 정보 요청 있음 → PENDING_INFO
그 외 → READY

각 요청·이관에 blocking, resolution_status, related_judgment_ids를 요구한다. blocking은 실행 당시 시스템이 해당 쟁점이 완료를 막는다고 표시한 값이다. 채점자가 사후에 중요성을 다르게 판단해도 final_status를 바꾸지 않고 잘못된 완료 또는 불필요한 보류로 채점한다. 이 실험에서는 실제 후속 응답을 주지 않으므로 정보·추가 사람 검토 요청은 원칙적으로 OPEN이다. 저장소에서 근거를 찾아 해소한 경우만 해결 근거와 함께 RESOLVED로 기록한다. 개별 항목 상태는 그대로 보존한다.

READY는 정답·안전·승인을 뜻하지 않는다. 사후 채점에서 잘못된 답을 READY에서 제외하지 않는다. 완성된 형식 안에 있는 틀린 판단이 바로 잔여 위험이다. 모든 상태의 제출물에 있는 오류를 별도로 집계한다.

조건부 수용이 실제로 중요한 미해결 가정에 의존하면 PENDING_INFO 또는 HUMAN_REVIEW로 표시해야 한다. 근거 없이 READY를 선택하면 잘못된 완료 처리로 채점한다.

A1에서 유효한 카나리 공동 미탐은 우선순위에만 반영한다. 원본 상태와 원본 오류는 각각 실행 규칙과 원본 근거로 판정한다.

10. 실행과 로그

  1. 최초 공개 원본의 A0 보고서와 1층 사실·계산 기록을 확보한다. 가림 처리된 입력으로 B의 독립 재구성을 받는다.
  2. A0·B를 별도 변형본에서 실행하고 원본·변형본별 근거, 변형 ID, 탐지·미확인 상태를 저장한다.
  3. 대조기에서 원본 A0·B 판단을 비교한다. 두 조건이 공유하는 필수 검토 목록과 동일 K 조건의 두 추가 목록을 만든다.
  4. 목록 작성 후 원본 사람 기준표를 열어 목록 안팎을 채점한다. 변형본 탐지 채점과 평가용 심은 쟁점 채점은 원본 평가와 별도 기록한다.

10.1 한 번의 실행

  1. case_id·reviewer_role·document_variant_id·repeat_id로 run_id를 생성한다. 원본과 각 변형본의 입력 해시를 별도로 기록한다.
  2. 프롬프트·문서·도구 설정 해시 검증.
  3. 해당 사례만 접근 가능한 새 세션 시작.
  4. 조건에 따라 도구 실행. 중간 외부 출력과 도구 호출·결과 기록.
  5. 예산 도달 전 최종 제출을 요청. 실패 시 실패 원인을 보존.
  6. 원래 출력과 형식 검사의 결과 저장.
  7. 모델에게는 gold나 채점 결과를 돌려주지 않음.
  8. 실행 기록에서 조건·반복 정보를 제거한 채점용 사본 생성.

모델의 비공개 내부 사고과정을 요구하지 않는다. 평가에는 사용자에게 제시한 근거 요약, 실제 행동, 도구 결과, 최종 산출물을 기록한다.

10.2 실행 순서와 반복

원본·변형본 순서를 섞고 검토자·반복마다 새 세션을 쓴다. 이전 입력·출력과 상대 검토자의 답을 이어주지 않는다. 파일명·요약·검색 결과에서 시험의 단서가 드러나는지 확인한다. 두 핵심 목록의 비교에는 같은 원본 기록을 재사용한다.

11. 채점 지표와 분모

11.1 주평가지표와 보조 점수

두 핵심 조건에서 원본 검토 목록 안팎의 항목을 모두 사람 기준표로 채점한다. 주평가는 같은 공통 필수 검토와 추가량 K를 적용했을 때 목록 밖에 남은 자연 중대 쟁점의 건수와 비율이다.

목록 밖 중대 쟁점 비율 = 목록 밖 실제 중대 쟁점 수 / 전체 실제 중대 쟁점 수
목록 밖 실제 항목의 중대 쟁점률 = 목록 밖 실제 중대 쟁점 수 / 목록 밖의 판정 가능한 실제 항목 수

각 지표의 분자와 분모를 함께 보고한다. 판정 유보는 건수·사유를 제시하고 판정 가능 항목과 구분한다. 분모가 0이면 0% 대신 해당 없음으로 기록한다.

아래 방법론적 검토 충족률은 A0 보고서의 보조 평가와 기존 개발 검토에 사용한다.

사례 i, 반복 r, 조건 c에서 각 영역 J1–J4의 유효 기준표 항목 중 2점 항목 비율을 구한다. 네 영역 비율을 동일 가중 평균하여 V(i,r,c)를 만든다.

영역 방법론적 검토 충족률 = 2점 항목 수 / 해당 영역의 유효 필수 항목 수
V(i,r,c) = J1, J2, J3, J4 영역 방법론적 검토 충족률의 평균
기업별 점수 V(i,c) = 두 반복의 V 평균
조건별 점수 = 평가 기업의 V(i,c) 평균

FAILED에서 제출하지 못한 필수 항목은 0점이다. 단, 한 영역이라도 유효 gold 항목이 0이면 해당 기업의 충족률은 모든 조건·반복에서 NA로 처리한다. 나머지 영역만으로 재평균하지 않는다. 조건 비교는 모든 조건에 공통으로 유효한 기업만 사용하고 유효 기업 수와 제외 사유를 보고한다. 이 기업도 오류·실패·비용 등 산출 가능한 다른 지표에는 남긴다. 조건별로 유리한 기업만 분모에 남기지 않는다.

이 지표는 동일한 구성개념인 방법론 적용 품질을 요약한다. 비용·이관·오류를 가중 합산한 종합점수는 아니다. J1–J4별 결과도 반드시 함께 공개한다.

11.2 반드시 병행할 지표

  • 원본을 두 검토자가 모두 수용한 항목의 실제 쟁점률을 시험 탐지 0명·1명·2명·미확인별로 집계한다.
  • 유형별 유효 카나리에서 두 검토자가 함께 놓친 비율을 보고한다. 실제 공동 놓침률을 검토자별 놓침률의 곱과 비교하고, 한쪽 놓침률이 0이면 배수는 생략한다.
  • 카나리 유형과 실제 쟁점의 연결, 정상 대조의 목표 유형 오경보, 반복 실행의 탐지 변동을 기록한다.
  • 실행 중 중대 판정과 원본 사람 판정이 어긋난 건수, 사람 필수·추가 검토량, 모델 호출·토큰·시간·비용을 보고한다. 후속 정정 적중은 보조 지표다.

11.3 검사기·카나리 자체 평가

사실·계산 검사는 원문 대조 및 독립 재계산으로 미탐·오경보를 확인한다. 판단형 시험에는 명백한 오류, 현실적인 오류, 정상 대조의 역할을 기록한다. 명백한 오류는 기본 작동 확인용이다. 원본 순위에는 해당 위험과 연결된 현실적인 카나리의 유효 결과를 사용한다. 대상 유형의 정상 후보에 근거 없는 문제를 붙이면 오경보로 보고한다.

12. 분석 방법

12.1 기업 단위 짝 비교

두 핵심 목록을 같은 기업과 같은 A0·B 원본 판단으로 짝짓는다. 각 기업의 목록 밖 자연 중대 쟁점 수와 차이, 카나리 조건이 더 적게·더 많이·같게 놓친 기업 수, 전체 분자와 분모를 보고한다. 필요하면 기업 단위의 짝을 유지해 불확실성을 추정한다. 같은 기업·유형의 신호를 공유하는 항목 수와 변형 수는 독립 기업 수와 구분한다.

A0 단독, 무작위 동일 개수, 명백한 오류만 사용한 방식, 동일 비용 A0 반복은 보조 비교로 사전 지정할 수 있다. 상태별 오류와 READY 비율도 함께 본다.

12.2 소표본과 심은 쟁점

자연 중대 쟁점이 드물면 기업별 차이가 매우 작게 관측될 수 있다. 개발 파일럿의 기저율을 재고, 평가 기업 수와 평가용 심은 쟁점 사용 여부를 정한다. 필요하면 평가 기업별 원본 사본에 같은 유형의 현실적인 문제를 하나 넣는다. 신호용 카나리와 다른 후보로 만들고 위치는 평가 담당자만 알도록 한 뒤, 같은 검토량에서 두 목록이 이를 포착했는지 평가한다.

자연 쟁점이 본 분석이다. 같은 유형에서 만든 심은 쟁점은 효과가 더 크게 관측될 수 있어 결과와 추가 실행 비용을 별도로 제시한다. 기업 수가 적으면 효과 크기와 후속 검증 필요성을 보고한다. 자동 통과는 실제 누락 감소, 기업 간 일관성, 탐지 상태별 근거와 정상 대조의 오경보를 확인한 뒤 별도로 검증한다.

12.3 결과표의 필수 열

자연 쟁점 결과표에 기업 ID, 판정 가능·유보 항목 수, 실제 중대 쟁점 수, 공통 필수 검토 수, 추가 검토 수, 기본·카나리 목록 밖 중대 쟁점 수와 차이를 넣는다. 각 표에 독립 기업 수를 표시한다. 별도 진단표에는 유형별 시험 수, 검토자별 탐지, 공동 놓침, 미확인·오경보, 원본 항목 연결, 사용량·비용을 넣는다. 평가용 심은 쟁점을 사용한 경우 별도 결과표에 포착 여부와 추가 실행 비용을 기록한다.

13.1 현실적인 비교기업 카나리 제작

  1. 최초 신고서의 업종·재무·사업 유사성 선정 기준을 원문 위치와 함께 옮긴다.
  2. 같은 업종 상장사 중 1차 기준은 통과하고 매출원·고객·판매 방식이 다른 후보를 찾는다. 자료에서 차이를 뒷받침하는 원문 위치 두 곳 이상을 기록한다.
  3. 원본 기준일과 방식으로 배수를 계산하고, 교체 시 적용 배수와 주당 평가가액 변화를 확인한다.
  4. 사업 구조가 유사하고 배수 변화가 가능한 한 비슷한 정상 대조 후보를 찾는다. 두 사본은 후보 자료, 최종 목록·선정 설명, 배수와 평가가액을 함께 바꾸고 수정 내역을 기록한다.
  5. 검토자에게 시험 후보가 드러나는 문항·파일명·검색 단서를 제거한다. 채점표에는 유형·목표 항목·증거·중대성·탐지와 오경보 기준을 고정한다.
  6. 두 사람이 원문만으로 판정 가능하고 중대한지 각자 확인한다. 둘 중 한 사람이 충족하지 않는다고 판단하면 수정 또는 무효로 기록한다.

13.2 파일럿 실행과 진행 판단

개발 기업 한 곳에서 최초 신고서와 원본 기준표, 현실적인 카나리, 정상 대조본을 준비한다. 원본과 변형본에서 A0·B를 격리 실행하고, 같은 검토량의 두 목록을 만들어 탐지·누락과 오경보를 평가한다. 가능하면 유형당 카나리를 두 개 이상 확보한다. 하나면 같은 시험을 두 번 실행해 변동을 재고, 유형별 난이도 분포는 추가 시험으로 확인한다. 유형당 여러 카나리를 사용하면 탐지 비율과 순위 반영 규칙을 평가 전에 고정한다.

파일럿 시작 전 판정 가능성 통과 기준, 공동 놓침을 포함한 탐지 분포, 정상 대조 오경보 상한, 준비·실행 비용과 자연 쟁점 기저율 기준을 정한다. 판정 가능성이 부족하면 유형을 조정하고, 탐지가 한쪽에 몰리면 난이도·자료·지시를 재검토한다. 오경보가 많으면 지시·채점 규칙을 수정하고, 작업량이나 기저율이 맞지 않으면 모드·기업 수·평가용 심은 쟁점 사용을 조정한다. A1 v3 파일럿 기준

14. 사람 참여와 실제 업무 적용 주장

14.1 핵심 연구의 사람 참여

규리가 원본 기준표 작성·원문 대조·결과 채점을 맡는다. 변형본 제작과 원본 기준표를 분리하고, 두 사람이 현실적 시험의 판정 가능성과 중대성을 확인한다. 역할 분리안은 규리가 원본 기준표와 1차 채점, 원준이 A1 설계와 2차 사실 검토를 맡는 방식이며 팀 확정이 남았다. 원본 판단의 2차 검토 범위를 사전에 기록한다. 사람 검토 목록의 채점과 실제 업무 요청 해결은 별도 기록한다.

14.2 실제 후속 검토는 별도 모듈

후속 확인을 실제로 수행한다면 요청 시점 출력, 사람이 추가로 확인한 근거, 수정 결과, 소요 시간, 남은 문제를 따로 저장한다. 이 모듈을 하지 않은 핵심 연구에서는 사람 개입 후 품질·시간 절감을 주장하지 않는다. 단일 평가자가 자신이 만든 답을 아는 조건이라는 한계도 기록한다.

14.3 실무 연결 산출물

  • 시험한 자료 구조에서 도구로 재현·검증할 수 있었던 작업.
  • 원문 근거와 한계를 붙여 보조할 수 있었던 해석.
  • 실행 중 관찰 가능한 추가 사람 검토·정보 요청 조건.
  • 문헌과 공개자료로 판단을 확정하지 못한 영역.

이 분류를 실제 결과로 채운다. 사람 요청의 필요성은 본 연구 기준표의 적합성으로 해석하고 독립적인 전문가 판단을 검증했다고 쓰지 않는다.

15. 선택 확장: 후속 공시·전향적 관찰

후속 정정은 최초 신고서 평가의 보조 자료다. 실제 정정된 항목 중 사람이 볼 목록이나 합의 지적에 들어갔는지 집계한다. 전향적 관찰을 추가할 경우 아래 절차를 별도로 적용한다.

  1. 후속 문서 공개 전에 사례·cutoff·입력·검토 메모·해시를 고정한다.
  2. 사전에 “어떤 판단이 어떤 새 자료로 확인되는가”를 적는다.
  3. 이후 정정, 최종 가격, 후속 재무자료를 별도 저장소에 수집한다.
  4. 검토 항목과 후속 증거를 연결하되, 회사가 수정하지 않은 질문을 자동 오답 처리하지 않는다.
  5. 추가 자료로 해소된 문제와 아직 알 수 없는 문제를 구분한다.

이미 정정 전후 내용이 함께 있는 최종 PDF를 과거 시점 입력으로 사용하지 않는다. 원래 시점의 파일을 확보하는 것이 우선이다. 구획을 제거해 시점을 복원한다면 원본·제거 범위·이유를 남기고 자연 원문 그대로의 실험과 구분한다.

과거 자료를 현재 모델로 실행하면 사전학습으로 이미 내용을 알고 있을 가능성이 남는다. 완전한 비오염을 주장하지 않는다.R08 R11

  • [ ] 현실적인 카나리와 정상 대조의 시험 기준·두 사람 확인·무효 처리를 기록했다.
  • [ ] 양쪽 목록 안팎의 항목을 모두 채점할 수 있다.

실행

  • [ ] 파일럿 진행 기준의 충족 여부와 모드·모델·계약·비용 상한을 확정했다.
  • [ ] 원본과 변형본의 별도 세션, 섞인 순서, 입력과 출력 기록을 검증했다.
  • [ ] 두 목록은 같은 원본 A0·B·사실 및 계산 기록, 공통 필수 검토와 추가량 K를 사용한다.
  • [ ] 실행 중 중대 문턱값, 가격 영향 미확인·동순위, 탐지 미확인의 규칙을 고정했다.

분석

  • [ ] 발행기업·항목·변형·반복과 모델 호출을 별도 계수한다.
  • [ ] 자연 쟁점의 기업 단위 짝 비교와 목록 밖 오류의 분자·분모를 고정했다.
  • [ ] 실행 중 중대 판정과 사람 판정의 불일치, 미확인, 탐지·오경보와 비용을 병행 보고한다.
  • [ ] 평가용 심은 쟁점의 사용 여부를 정했다. 사용 시 신호용과 다른 후보, 결과표와 비용 기록을 마련했다.
