공개 방법론에 기반한 IPO 검토 에이전트 프로젝트 설계서

버전: 2.0 · 기준일: 2026-10-27, 한국시간
평가 담당: 규리 1명. 공개 방법론으로 기준표 작성·검토·최종 채점을 수행한다.
짝 문서: IPO_Experiment_Protocol.md. 별도 제안서는 프로젝트의 배경과 진행을 처음부터 설명한다.
상태: 실험 실행 전 설계. 자료 모집과 기준표 구축, 모델 실행은 아래 절차에 따라 진행한다.

실제 IPO 공개자료에서 AI가 가치평가 방법론을 근거에 맞게 적용하는지 평가하고, 실패를 줄이는 도구·검증 절차와 추가 사람 검토가 필요한 조건을 제시한다.

1. 팀원에게 전달할 요약

항목 전달 내용
프로젝트 설계와 범위 공개된 IPO 공모가 산정 근거를 재검토하고 추가 확인사항을 고르는 업무를 다룬다. 사실·계산·방법론 적용·미확인 사항 처리를 평가하고, 실패를 개선한 뒤 새로운 기업에서 검증한다.
IPO 선정 이유 실제 공시에 산식·비교기업·이익·주식수가 공개되어 있어 자료와 계산을 확인하기 비교적 좋다. 회사의 선택은 참고 대상이며, 평가 기준은 공개 방법론과 원문에 연결한다.
진행 방식 실제 3건으로 자료와 단독 채점의 가능성을 확인한다. 일부 실제 사례를 연습용으로 사용해 시스템을 고친 뒤, 개발에 쓰지 않은 기업에서 품질·완료 범위·추가 검토 요청·비용을 비교한다.

2. 처음 읽는 사람을 위한 설명

기업이 일반 투자자에게 주식을 공모하면서 상장을 추진하는 과정을 여기서는 IPO라고 부른다. 주식을 모집·매출하는 가격이 공모가다. 공모가 결정에는 기업가치 검토와 수요예측·협의가 관여한다.R01

이 프로젝트는 이미 공개된 산정 자료를 재검토한다. AI는 이익·비교기업·주식수·산식의 관계를 확인하고, 가정의 영향과 필요한 추가 확인을 설명한다. 비공개 초기 실사나 협상을 그대로 재현하는 과제는 아니다.

용어 뜻
PER 주가를 주당순이익으로 나누거나 시가총액을 순이익으로 나눈 배수
비교기업 또는 peer 가치평가를 위해 이익 구조와 위험 등을 비교하는 상장기업
LTM 최근 12개월 실적. 반기 실적을 두 배로 늘리는 연환산과 구별
민감도 분석 가정이나 입력을 바꾸었을 때 계산 결과가 얼마나 달라지는지 확인
에이전트 API 모델에 검색·계산 도구와 실행 규칙을 붙여 중간 결과에 따라 행동하게 한 시스템
기준표 또는 gold 규리가 모델 출력 전에 작성한 사례별 근거·허용 답·채점 예시
cutoff 해당 사례에서 사용할 수 있는 정보의 마지막 공개 시점
개발용 사례 시스템의 실수를 찾고 고치는 동안 연습 자료로 쓰는 실제 IPO
평가용 사례 설정을 고친 뒤 새로운 기업에서도 통하는지 확인하는 실제 IPO
추가 사람 검토 해결되지 않은 근거 충돌·해석을 더 확인하도록 요청하는 행동. 본 실험에서는 요청을 기록하고 적절성을 평가

3. 프로젝트를 설계한 순서

3.1 세 가지 질문을 하나의 흐름으로 연결한다

첫째, 실제 업무에서 어떤 산출물이 좋은 검토인지 정의한다. 둘째, 같은 자료와 조건에서 시스템의 성취도를 측정한다. 셋째, 관찰한 실패를 근거로 도구와 사람의 역할을 제시한다. 업무 요구 → 기준표 → 실행과 채점 → 실패 분석 → 개선 → 새 사례 검증 → 적용 조건이 이어져야 한다.

평가 대상은 모델과 검색·계산·검증 절차가 함께 작동하는 시스템이다. 과제와 반복 실행을 구분하고 실제 도구 행동을 기록하는 에이전트 평가 방법을 참고한다.R07

3.2 실제 자료와 정답을 구별한다

실제 자료를 사용하면 회사·손익·상황을 임의로 만들어 넣는 부분을 줄일 수 있다. 그러나 실제 회사의 결정이 유일한 최적값이라고 입증되는 것은 아니다. 다음처럼 평가 기준을 나눈다.

대상 평가 기준
수치·단위·기간·주식수·계산 공시 원문, 확보 가능한 원천자료, 재계산
적용 이익·비교기업·가정의 해석 공개 방법론에 연결한 사례별 기준표
정보 요청·추가 검토 미해결 정보와 필요한 판단의 구체적인 연결
확정 공모가·후속 정정 보조적으로 관찰할 공개 결과
상장 후 주가 핵심 평가 대상에서 제외

근거 있는 수용도 좋은 답이다. 경고나 요청의 개수를 늘리는 행동 자체에는 점수를 주지 않는다. 숫자 허용 차이는 반올림·단위에서 정하며, 경제적 오차에 임의의 ±5%를 적용하지 않는다. 의미 있는 허용 경계의 사전 지정 원칙을 참고하되 금융 허용값은 별도로 정당화해야 한다.R10

3.3 여러 기업과 반복 실행을 구별한다

개발 10개·평가 20개 기업을 초기 목표로 둔다. 파일럿 3개는 개발 10개에 포함한다. 평가 20개에 시스템 3개를 두 번씩 적용하면 120회 실행이지만, 서로 다른 발행기업은 20개다. 반복은 출력의 변동을 보는 용도다. 수량은 탐색적인 자원 계획이며 검정력으로 충분성이 입증된 수가 아니다.

4. 업무 후보를 좁힌 이유

4.1 선정 기준

선정 기준은 공개자료와 실제 업무 문서, 에이전트 평가 방법을 바탕으로 구성한 연구자의 기준이다.R01 R02 R07 R08

기준 확인 질문
업무의 한정 누가 어느 시점에 어떤 판단과 산출물을 만드는가?
입력 접근성 일반인이 핵심 자료를 확보할 수 있는가?
평가 가능성 회사의 선택을 그대로 정답으로 두지 않고 평가할 수 있는가?
판단의 실질 복사·계산 외에 근거를 적용하고 다음 행동을 고르는가?
실패 대응 실행 중 관찰할 신호로 도구·추가 검토 규칙을 만들 수 있는가?
새 사례 개발에 쓰지 않은 유사 과제를 확보할 수 있는가?
자원 규리 한 명의 기준표 작성·채점과 팀의 구현이 가능한가?

AI 도입 사례는 업무 관련성을 보강한다. 자료와 기준표가 없다는 문제를 도입 사례만으로 해결할 수는 없다.

4.2 후보 간 비교

아래 순위는 우리 팀의 공개자료 제약 아래에서 내린 설계 판단이다.

후보 공개자료로 가능한 부분 이번 연구의 제약 선택

4.3 IPO의 강점

개인도 OpenDART에서 공시 원문과 주요 정보를 이용할 수 있다.R02 IPO 문서에는 산정표와 설명이 있어 수치 재현과 방법론 적용을 함께 다룰 수 있다.R03–R05 또한 IPO 수요예측 지원에 AI를 활용했다는 임원 인터뷰가 있어 인접 실무와의 접점이 확인된다. 이 인터뷰는 자기보고이며 본 과제의 효과를 검증한 결과는 아니다.R06

5. 정확한 업무와 자료 범위

5.1 업무 정의

요소 내용
역할 공개 IPO 가치평가 자료를 검토하는 분석 보조자
시점 특정 버전이 공개된 이후의 고정 시점
입력 허용 시점까지 공개된 발행사·비교기업 문서와 수치
판단 적용 이익·비교기업·가정의 근거와 제약, 중요한 다음 확인
출력 재계산표·근거 연결 검토표·우선순위 메모·미해결 요청
행동 지정 저장소 검색·열람·계산·민감도·정보 및 사람 검토 요청 기록

5.2 핵심 사례 범위

국내 비금융 IPO 중 이미 발생한 실적에 기초한 PER이 주된 산정 방식인 사례를 다룬다. 연간·LTM·중간실적 연환산과 비경상 손익 조정 여부를 태그로 구별한다. 연환산에도 계절성·지속성 가정이 들어가므로 가정의 의미를 검토한다.

금융회사·SPAC·REIT, 미래 추정이익 PER·EV/EBITDA·DCF가 주된 방식인 사례는 별도 확장으로 둔다. KRX 2025 안내는 일반적 업무 근거이며 코스닥·모든 과거 거래의 통일된 법적 정답표로 사용하지 않는다.

기업당 대표 문서는 일반청약 시작 직전 마지막 유효 투자설명서의 산정 내용으로 정한다. 철회 거래·대체 증권신고서·진행 중 거래의 처리와 cutoff는 프로토콜의 동일 규칙을 적용한다. 성과를 보고 버전을 고르지 않는다.

2026-10-26에 원문과 관련 표를 확인한 후보들이다. 접수번호·대표 버전·독립 원천자료와 사례별 기준표는 추가 구축해야 한다.

기업 확인한 문서 자연적인 검토 소재
HD현대마린솔루션 2024-04-24 정정 투자설명서 연간 실적 PER, 사업 비교, 표시 배수의 반올림 R03
멜콘 2026-09-29 정정 투자설명서 반기 연환산, 비경상 손익 조정, 발행사·peer의 기간 R04

표시된 배수를 곱한 값이 공시 평가액과 다를 때에는 반올림과 원래 계산 정밀도를 먼저 확인한다. 이미 공시가 설명한 조정을 복사한 결과는 새 이슈 발견과 구분한다. 정정본에는 정정 전 값이 함께 있을 수 있으므로 표의 구획도 기록한다.

6. 규리 한 명이 참고자료로 평가하는 방법

6.1 평가의 의미

주요 성능은 공개 방법론에 근거한 검토 품질이다. 평가 담당자는 규리 한 명이다. 외부 전문가, 두 번째 검토자, 평가자 간 합의를 요구하는 절차를 두지 않는다.

평가 층 확인 내용 수단
사실·계산 수치·단위·기간·주식수·식·출처 원문 위치와 재계산
방법론 적용 실제 사실과 원칙을 연결한 판단 출처·허용 답·판정 예시가 붙은 기준표
운영과 Trust 완료 초안의 오류·추가 검토·검사기 성능 실행 로그와 같은 기준표

6.2 곧바로 참고할 자료

자료 읽을 부분 가져올 검토 원칙
KRX 2025 가이드북 R01 인쇄 176–177쪽 산정과 비교기업의 타당성
CFA 공개 요약 R17 Summary의 trailing P/E, normalizing EPS, central tendency 이익 기간·정의와 배수 요약 방식
NYU 배수 강의 R18 Definitional / Descriptive / Analytical / Application Tests 측정 일관성·분포·기업 간 차이
NYU 이익 정상화 설명 R19 규모 변화와 정상화 시점 정상화 방식의 전제와 적용 한계

CFA에서 확인한 무료 범위는 소개·학습목표·요약이다. 자료를 통째로 정답으로 삼지 않고, 관련 원칙을 사례에 적용한 이유를 기록한다.

6.3 기준표와 채점

각 항목에 원문에서 읽을 위치, 사례의 사실, 확인할 조건, 충족·미충족 예시, 허용 가능한 결론을 붙인다. 원칙은 문헌에 연결하고 점수·필수 출력·보류 규칙은 연구자의 운영규칙으로 표시한다.

판정 의미
2점 충족 사실과 근거가 맞고 원칙·산정 영향·결론·필요한 다음 행동이 연결됨
1점 부분 충족 관련 사실은 맞으나 중요한 영향·한계·다음 행동이 불완전
0점 미충족 누락, 잘못된 사실·계산, 근거 없는 단정이나 불필요한 보류
NA 기준표 판정 불가 문헌과 원문만으로 평가자가 허용 답을 정할 수 없는 항목

예를 들어 비교기업을 검토할 때 근거 있는 수용·조건부 수용·추가 자료 요청을 모두 인정할 수 있다. 업종명만으로 포함·제외를 단정한 결과는 근거의 연결이 부족하다.

규리는 기준표를 최종 평가 출력보다 먼저 작성·고정한다. 프로그램이 조건명·실행 순서를 가린 사본을 만들면 같은 기준으로 채점하고 사유를 남긴다. 단독 평가자에게 완전한 눈가림이나 외부 검증이 확보됐다고 표현하지 않는다.

기준표의 NA와 모델의 보류는 다르다. AI가 어려워한 항목을 사후에 NA로 빼지 않는다. 기준표를 수정하면 모든 시스템에 동일 적용하고 사유와 영향을 보고한다. AI는 초안을 도울 수 있으나 채택은 규리가 원문을 확인해 결정한다.

A0 기본 에이전트 중간 결과에 따라 다음 도구·검색 순서를 선택 적응적 행동 선택의 이점

같은 모델 버전·자료·공통 방법서·기본 도구·출력 형식·최대 예산을 제공한다. 사례별 기준표의 답은 숨긴다. B와 A0도 불확실성·정보 요청·추가 사람 검토를 보고할 수 있다. A1만 더 많은 전문 지식을 받게 하지 않는다.

A0와 A1의 차이는 개선된 시스템 묶음의 효과다. 개별 장치의 인과 효과는 별도 제거 실험 없이 주장하지 않는다. A1의 추가 검사·수정 비용도 포함한다.

8. 실행 단계와 프로젝트 흐름

첫 단계에서 규리가 IPO 1건을 직접 풀어 자료 정리·기준표 작성·출력 채점 시간을 측정한다. 파일럿 3건에서 근거와 판정 예시를 조정한다. 이후 적격 사례 모집대장과 작업량을 보고 수량을 고정한다.

개발 사례에서는 오류를 추출·기간·산식·비교 논리·다음 행동으로 구분한다. 실패 ID마다 원문 증거와 개선 장치를 연결한다. 예를 들어 정정 전 수치를 현재값으로 읽은 오류에는 구획 검증을 붙인다.

개선을 마친 뒤에는 새 기업에서 최종 평가한다. 최종 결과를 보고 수정한 버전은 새 탐색 결과로 표시한다. 같은 평가 자료를 깨끗한 재평가라고 재사용하지 않는다.R08

마지막에는 실제 측정한 결과로 맡길 작업·검증 도구·추가 검토 요청 조건을 정리한다. 성능이 나쁘거나 B가 더 좋아도 연구 결과로 남긴다.

9. 운영 구조와 Trust

본 실험의 사람 검토 요청은 기록하는 행동이다. 규리가 보고서를 채점하는 일과 업무 담당자로서 요청을 받아 문제를 해결하는 일은 구분한다. 핵심 실험에서는 요청의 적절성까지 측정하며 요청 이후의 해결·업무시간 절감을 가정하지 않는다.

Trust는 어떤 조건에서 초안에 의존하고 언제 더 확인해야 하는지를 다룬다. 완료 초안의 핵심 오류율과 완료 비율, 전체 오류·실패, 필요 요청 누락·불필요한 요청, 검사기 미탐·오탐, 비용을 함께 보고한다. 완료 0건이면 완료 초안 오류율은 NA다. 위험과 처리 범위를 함께 보는 개념은 선택적 예측 연구를 참고한다.R09

현업 배포는 시험한 공개자료 모듈 외에 내부 자료·책임·승인 체계의 별도 실증이 필요하다. 실제 보험 AI 파일럿의 추천·사람 승인 구분은 참고 구조이며 이 IPO 시스템의 성능 근거가 아니다.R12

10. 자료 시점과 사전학습 오염

고정 저장소에는 사례의 cutoff까지 공개된 자료만 넣고, 정답과 후속 자료를 분리한다. 같은 발행기업의 다른 버전을 개발과 평가에 나누지 않는다. 공통 peer 자료의 중첩도 기록한다.

모델 버전과 공식 확인 가능한 지식 기준일, 문서 공개일을 기록하고 이전·이후·확인 불가로 표시한다. 최근 사례 확보는 기존 노출 가능성을 줄이려는 조치다. 시기별 성능 차이만으로 오염을 확인하거나 제거했다고 말하지 않는다.R08 R11

2026-11-01부터 11-10 사이 후속 자료가 나오는 적격 사례가 있으면 공개 전에 입력·메모를 고정하는 보조 실험을 할 수 있다. 현재 일정이 확보됐다고 전제하지 않으며 핵심 완료 조건으로 두지 않는다. 후속 정정이 없었다고 질문을 자동 오답 처리하지 않는다.
