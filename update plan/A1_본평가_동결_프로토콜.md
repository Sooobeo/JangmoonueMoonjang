## 1. 기업·원문·항목

1. **명단과 자료 버전.** 기존 미사용 8곳, 2024년 4분기 6곳, 추가 구간 23곳을 `roster.json` 순서대로 모두 처리한다. 법인코드로 기업을 식별하고 접수번호와 PDF SHA-256으로 원문을 확인한다. 명단 SHA-256은 `438e093bf95505b2e00fd8a42b76c6b3c553eaeff5bfeb572c6eac5cfc35ab9f`다. PDF는 Git 밖에 보관한다. 파일이 없거나 해시가 다르면 실행 전 전송을 멈추고 같은 원본 바이트를 복구한다. 준비 실패·판정 유보·유효 기업 부족은 37곳의 흐름표에 남기고 예비 8곳은 편입하지 않는다. 워트는 발행사로 처음 평가하므로 포함하고, 멜콘의 개발 비교기업으로 자료가 사용된 이력을 고려해 워트 제외 결과도 보고한다. [명단과 원문](../ipo_agent_eval/reports/a1_current/official/enrollment_expansion/확보한%20기업.md) · [명단과 해시](../ipo_agent_eval/reports/a1_current/official/enrollment_expansion/roster.json) · [모집 규칙](../ipo_agent_eval/reports/a1_current/official/enrollment_expansion/모집규칙.md)
2. **공개시점.** 발행사 원문은 동결한 최초 신고서로 한정한다. C 후보 근거와 후보군 확인 자료는 최초 신고서 공개까지 이용 가능했던 자료만 사용한다. 같은 날의 별도 자료는 선행 공개 시각을 확인한 경우에 포함한다. 시각이 날짜까지만 확인되면 이전 날짜 자료를 사용한다. 원문과 보조 자료의 접수번호·버전·공개시점과 정밀도·SHA-256·근거 위치를 기록한다. 물리 쪽은 PDF의 첫 장을 1쪽으로 센다. [공개시점 규칙](updateplan.md#21-최초-신고서와-공개-시점)
3. **원본 항목표.** 기업마다 공통 7개를 만든다. J1 적용 이익의 기간과 회계상 귀속, J3 기준주가, PER 집계, 적용 주식 수, 주당 평가가액 검산, 할인율·밴드다. 공시가 제시한 적용 이익 조정은 손익 항목별로 J1을 추가하고, 최종 PER 산정에 실제 사용한 비교기업마다 J2 사업 비교 적합성을 한 건씩 추가한다. 없는 항목을 추정해서 추가하지 않는다. 공통 항목에 필요한 근거가 부족하면 항목을 유지하고 근거 상태에 남긴다. ID는 `접수번호-일련번호`다. 공통 7개 고정 순서, J1 조정의 최초 근거 물리 쪽·표 행 순서, J2 비교기업의 최종 PER 표 행 순서로 부여한다. 동일 대상·질문의 중복 행은 첫 행에 합치고 근거를 모두 연결한다. 질문·대상·역할별 적용 여부·허용 쪽과 근거 ID를 응답 수신 전에 동결한다. [공통 항목의 파일럿 정의](../ipo_agent_eval/scripts/current_validation.py) · [팀 질문·근거 사전](real%20real%20update.md#2-ipo-실무-자료로-만든-질문과-근거-사전)
4. **B 사전 검증.** 원문 행·단위·기간·귀속·기준일을 확인하고 적용 이익, PER 또는 평가 시가총액, 주식 수, 주당 평가가액, 할인율·밴드의 연결을 재계산한다. `적용 이익 × 적용 PER ÷ 적용 주식 수`를 쓰며 공시가 명시한 평가 시가총액을 분자로 썼다면 그 경로와 이익·PER의 일관성을 함께 검사한다. 공시 반올림·절사 규칙과 표시 정밀도를 적용한 뒤 검사별 `통과 / 불일치 / 미확인`과 근거를 남긴다. 원문으로 확인한 **결정적 계산·사실 오류**가 §3 중대 기준을 충족할 때 해당 원본 항목을 공통 필수로 잠근다. 대안이 공개 근거와 같은 기간·범위·단위에서 재현될 때만 공시 평가가액 대비 절대 변화율을 두 경로에 제공한다. 복수 적격 대안은 근거와 수식을 모두 보존하고, 오류 입력을 고쳐 공시 산식을 재현하는 대안을 우선한다. 같은 우선순위의 대안 중 절대 변화율이 가장 작은 값을 순위 입력으로 쓴다. 근거 부족, 분모 0·누락은 `null`이다. 할인율만 바뀔 때는 밴드 변화로 기록한다. [B 원문 대조와 재계산 예](../ipo_agent_eval/scripts/current_validation_b.py) · [J1 공식 짝 비교](../ipo_agent_eval/reports/a1_current/official/j1_pair/B_J1_짝비교.md)

## 2. 가림 입력과 선별

| 역할 | 받는 자료와 제출 |
|---|---|
| A0 | 원래 공시 선택을 적은 지정 질문과 허용 원문. 파일럿 공식 역할과 같이 B 결과는 입력에서 제외한다. 원본 항목마다 수용·문제 제기·미확인 중 하나와 물리 쪽·짧은 직접 인용·이유를 제출한다. |
| C | 공통 지시문과 두 입력 필드 `issuer_evidence`, `candidates`. 최종 선정 여부·이유, 산정표, 공모가, 회사명·종목코드·URL·접수번호·원본 ID, B·A0·기준표를 가린다. 자기 근거 ID로 후보별 판단과 비교 방법을 제출한다. |
| 규칙·A1 | 동일 원본 항목표·A0와 C의 구조화 판단 및 원래 인용·B·공통 필수·가격 영향. 규칙은 공유된 근거 ID를 사용하고 A1에는 허용 원문 발췌와 쪽 목록, 제한 조회를 제공한다. 기준표와 이전 답변·순위는 입력에서 가린다. |
| 독립 채점 | 원본 질문·최초 신고서의 사전 고정 쪽과 근거만 받는다. 문서의 공시 선택 자체는 평가 대상이다. A0·C의 답, B 판정, 어느 방식이 이관했는지, 다른 채점 결과를 가린다. 불일치 조정도 원문과 질문만으로 수행한다. |
| 검토 시간 측정 | 실제 이관의 합집합을 항목별로 배정한다. 동일 중립 질문과 사전 고정한 항목별 최초 신고서 쪽을 제공한다. 배정 경로·순위·이유·기준표를 가린다. |

**C 후보 구성.** 파일럿처럼 실제 최종 비교기업과 별도 업종 후보를 섞는다. 별도 후보는 최초 신고서 공개 직전의 국내 상장사 중 발행사와 같은 KSIC 소분류를 사용한다. 상장 여부와 분류를 해당 시점 자료로 확인하고, 최종 비교기업과 발행사를 제외한 뒤 같은 시장, 다른 국내 시장 순으로 검색한다. 시장 그룹마다 종목코드 오름차순에서 접수 전에 나온 자체 공시로 사업·제품 근거를 확보할 수 있는 첫 1곳을 쓴다. 후보 자료는 당시 이용 가능했던 가장 최근 정기보고서에서 취한다. 각 후보의 `business`에는 주요 제품·사업을 뒷받침하는 최대 2개 발췌, `financials`에는 확인 가능한 매출 구성과 보고기간의 최대 2개 발췌를 쓴다. `multiples`는 빈 목록으로 고정한다. 항목마다 문서 순서에서 첫 적격 문단 또는 표 행을 사용하고 한 발췌는 익명화 후 최대 350자다. 필요한 식별자는 중립 표시로 치환하고 원문 인용·표 위치와 변경 매핑은 비공개로 보존한다. 자료가 없는 필드는 빈 목록으로 둔다. 사업·제품 근거를 확보하지 못한 원본 후보는 C 전송물에서 빼고 원본 항목의 C 판정을 `미확인·자료 부족`으로 남긴다. 전송할 원본 후보가 있는데 별도 후보를 확보하지 못하면 해당 기업의 C 가림 입력을 미완료로 처리한다. 원본에 J2 항목이 없는 경우 C 후보 비교는 적용 불가로 기록한다. 후보는 `SHA-256(접수번호 + '/' + 후보 종목코드)` 오름차순으로 정렬한 뒤 중립 ID를 부여한다. 별도 후보는 가림 자료에만 사용한다. 실제 전송물 전체의 문구·표·근거 ID·메타데이터, 인접 쪽과 캐시의 접근 가능성을 점검한다. 원문 사실로 기업을 추정할 가능성과 근거 부족은 기록한다. [가림 자료·비공개 매핑 선례](../ipo_agent_eval/scripts/validation_roles.py)

**응답 연결.** A0와 C는 기업·역할별 독립 무상태 요청으로 실행한다. C 응답을 잠근 뒤 비공개 매핑으로 원본 ID를 연결한다. 근거가 확인된 J2의 `INCLUDE / REVIEW / EXCLUDE`를 `수용 / 미확인 / 문제 제기`로 변환한다. J1 기간·귀속은 발행사 근거가 있고 같은 판단 대상의 범주를 명확하게 확정할 수 있을 때 비교한다. 원본 범주와 일치하면 수용, 불일치하면 문제 제기다. `UNKNOWN`, `OTHER`, 조건부 응답, 원본과 직접 대조할 수 없는 대안은 미확인으로 두고 원래 제안을 보존한다. J1 개별 손익 조정과 J3의 C는 `미확인·역할상 비교 불가`로 두고 전수 순위와 채점에는 남긴다. `역할상 비교 불가 / 자료 부족 / 제출 실패 / 인용 불일치`를 각각 기록한다. 원문 행·기간·단위·범위와 직접 인용의 내용까지 확인하고, 순위 계산에 쓴 근거 ID 검사는 별도로 재현한다. [공식 역할 입력·검사](../ipo_agent_eval/scripts/validation_official.py) · [원래 응답 연결](../ipo_agent_eval/scripts/validation_roles.py)

**규칙 정렬.** 공통 필수 밖에서 등록 근거 ID가 있는 문제 제기, 미확인 포함, 나머지 순이다. 파일럿 구현과 같이 C의 `미확인·역할상 비교 불가`는 미확인 묶음에 들고 양쪽의 판단 갈림 건수에서는 빠진다. 묶음 안에서 절대 가격 영향 내림차순, 미산출 뒤, 항목 ID 오름차순으로 정렬한다. 문제 제기의 근거 ID는 허용 색인에 연결돼야 한다. 인용이 실제 판단을 지지하는지는 별도로 감사하고, 두 목록을 고정한 뒤 개별 순위를 수정하지 않는다. [규칙 구현](../ipo_agent_eval/scripts/current_selector.py)

**A1 조회·정렬.** 기업별 축약 조회 입력은 항목 ID·질문·두 상태·이유 앞 180자·항목별 쪽 색인·허용 물리 쪽 목록·빈 `triz` 배열이다. 원문 카탈로그 안에서 중복 없이 0~4개의 물리 쪽을 반환한다. 필요한 인접 쪽도 네 쪽 안에서 센다. 항목별 직접 근거의 원문 위치와 근거 ID를 동결한다. 최초 발췌에는 공시 선택을 확인할 수 있는 항목별 첫 근거 쪽을 넣고, 카탈로그에는 대응하는 산정표·재무제표·주석과 해당 근거를 잇는 필요한 인접 쪽을 올린다. 조회 뒤 질문 전부, 양쪽 전체 이유와 근거, B와 원문 발췌를 넣어 한 번 선별한다. 조치는 `사람 검토 / 자료 요청 / 기록 보관`이다. 하나의 항목 ID마다 조치·이유·근거 ID·우선순위 1~100과 필요한 확인 질문 또는 요청 자료를 제출한다. 우선순위 내림차순, 동률은 ID 오름차순이다. 입력 발췌와 조회 쪽의 인용을 구분하고, 공개 자료 부족·조회 한도 소진·참조 오류를 별도 기록한다. 모든 항목의 단일 제출과 인용 ID 허용 범위를 코드가 검사한다. ## 3. 중대 기준과 기준표 확정

**중대 쟁점**은 원문에서 확인되는 사실 오적용 또는 중요한 반대 근거 누락이 **비교기업 선정·산정 판단을 바꿀 만하거나**, 근거가 확인된 적격 대안으로 계산한 **주당 평가가액의 절대 변화율이 5% 이상**인 경우다. `abs(대안 평가가액 − 공시 평가가액) / abs(공시 평가가액)`을 사용한다. 분모가 0이거나 없으면 수치 미산출과 사유를 남기고 질적 기준을 적용할 수 있다. 민감도만 발생하거나 자료가 부족하면 그 자체로 확정 중대가 되지 않는다. 등급은 `수용 가능 / 비중대 쟁점 / 중대 쟁점 / 판정 유보`다. 판정 유보는 판단을 확정할 원문 근거 부족이고, 제출 실패나 누락은 실행 결측이다. 기업·항목·근거 물리 쪽·직접 인용·판정 이유·남은 근거 및 계산을 등급마다 남긴다. [채점 지시문과 인용 검증](../ipo_agent_eval/scripts/current_validation.py)

**주 기준표는 독립 Codex 대행 채점으로 고정한다.** `gpt-6.2-astra` medium의 새 세션 두 개가 각 기업의 전 항목을 독립 판정한다. 두 유효 등급이 일치하면 확정한다. 같은 기업에서 등급이 갈린 모든 항목은 세 번째 새 세션에 한 번 묶어 같은 지시문·스키마·원문·질문으로 제시한다. 세 번째 세션에 앞선 등급은 노출하지 않는다. 검증된 다수 등급을 채택한다. 세 유효 등급이 모두 다르면 `판정 유보·채점 불일치`로 남긴다. 필수 채점 세션이 계약 오류나 실패 한도에서 복구되지 않으면 해당 기업의 기준표는 기술적 미완료다. 제출의 항목 누락·중복, 허용 쪽 여부와 공백을 정규화한 직접 인용이 해당 쪽에 연속해서 존재하는지를 코드로 검사한다. 중대·유보·불일치 항목은 순위와 운영 목록을 가린 상태에서 원문 인용이 해당 판단을 뒷받침하는지 대조한다. 원문 근거가 불충분하면 사유와 원판정을 보존하고 유보한다. 두 원판정과 조정 결과, 조정 전 4단계 정확 일치율·분모, 등급 교차표를 보존한다. 두 목록을 연결한 뒤에는 목록 차이에 걸린 인용을 감사하고 등급은 동결본을 사용한다. 파일럿은 기업별 일부 항목을 재채점했다. 본평가는 **독립 전수 재채점**으로 고정한다. 실제 사람 기준표와 평가자 간 인간 합의는 미측정이다. [파일럿 기준표 재채점](../ipo_agent_eval/reports/a1_current/official/공식재실행.md#기준표를-바꾸면-어떻게-달라지나) · [채점 검증 선례](../ipo_agent_eval/scripts/current_validation.py)

## 4. 분석과 판정

| 지표 | 계산 |
|---|---|
| **주 지표** | 공통 필수 밖의 확정 중대 × 확정 비중대 쌍을 기업 내에서 비교한다. 비중대에는 수용 가능과 비중대 쟁점이 들어간다. 중대가 앞이면 1, ID 정렬 전 동률은 0.5, 뒤면 0이다. 기업별 평균의 `A1 − 규칙` 차이를 기업 동일 가중으로 평균한다. 두 등급군이 모두 있고 두 전체 순위와 기준표가 완전한 기업이 유효 짝이다. |
| **같은 K** | 공통 필수 전부에 행동과 무관한 전체 순위 상위 `min(1, 공통 필수 밖 원본 수)`건을 더한다. 두 순위와 기준표가 완전한 모든 기업에서 확정 중대 회수·누락을 센다. 회수율은 회수한 확정 중대 총수 ÷ 확정 중대 총수다. 분모가 0이면 `null`이다. 정책 판정은 `K=1`에서 하고, 다른 K의 곡선은 기술적으로 보고한다. |
| **실제 이관** | 공통 필수 전부에, 규칙은 근거 ID가 있는 문제 제기 중 첫 1건, A1은 `사람 검토` 중 첫 1건을 더한다. 대상이 없으면 추가 0건이다. 추가 이관 한도를 넘긴 적격 항목은 검토 대기다. 자료 요청·기록 보관·규칙 미배정·검토 대기는 각각 집계한다. 두 운영 목록과 기준표가 완전한 모든 기업에서 전체 원본 대비 이관율, 필수·추가 건수, 중대 누락·사유와 회수율을 보고한다. |
| **운영 추가 누락** | 기업·항목별로 `(규칙 운영 목록 − A1 운영 목록) ∩ 확정 중대`를 센다. 허용치는 **0건**이다. A1이 다른 항목을 새로 찾아도 상계하지 않는다. 유보까지 중대라고 가정한 최대 추가 누락은 같은 차집합에 들어 있는 유보 건수를 더해 보여 준다. |
| **판정 유보** | 주 분석에선 유보를 제외한다. 유보를 어느 등급군에 넣더라도 두 경로에 같은 배정을 적용한다. 기업별 순위 일치도 차이의 최소·최대를 구하고 주 분석에 포함된 동일 기업군에서 평균한다. 같은 K·운영 목록의 누락 및 누락 차이도 가능한 최소·최대로 보고한다. 유보 처리로 새로 비교 가능해지는 기업의 수를 별도 표시한다. |

**표본과 통계.** 유효 짝 15곳은 표준화 짝 효과 `d=0.8`, 양측 `α=.05`, 목표 검정력 80%의 계획값이다. 파일럿의 유효 2/4에서 `p=.50`을 가정하면 37곳 중 유효 15곳 이상을 얻을 확률은 약 **90.6%**다. 모든 37곳의 자료 범위와 단계별 분모를 보고한다. 결과를 중간에 열어 조기 종료하거나 유효 목표에 맞춰 보충하지 않는다. 주 비교는 양측 짝 t검정과 95% t 신뢰구간이며, **유효 짝 15곳 이상이고 신뢰구간 하한이 0을 넘을 때** 이 기준표에서 A1의 순위 우위를 판정한다. 15곳 미만, 분산 0, 유효 짝 2곳 미만이면 가능한 점 추정과 기술 통계, 판정 불가 사유를 보고한다. 유효 짝이 2~14곳이고 분산이 양수면 기술적 신뢰구간도 함께 제시한다. 기업별 등급군 부재, 원문·가림 입력 결측, 역할·순위·채점 실패를 각각 보고한다. 워트 제외와 유보 경계는 보조 분석으로 고정한다. **Codex 한도와 시간.** 독립 채점과 검토 페르소나는 `gpt-6.2-astra` medium을 사용한다. 요청마다 비어 있는 임시 작업 폴더와 새 임시 세션에서 읽기 전용으로 실행한다. 저장소·과거 세션·파일·웹·셸·기타 도구 접근 차단을 사전 점검하고 도구 이벤트가 관측된 응답은 무효 처리한다. 별도 채점은 기업당 최초 2개와 필요시 조정 1개로 111개 작업까지다. 검토 시간은 두 실제 목록의 고유 `(기업, 항목)` 합집합을 `SHA-256(접수번호 + '/' + 항목 ID)` 순으로 처리한다. 작업 수는 `공통 필수 총수 + 74`가 상한이다. 두 작업 종류 모두 재시도 포함 최대 2번 시작, 1회 최대 180초다. 공통 필수 총수는 B 동결 때 확정한다. 기존 Codex 사용 범위에서만 실행하고 세션·토큰을 Terra와 구분해 기록한다. 원문 준비·세션 경과·인용 검증·전체 경과를 분리해 합산하고 공통 항목의 한 관측값을 양쪽에 쓴다. 결측 시간은 `null`과 분모를 보고한다. 실제 사람 시간과 Codex 금액은 미측정이다. ## 6. 실행 전 무호출 확인과 원장

**현재 확정 범위.** 명단·PDF 37개와 본 문서의 평가 규칙을 확정했다. 기존 실행기는 개발·검증 회사와 후보를 하드코딩하고 있다. 37곳의 항목표·근거 색인·B 입력과 결과·가림 입력·채점 입력·범용 실행기, 전체 예산 차단은 본평가 요청 전에 준비하고 무호출 사전 점검에서 확인한다. 본평가 답변과 채점표는 아직 생성·열람하지 않았다. [원문 검산](../ipo_agent_eval/reports/a1_current/official/enrollment_expansion/verification.json) · [기존 검증 사례 추출](../ipo_agent_eval/scripts/current_validation.py) · [기존 후보·사업보고서 처리](../ipo_agent_eval/scripts/validation_roles.py)

1. **원본에서 역할 입력까지.** 37개 PDF 해시·법인코드·접수번호·물리 쪽을 확인한다. 원본→항목→근거→공통 필수→A0·C·채점·시간 측정용 질문·허용 쪽이 맞아야 한다. 실제 C 전송물의 가림을 점검한다. 제공 불가 항목과 원인도 답변을 받기 전에 명단에 남긴다. 자료 입력을 담당한 운영자는 기준표를 확인한 뒤 원래 입력이나 배정 기준을 바꾸지 않는다.
2. **동결 목록.** `ipo_agent_eval/reports/a1_main/v1/`을 본평가 전용 경로로 사용한다. 첫 요청 전에 문서·PDF와 후보 자료·공개시점, 항목표·물리 쪽·B·가격 영향, 비공개 후보 매핑, A0·C·채점 입력, A1·시간 측정 입력 생성 규칙, 지시문·스키마·모델·설정·실행기·의존성 버전과 파일 해시를 잠근다. 실행기에서 아래 지문과 일치하는 지시문·스키마를 확인한다. A1에는 두 역할의 응답과 조회 결과를 단계별로 결합하고, 페르소나에는 실제 이관 합집합을 사용한다. 이렇게 생성한 전송 바이트는 각각 송신 직전에 해시를 남긴다. 독립 채점표와 두 순위·운영 목록은 서로 가린 상태에서 각각 잠근 뒤 분석에서만 연결한다.
3. **무호출 모의 실행.** 공통 필수와 추가 0/1건, ID 동률, 자료 요청, 단일 등급군, 유보가 많은 기업, 조회 초과·중복·위조 근거, 가림 누출, 응답 실패·재시도·규칙 대체, 동시 예약과 비용 차단, 중도 재개를 재현한다. 원장에 등재되지 않은 요청은 전송하지 않는다. 결과 생성 이후 분석 조건에 영향을 주는 변경은 이번 버전에 소급 적용하지 않는다. 구현 오류를 발견하면 실행을 멈추고 영향 범위·원인·수정 전후 해시와 이미 노출된 기업을 기록한다.
4. **보존과 보고.** 요청·응답 파일과 해시, 원본 ID와 모델 반환 ID, 조회 쪽과 출처, 시간·재시도·캐시·실패, 입력·출력 토큰과 예약 비용을 추가 기록 방식으로 보존한다. 정정 기록은 원래 기록에 연결한다. 기업별 원본 건수부터 채점·순위·두 이관 목록·시간까지 대조하고, 전송 실패와 결측도 분모에 포함해 흐름표를 제공한다. PDF와 원문 실행 원장은 별도 보관하고 공개 요약에는 필요한 증빙만 첨부한다. [보관본 검산기](../ipo_agent_eval/scripts/check_evaluation_archive.py) · [기존 원장](../ipo_agent_eval/reports/a1_current/official/resume_costs.json)
