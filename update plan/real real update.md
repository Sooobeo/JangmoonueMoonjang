# A0 교차검증·라벨링과 A1 AI 최종판단 설계

작성 2026-11-25 · 팀 합의 반영 2026-11-26(한국시간)

**개발 기본 흐름.** 비교 가능한 수용 합의는 TRIZ로 근거 반응을 점검한다. 판단이 갈린 항목은 A1이 기존 답변과 허용 원문을 한 번의 선별 실행에서 대조한다. 목표는 중대 쟁점 누락을 관리하면서 사람 이관을 줄여 자동화 가능한 범위를 넓히는 것이다. 조건부 보류와 갈린 항목의 상호 재질문은 실측 근거에 따라 도입 여부를 정한다. [합의 점검](#44-triz를-적용한-합의-점검) · [갈린 판단의 처리](#45-갈린-판단을-a1에서-대조) · [사람-이관 평가](#53-실제-사람-이관-평가)

## 1. 검증할 질문과 적용 범위

**같은 두 AI의 원본 답변에서 출발할 때, 합의 점검을 포함한 A1이 구조화 라벨을 사용하는 규칙보다 중대 쟁점을 더 앞에 놓는가? 사람이 같은 건수만 검토할 때도 더 많이 찾는가?** 운영에서는 중대 쟁점 누락률을 허용 범위 안에 두면서 실제 이관 건수와 사람 검토 시간을 줄일 수 있는지도 측정한다. 중대 쟁점은 공개 근거로 확인할 수 있는 사실 오적용이나 중요한 반대 근거 누락으로, 가격 영향이나 선정·산정 판단을 바꿀 만한 경우를 말한다. 대상은 최초 증권신고서의 과거 실적 PER 기반 희망 공모가 산정 근거다.

**B 사전 검증 → 가·나 독립 판단 → 항목 ID로 전체 기록 연결 → 수용 합의의 근거 반응 점검 → A1이 원문과 각 근거를 대조해 조치와 순위를 제안 → 코드가 사람 검토 목록을 배정.** 초기에는 A1이 전 항목을 본다. 갈린 판단은 원래 두 답변과 근거를 연결한 직후 A1에 전달한다. A1 최종판단은 **누가 무엇을 확인할지 정하는 판정**이다. 사람이 이관 항목의 원문을 확인하며, 평가에서는 전 항목 기준표로 이관 여부와 관계없이 중대 쟁점을 확인한다.

가·나는 대화에서 말한 두 AI 검토 역할이다. v5 실행에 연결할 때 **가 = 기존 A0, 나 = 주관사 선택을 가린 독립 검토자 C**다. 현재 v5의 순위기는 규칙으로 실행된다. 이 설계는 전체 라벨 기록을 입력으로 사용하는 **별도의 A1 AI 선별 조건**을 제안한다. 기존 v5와 실행 기록은 비교 기준으로 사용한다. [v5 작동 흐름과 역할](updateplan.md#3-a1-작동-흐름) · [현재 순위기](../ipo_agent_eval/ipo_eval/a1_ranking.py)

### 2.1 검토 질문과 판단

항목 단위는 **발행기업 × 대상 × 질문**이다. 대상은 발행사, 비교기업 한 곳 또는 집계에 쓰인 후보 집합이다. 이익의 기간과 귀속, 집계 후보군과 집계 방식, 적용 주식 수와 할인처럼 결론이 따로 바뀔 수 있으면 항목을 나눈다. 운영자 항목표에 주관사의 선택·선정 이유·공시 위치와 역할별 `비교 가능 / 역할상 비교 불가`를 기록한다. 검토자 나(C)는 최종 채택 여부와 선정 이유가 가려진 중립 질문과 후보 ID로 답한다.

| 질문 유형 | 같은 항목에서 답할 질문 | 대표 근거 |
|---|---|---|
| J2 선정 요건 | 후보 X는 공시가 적용했다고 밝힌 특정 요건에 부합하는가? | 업종·상장, 재무 특성, 사업별 매출. 명시된 조건의 사실 확인은 B에 연결 |
| J2 사업 비교 적합성 | 후보 X의 제품·매출원·고객이 발행사 배수의 비교 근거로 적절한가? | 제품·적용 공정, 매출 구성, 고객·판매 방식, 재무 특성 |
| J1 이익의 기간과 귀속 | 특정 기간 또는 회계 범위의 이익을 비교에 쓰는 근거가 충분한가? | 발행사와 후보의 실적 기간, 연결·별도, 지배주주 귀속 범위. 기간과 회계 범위는 별도 항목으로 생성 가능 |
| J1 이익 조정 | 특정 손익을 제외하거나 포함한 근거가 충분한가? | 조정 내역, 규모, 반복성 및 관련 주석 |
| J3 기준주가 선택 | 해당 기준일·관측 구간을 적용하는 근거가 충분한가? | 기준일 종가, 기간 평균, 거래소 시세, 산정표 |
| J3 배수 집계 | 해당 후보 집합과 집계 방식이 공시 목적에 적절한가? | 비교기업별 배수, 집계방식과 대안, B 재계산값 |
| J3 주당 평가가액·공모가 범위 | 주식 수 범위 또는 할인율 선택의 근거가 충분한가? | 희석 내역, 할인 근거. 주식 수와 할인은 별도 항목으로 생성 가능 |

**초기 비교는 J2 사업 비교 적합성부터 한다.** 가·나는 동일 후보에 대해 적합성을 판단한다. 주관사의 실제 선별 기준이나 선택을 알아야 하는 요건 확인은 B·가에 연결하고, 검토자 나(C)의 해당 항목은 `역할상 비교 불가`로 기록한다. 나(C)가 이익 기간·배수 집계의 중립 대안을 제시하면 답변 확정 후 사전 규칙으로 연결한다. 다른 대안만 제시했다면 해당 원본 선택에 대한 판정은 `미확인`으로 두고 대안을 보존한다. 자료 요청은 기존 J4처럼 모든 질문에 붙을 수 있는 후속 조치로 기록한다.

| 공통 판정 | 적용 기준 |
|---|---|
| 수용 | 결론을 지지하는 구체적 근거가 있고, 중요한 조건이 해소되거나 남은 한계가 수용 범위 안에서 설명됨 |
| 문제 제기 | 공시 근거와 충돌하거나 선택의 타당성을 약화시키는 구체적 근거가 있음. 근거를 든 추가 검토·제외 포함 |
| 미확인 | 판정을 확정해 줄 자료가 부족하거나 제출에서 명시 판정을 연결하기 어려움. 미확인 사유를 함께 저장 |

조건부 수용은 **조건 해결 여부**를 함께 남긴다. 서로 다른 근거로 가능한 두 판단은 모두 보존한다. 사람 기준표는 특정 모델과의 일치보다 중요한 반대 근거가 해소됐는지 판정한다. ### 2.2 근거 유형

근거는 **독립적으로 확인할 수 있는 사실 하나**와 그 사실이 질문의 선택을 **지지 / 약화 / 조건 설명**하는 방향을 한 건으로 기록한다. 쟁점 하나에 여러 근거를 붙일 수 있다. 기간, 단위, 연결·별도, 분모는 대조에 필요한 경우 각각의 근거에 붙인다. 필수 자료가 빠진 경우에는 자료명·기간·필요 이유를 기록한다.

| 근거 유형 | 기록할 내용 | 원문을 찾는 위치 |
|---|---|---|
| 업종·상장 요건 | 적용 업종 분류, 상장시장·상장 기간, 관리종목 등 확인 항목 | 선정 기준표, 거래소 종목정보 |
| 제품·적용 공정 | 제품 기능, 사용 공정, 초도 공급·유지보수 등 사업 단계 | 사업보고서의 사업 내용과 주요 제품·서비스 |
| 매출 구성·수익원 | 제품·사업부·서비스별 금액·비중, 전체 매출 등 분모, 기간 | 제품별 매출표, 사업부문 주석 |
| 고객·판매 방식 | 고객군·최종 수요처, 직접 납품·간접 판매를 보여주는 사실 | 매출 및 수주상황, 주요 매출처 |
| 재무 특성 | 매출 규모·성장률, 영업이익·순이익, 흑자 여부, 필요한 감사의견 | 선정표, 손익계산서, 감사보고서 |
| 이익 기간·회계 범위 | 온기·반기 연환산·최근 네 분기 합산, 연결·별도, 귀속 주체 | 적용 이익표 각주, 재무제표와 주석 |
| 일회성 손익 조정 | 제외·포함한 항목과 금액, 일회성 판단의 근거 | 산정표 각주, 금융손익 등 재무제표 주석 |
| 시세·배수·집계 | 기준일과 주가 구간, 시가총액, 개별 PER, 집계와 대안 | 거래소 시세, 비교기업별 PER 산출표, B 계산 기록 |
| 주식 수·희석 및 할인 | 신주·구주·잠재 주식 집계, 할인율과 선정 근거 | 모집·매출 조건, 주당 평가가액·할인율 표와 각주 |

J2 첫 파일럿에서는 위쪽 다섯 유형으로 시작한다. **근거 유형은 공통 사전, 실제 적용 수치와 조건은 기업별 신고서의 값**으로 저장한다. 개발 표본에서 두 유형에 겹쳐 붙인 사례와 사전에 들어가지 않는 근거를 대조해 정의를 다듬는다. 해당 질문에 필요한 근거가 소재한 곳을 정하고, 평가 전에 사전 버전을 고정한다. ### 2.3 원문 위치와 확인 상태

| 원문 형태 | 기록할 위치 |
|---|---|
| 최초 증권신고서 PDF | 제출 회사·접수번호·버전 또는 등록된 문서 ID, PDF 물리 쪽, 절·표 제목과 행·열 또는 각주 |
| 발행사·비교기업 자체 공시 | 공시 회사, 문서 ID·공개시점, 보고기간, 절·표·행 또는 주석 |
| 거래소 시세 | 시장·종목 ID, 거래일 또는 기간, 항목과 단위, 데이터 출처 |
| B 계산 기록 | 계산 결과 ID·산식·입력 근거 ID·검사 상태. 원문 위치는 각 입력 근거에서 조회 |

접수번호와 실제 공개 시점, 최초 신고서 이후 자료의 차단은 [v5의 공개시점 규칙](updateplan.md#21-최초-신고서와-공개-시점)을 사용한다. PDF 물리 쪽과 인쇄 쪽이 다르면 물리 쪽을 표준으로 적는다. 구조 점검은 **출처 ID를 찾을 수 있는지**, 내용 대조는 **해당 원문이 정말 주장한 사실을 보여 주는지**, 판단 검토는 **그 사실이 해당 결론을 어느 정도 지지하는지** 확인한다. 보고서가 다른 회사나 연도의 같은 이름 항목을 인용하면 위치가 맞아도 내용 대조에서 보류한다. 두 AI가 같은 표나 그 복제본을 썼다면 원출처 하나로 처리한다. 표의 값과 본문·각주를 이어야 확인되는 근거에는 각 위치를 모두 연결한다. ## 3. 가·나의 독립 라벨과 교차 대조

1. **항목표 동결.** 기업·질문·후보 또는 대상 ID와 역할별 적용 여부를 먼저 고정한다. 각 역할은 허용되는 입력과 ID만 받는다. 검토자 나(C)는 최종 선정표, 선택을 드러내는 B 결과와 가의 응답을 제외한 가림 자료로 검토한다.
2. **독립 응답.** 가·나는 자신의 `판정 + 근거 유형 + 구체적 사실 + 원문 위치 + 남은 조건`을 제출한다. 개발 초기에는 기존 A0·C 응답에서 해당 문장과 인용을 연결하고 원본의 문장·판정을 보존한다. 후속 실험에서 직접 구조화 응답을 받는 변경을 따로 비교할 수 있다.
3. **코드 대조.** 항목과 근거 ID를 대조하고 가·나 원판정을 함께 보관한다. 두 판정으로부터 `양쪽 수용`, `판단 갈림`, `양쪽 문제 제기`, `미확인 포함`을 생성한다. 미확인이 섞이면 그 상태를 표시하고 다른 쪽의 문제 제기도 그대로 남긴다. 같은 사실의 기간·범위가 다르면 `비교 조건 상이`로 표시한다. 양쪽 수용 중 적용 가능한 항목에는 §4.4 결과를 붙인다. 판단 갈림과 나머지 미해소 항목은 이 기록을 A1에 직접 전달한다.
4. **전체 기록 보존.** 모든 원본 항목에 가·나의 판정과 근거, B 검사 상태를 연결한다. 자료 미제공, 응답 누락, 근거 위치 확인 불가, 역할상 비교 불가는 사유를 구분한다. 채점 가능한 사례에서 AI가 근거를 빠뜨린 경우는 해당 AI의 누락으로 기록한다. 항목당 최소 기록은 판정 또는 명시적 미확인이다. 나(C)의 역할상 비교 불가는 판단 갈림 집계에서 제외하되 원본 순위와 사람 기준표에는 남긴다.

가·나가 서로 다른 근거를 댔다면 발행기업과 후보, 기간·사업 범위가 맞는지 먼저 본다. 같은 기간·범위의 사실이 상충할 때는 A1이 실제 원문을 다시 확인할 후보가 된다. 서로 다른 사실은 함께 판단에 쓰일 수 있다.

## 4. A1 AI의 최종판단과 튜닝

### 4.1 입력과 출력

**입력**은 A1에 배정된 항목, 양쪽 판정과 인용, 허용 원문 색인, B 결과, 중대 기준과 기업당 검토량이다. 적용 조건에 따라 §4.4의 합의 점검 결과를 함께 받는다. A1 AI는 한 번의 선별 실행에서 배정 항목을 읽고, 판정을 바꿀 수 있는 부분에 한해 허용 원문을 조회한다. 원문 조회 한도와 실행 시간 상한을 사전에 고정한다. 필수 근거를 확인하지 못하면 `공개 자료 부족 / 조회 예산 소진 / 원문 참조 오류`를 구분한다. 조회 예산 소진과 원문 참조 오류는 미해소 상태와 검토 필요성을 결과에 남긴다.

| 조치 | 적용 조건 | 남길 기록 |
|---|---|---|
| 사람 검토 | 확인 가능한 중요한 쟁점이 있고 그 확인이 선정·산정 판단에 영향을 줄 수 있음 | 항목 ID, 확인 질문 한 문장, 중요성의 근거, 확인할 원문 위치 |
| 자료 요청 | 판단을 좌우하는 정보가 허용 자료에 부족함 | 요청할 문서·기간·표 또는 항목과 현재 막힌 판단 |
| 기록 보관 | 허용 원문과 B 결과로 갈린 이유가 해소되었거나, 근거를 대조한 결과 추가 확인이 선정·산정 판단에 미치는 영향이 중대 기준 아래로 확인됨 | 해소 근거와 원문 위치, 보관 사유, 남은 한계 |

A1은 원본 항목별로 조치를 제안하고, 추가 검토의 우선순위를 **사전 정의한 중대성 → 원문으로 확인할 수 있는 쟁점 → 가격 영향** 순으로 매긴다. 동률은 항목 ID 순이다. 서로 다른 합리적 가정에 근거한 판단을 함께 보관할 수 있다. 가격 영향은 공시 주당 평가가액 대비 대안 평가가액의 절대 변화율로 기록한다. 공시 평가가액이 없거나 0이면 변화율과 사유를 미산출로 기록한다. 할인율만 바뀌는 경우에는 희망 공모가 범위 변화를 별도 필드에 적는다. 기존 파일럿의 중대 기준안은 변화율 **5% 이상** 또는 **비교·산정 판단을 바꿀 만한 근거**다. 적용 범위를 개발 결과를 보기 전에 확정하고, 가격 영향을 산출할 수 없어도 질적 중요성은 판단한다. 확인된 B 중대 오류는 공통 필수 검토로 보존한다. 필수 자료가 없는 중대 쟁점은 자료 요청과 미해소 상태를 남긴다. [v5 중대 기준과 정렬](updateplan.md#32-2층--원본-판단-비교와-시험용-오류-검사)

**출력 검증과 검토량 적용은 코드가 담당한다.** A1에 배정한 각 항목의 조치·사유·순위와 실제 조회 기록에 인용이 연결되는지 확인한다. 입력에 실린 발췌와 A1이 도구로 조회한 원문은 따로 기록한다. 공통 필수 검토를 먼저 포함하고, 사람 검토 적격 항목 가운데 추가 검토량만큼 배정한다. 순위 밖에 남은 적격 항목에는 `검토 대기` 상태를 붙인다. 자료 요청은 별도 표시하고 사람 검토 건수는 목록에 배정된 항목만 센다. 실제 인용이 주장을 지지하는지는 결정에 쓰인 지점과 사전 표본을 사람이 원문으로 대조해 채점한다. 제출 구조 오류는 고정 예산 안에서 형식 보정 한 번을 허용한다. 회복되지 않은 실패와 운영에서 규칙 목록으로 대체한 결과를 각각 기록한다. [AJ-Bench](https://aclanthology.org/2026.findings-acl.1269/)

### 4.2 A1 지시문 초안과 출력 예

> 배정된 모든 항목에서 두 판정과 근거를 대조하라. 업체·기간·분모·재무 범위를 맞추고, 판단이 갈리면 차이가 입력 조건에서 생겼는지 같은 근거의 해석에서 생겼는지 확인하라. 합의 점검 결과는 원본의 어느 근거를 다시 볼지 정하는 데 사용하라. 핵심 반대 근거가 남았고 원문 확인이 선택을 바꿀 수 있으면 사람 검토를 제안하라. 자료가 부족하면 필요한 자료와 아직 확인하지 못한 판단을 적어라. 갈림을 해소했으면 근거와 원문 위치를 남겨라. 배정된 모든 항목에 조치와 이유를 제출하고, 그중 공통 필수 검토 외 항목의 순위를 제시하라.

### 4.3 프롬프트와 정책을 튜닝하는 순서

여기서 튜닝은 **판정 지시문, 예시, 원문 조회 범위와 선별 정책의 개발 보정**을 뜻한다. 수정 때마다 어느 오류가 줄고, 추가 호출이나 사람 확인 시간이 얼마나 달라졌는지 기록한다.

| 순서 | 개발에서 바꿀 것 | 확인할 항목 |
|---|---|---|
| 1. 기준안 | 모델·지시문·원문 조회 상한을 고정하고 세 가지 조치의 정의와 출력 계약 적용 | 배정 항목에 조치가 있는지, 근거 ID와 사람 질문이 유효한지 |
| 2. 경계 사례 | 누락의 첫 지점을 항목 연결 → 근거 조회·인용 → 중요성 판단 → 목록 배정 중에서 기록. 해당 경계 사례를 지시문에 한 번에 하나씩 보강 | 합의 항목의 중대 쟁점 누락, 갈린 판단의 해소 근거, 불필요한 이관, 근거 없이 확정한 판단 |
| 3. 최소 조회 | 공통 발췌만 쓰는 안과 중요한 근거 충돌에 한해 원문을 추가 조회하는 안을 비교 | 맞는 표·행으로 가는 비율, 원문 조회·재시도 부담, 판정이 달라진 이유 |
| 4. 기준안 선택과 동결 | 검증 기업에서 출력 계약·필수 검토 보존을 확인한 안을 중대 쟁점 누락과 검토 비용 순으로 비교해 하나를 선택 | 확정한 프롬프트·모델·도구·자료·라벨 버전과 해시, 검토량·중대 기준·동률·자료 부족 처리를 기록하고 본 평가 입력 열기 전에 고정 |

### 4.4 TRIZ를 적용한 합의 점검

두 AI의 합의를 활용하면 읽을 항목을 줄일 수 있지만, 둘 다 같은 근거를 빠뜨리면 중대 쟁점도 빠진다. 반대로 모두 다시 읽으면 시간과 호출 비용이 든다. TRIZ의 **분할**을 적용해 결론과 개별 근거를 대조하고, **반전**을 적용해 통제된 근거 변화에 대한 반응을 검사한다. **조건에 의한 분리**를 적용해 검사할 만한 합의에만 이 절차를 쓴다. 순위 평가는 **차원 바꾸기**를 적용해 첫 한 건과 전체 순위를 함께 본다. [TRIZ 발명 원리와 모순의 분리](https://wiki.trizstudies.org/Problem-solving-tools.html)

1. **후보 선정.** 양쪽이 수용하고, 같은 기간·기업·사업 범위의 핵심 사실과 그 사실이 판단을 지지하는 경로가 연결되며, 중요한 반대 근거가 해소된 항목을 고른다. 두 인용이 같은 원천이면 한 출처로 센다. 다른 이유로 수용한 항목, 원문 확인이 덜 된 항목, 역할상 비교 불가, 양쪽 문제 제기와 미확인은 A1이 검토한다. B가 확인한 공통 필수는 검사 결과와 관계없이 사람 목록에 남긴다.
2. **변형 시험.** A0·C 각각에 같은 형식과 허용 범위로 항목의 원본 발췌와 변형 발췌를 새 세션에서 따로 제시한다. 순서는 섞고, 원본 답변과 기대 방향은 가린다. C에 주관사의 선택이나 선정 기준을 새로 노출하지 않는다. 발췌 입력에서 원본 판정이 재현되는지 확인해 전체 보고서와 항목 단위 입력의 차이를 기록한다. 원본 판정이 재현되지 않거나 답변·근거가 빠지면 점검 결과를 `미확인`으로 두고 A1이 검토한다.
3. **결과 사용.** 실패·미확인과 적용 불가 사유를 A1에 전달한다. 보류 후보는 두 검토자 모두 원본 판정을 재현하고, 불변 시험과 타당성이 확인된 방향 시험을 통과한 항목이다. 초기 개발에서는 전 항목을 A1이 검토하고 보류 후보를 사람 기준표와 대조한다. 보류 조건을 보정해 동결한 뒤 별도 비교 조건에서 적용한다. 그 조건에서 코드는 A1이 검토한 항목 다음에 보류 항목을 L3-규칙 순으로 붙여 전체 평가 순위를 만든다. 실제 운영에서는 보류와 자료 요청을 별도 상태로 남긴다. 변형에 올바르게 반응해도 두 AI가 함께 놓친 근거가 있을 수 있으므로, 전 항목 기준표로 보류 중대 쟁점과 분모를 확인한다.

| 시험 | 바꾸는 부분 | 확인할 반응 |
|---|---|---|
| 불변 | 의미나 원문 연결을 그대로 둔 채 표 행 순서·서식만 변경 | 판정과 핵심 근거가 유지된다. 원본을 그대로 반복한 응답도 소표본에서 확인해 일반 재실행 변동과 비교한다. |
| 문턱 | 확인된 수치 기준의 경계와 양쪽 값을 제시 | 기준 충족 여부가 정해진 방향으로 바뀐다. B의 규칙 검사와 변형 제작 확인에 사용한다. 해당 요건을 C에 보여줄 수 있는지는 별도로 판단한다. |
| 방향 | 같은 기간·분모·범위에서 사업 비교를 약화하는 근거 하나를 바꾸고 연결된 발췌를 함께 맞춤 | 해당 근거를 더 강한 지지로 인용하지 않고 변화 이유를 설명한다. 독립된 지지 근거가 남는 경우 종합 판정 유지도 허용한다. 결론까지 달라질 관계는 개발에서 사전 확인한다. |

변형 사본에는 원본과 다른 자료 ID를 부여한다. 근거 수치, 분모, 합계, 연결된 설명을 함께 확인한 뒤 쓰고, 변형 수치가 실제 공시 인용이나 사람 기준표에 섞이지 않도록 한다. 부적절한 변형과 답변 실패를 따로 기록한다. 생성 규칙의 적용 가능성은 모델 출력과 원본 사람 판정을 보기 전에 점검한다. `미확인`은 자료나 실행 상태로 기록한다. 전 문서 수준에서 여러 근거를 함께 빠뜨리는 오류는 기존 카나리의 별도 진단 대상으로 둘 수 있다.

|---|---|---|

### 4.5 갈린 판단을 A1에서 대조

**기본안은 A1의 원문 대조 1단계다.** A0·C의 원판정과 인용을 보존하고, 두 검토자가 볼 수 있었던 자료 범위를 함께 A1에 전달한다. A1은 기업별 한 번의 선별 실행 안에서 갈린 항목의 원문을 필요한 만큼 조회한다. A0·C 사이의 상호 재질문은 §5.3의 후속 비교안이다. 이 경로에서는 두 AI의 최초 독립 응답과 C의 가림을 유지한다.

| 갈린 이유 | A1이 확인할 것과 다음 조치 |
|---|---|
| 기간·분모·회계 범위가 다름 | 원문과 B 결과의 기준을 맞춘다. 예를 들어 온기와 반기 매출 비중을 각각 인용했다면 어떤 기간이 질문에 맞는지 확인한다. 차이를 설명했고 중대 쟁점이 해소됐으면 원문 위치와 함께 보관한다. |
| 같은 근거를 다르게 해석함 | 양쪽의 지지·반대 근거가 실제로 같은 질문을 다루는지 확인한다. 선정·산정 판단을 바꿀 쟁점이 남으면 확인 질문 하나와 원문 위치를 붙여 사람 검토 후보로 올린다. |
| 결정적인 정보가 한 역할에게 가려짐 | `역할상 비교 불가`로 기록한다. A1이 허용 원문에서 확인할 수 있으면 자체 대조하고, C의 입력과 응답에는 가려진 주관사 선택을 전달하지 않는다. |
| 근거가 부족하거나 응답·조회가 불완전함 | 부족한 자료나 오류 사유를 적고 `자료 요청` 또는 미해소 상태로 남긴다. 중요 쟁점의 해소 여부를 평가할 때도 이 상태를 집계한다. |

이 항목에 대해서는 비교 조건 차이, 해석 차이, 역할 차이 또는 미확인 사유를 기록하고, 확인한 원문 ID와 최종 조치를 함께 남긴다. 사람 목록에 바로 배정되는 B 공통 필수 항목에는 기존 필수 규칙을 적용한다. 나머지 사람 검토 후보에는 순위를 매기고 코드가 검토량을 적용한다.

## 5. 라벨과 최종 선별의 효용을 비교하는 실험

같은 발행기업 안에서 가·나 원본 응답, 항목 목록, B 결과, 허용 근거와 공개시점, 공통 필수 검토와 기업별 추가 검토량 `K`를 공유한다. 사람이 모델의 판정·순위를 보기 전에 원본 항목 전부를 동일 기준으로 채점한다. A0·C 답변의 항목 연결과 사람 기준표 작성은 가능하면 담당을 나눈다. 한 사람이 맡는 경우에는 모델 출력과 순위를 가린 원본 판정을 먼저 저장하고 확정한 뒤 연결한다. 팀은 사전에 K와 평가 불가 처리 기준을 고정한다.

| 조건 | A1에 주는 입력 또는 선별 방식 | 비교로 알 수 있는 것 |
|---|---|---|
| L1 판정만 | 가·나 판정과 공통 항목 ID. 가·나의 근거 인용은 최초 입력에 첨부하지 않음 | 근거 첨부 효과를 평가하는 기준 |
| L2 판정과 근거를 문장으로 | 같은 판정·사실·원문 위치를 항목별 자유서술 형식으로 제공 | L1과 비교해 근거를 함께 넘기는 가치 |
| L3 구조화 라벨 | L2와 같은 사실·원문 위치를 필드와 근거 ID로 정렬해 제공 | L2와 비교해 구조화의 가치 |
| L3-규칙 구조화 + 규칙 정렬 | L3와 같은 라벨을 사용하고 사전 규칙으로 정렬 | L3와 비교해 A1 AI 선별의 추가 가치 |
| 합의 점검을 포함한 A1 | L3 입력에 합의 점검 결과를 연결하고 A1이 전 항목을 검토한다. 갈린 항목에는 §4.5를 적용한다. | 같은 규칙 기준 대비 전체 방식의 효용 |
| 합의 점검과 조건부 보류를 포함한 A1 | 보류 조건을 검증하고 동결한 뒤 §4.4의 방식으로 순위를 합친다. | 보류로 감축한 A1 검토량과 그에 따른 중대 쟁점 누락·비용 |

L3-규칙은 공통 필수 다음에 **유효한 근거 ID를 붙인 문제 제기 → 미확인 포함 → 나머지** 순으로 정렬한다. 각 묶음은 확인 가능한 가격 영향 내림차순으로 정렬하고, 가격 영향 미확인은 뒤에 두며, 동률은 항목 ID 순으로 처리한다. 가격 영향은 양쪽 조건이 공유하는 원본 공시의 주당 평가가액과 사전에 정한 적격 대안의 B 재계산값으로 구한다. 변형 사본에서 나온 수치는 순위의 가격 영향 입력에서 제외한다. H1의 A1이 별도 조회를 사용하면 전체 방식의 효과로 해석하고, 조회·토큰·시간을 공개한다. 동일 정보에서 선별 방식만 보려는 비교는 추가 조회 없이 L3와 L3-규칙을 비교한다. L1~L3 형식 비교에서는 추가 조회를 끄고 같은 모델·지시문을 사용한다. L2·L3은 같은 근거를 두 형식으로 렌더링한다. 기존 v5 순위표는 카나리 사용과 비용이 달라 참고 결과로 보고한다. ### 5.1 비교 순서와 지표

| 비교 | 측정할 질문 |
|---|---|
| **H1 · 합의 점검을 포함한 A1 대 L3-규칙** | A1 전체 방식이 원본의 자연 중대 쟁점을 상위에 배치하는가? 같은 `K`에서 실제로 더 많이 찾는가? |
| H2 · 점검과 보류를 적용한 A1 대 점검 없이 전 항목을 보는 A1(L3) | H1 이후, 허용 범위 안에서 검토 성능을 유지하면서 점검 비용까지 합친 전체 시간과 비용을 줄이는가? 보류 자체의 영향은 같은 점검 결과를 받고도 전 항목을 보는 조건과 대조한다. 허용할 성능 저하 폭은 사전에 정한다. |
| 탐색 · L1·L2·L3 | 같은 판단과 근거를 어떤 형식으로 넘길 때 효과가 있는가? |

**주 지표 후보는 기업별 순위 일치도다.** 공통 필수 밖에서 판정이 확정된 중대 쟁점과 그 외 항목을 한 건씩 짝짓는다. 중대 쟁점이 더 앞이면 1, 순위가 같으면 0.5, 뒤면 0을 부여해 기업 내 평균을 구한다. 유효한 동률은 항목 ID로 순서를 강제하기 전의 우선순위로 정의한다. 두 조건의 차이는 기업에 같은 가중치를 줘 평균과 불확실성 구간을 보고한다. 두 부류가 모두 있는 기업에서 산출되므로 유효 기업 수와 제외 사유를 공개한다. 판정 유보는 주 분석에서 제외하고 결과가 바뀔 수 있는 범위를 함께 보고한다.

**같은 K의 지표는 자연 중대 쟁점 누락 수다.** 전체 순위 앞에서부터 `min(K, 공통 필수 제외 원본 항목 수)`개를 같은 방식으로 뽑아 비교한다. `K=1`과 `K`별 회수율을 함께 보고한다. 예를 들어 전체 다섯 항목 중 중대 쟁점 두 건이 1·5위이면 순위 일치도는 0.50이고, 2·3위면 0.67이다. 첫 한 건만 볼 때는 각각 1건과 0건을 찾는다. 자료 요청·검토 대기·보관의 중대 항목도 목록 밖 누락에 포함한다. 완전한 순위가 없으면 실패·분모와 운영 대체 결과를 함께 기록한다. 실제 이관량은 §5.3에서 별도로 측정한다.

**보류와 비용도 건수로 남긴다.** 전체 항목 대비 보류 비율, 보류 중대 쟁점 수·보류 건수, 전체 자연 중대 쟁점 중 보류로 빠진 수를 보고한다. 기준표 전수 채점이 있는 평가에서는 보류 항목 전부를 대조한다. 전수 채점이 없는 운영에서 표본 감사를 할 때는 추출 규칙과 분모를 기록한다. 비용은 변형 제작·확인 시간, A0·C의 원본 재제시와 변형 호출, A1 호출·조회·토큰, 사람 확인 시간을 포함한다. 두 검토자에게 원본과 변형 2종을 각각 별도 요청하면 항목당 6회다. 예산과 허용 누락선을 보정 전에 정하고, 비용이 실제로 줄었는지 H2에서 확인한다.

### 5.2 평가 기업 수와 파일럿

기업별 순위 차이에 대한 양측 짝 t검정, 유의수준 5%, 목표 검정력 80%를 가정한 산정이다. 표준화한 차이 `d`가 `0.5 / 0.6 / 0.7 / 0.8 / 1.0`일 때, 주 지표를 산출할 수 있는 기업은 각각 `34 / 24 / 19 / 15 / 10`곳이 필요하다. **유효 기업 18곳은 d≈0.70, 14곳은 d≈0.81**을 가르는 규모다. 전체 18곳의 70%에서만 순위 일치도를 계산할 수 있다면 평균 12.6곳이다. 평가 18곳과 최소 14곳은 일정 검토를 위한 후보로 두고, 필요한 유효 기업 수와 확보 가능한 전체 기업 수를 따로 산정한다. [짝 t검정 검정력 계산](https://www.ncss.com/wp-content/themes/ncss/pdf/Procedures/PASS/Paired_T-Tests.pdf)

**개발은 HD현대마린솔루션·멜콘**에서 시작한다. 두 곳에서 J2 항목 연결, 가림, 변형의 타당성과 기업당 채점 시간을 점검한다. 개발과 겹치지 않는 검증 사례에서 전체 및 공통 필수 밖 자연 중대 쟁점 수, 순위 일치도가 정의되는 기업 비율, 보류 대상과 실측 비용을 기록한다. 검증 기업 4곳은 가능성을 확인할 소표본으로 활용한다. 최종 평가 규모와 분석 방법은 평가 기업의 모델 답과 기준표를 보기 전에 고정한다. 사람 평가자가 한 명이면 표본 재점검은 동일인 재점검으로 보고한다. ### 5.3 실제 사람 이관 평가

같은 K에서는 두 조건이 각각 주어진 수만큼 사람에게 보내므로 목록의 **구성**을 비교할 수 있다. 실제 운영에서는 사전에 정한 중대 기준에 따라 **사람이 풀어야 할 쟁점이 있는 항목만** 이관한다. 이렇게 만든 운영 목록을 같은 기업의 기준 운영 목록과 짝지어, 이관량과 중대 누락을 함께 비교한다. 공통 필수 항목은 두 목록에 들어간다.

| 기록 | 계산과 해석 |
|---|---|
| 사람 이관 건수와 비율 | 실제 배정된 원본 항목 수와 전체 원본 항목 대비 비율을 기록한다. 공통 필수와 그 외 항목을 함께 세고, 각각의 건수도 보고한다. 검토 대기와 자료 요청 건수는 따로 남긴다. |
| 자연 중대 쟁점 누락 | 사람의 전 항목 원본 기준표에서 이관 목록 밖의 중대 쟁점 수와 전체 중대 쟁점 수를 기록한다. 자료 요청·검토 대기·보관·조건부 보류에 남은 중대 쟁점도 포함한다. 사유와 상태를 함께 보고한다. |
| 사람 시간과 전체 비용 | 실제 원문 확인 시간, 모델 호출·토큰·조회, 변형 자료 제작·확인 및 반복 요청을 포함한다. 사람 이관이 줄어도 대기·재작업과 비용이 어떻게 바뀌었는지 기록한다. |

운영 정책의 중대 기준, 배정 상한과 허용할 누락 범위는 결과를 보기 전에 고정한다. 실제 배정 건수는 기준에 따라 달라질 수 있다. **허용 범위 안에서 중대 누락을 유지하면서 이관 건수나 사람 시간이 줄었는지**로 자동화 범위를 판단한다. 모델 조건을 바꾸거나 항목이 평가 불가능하면 사유를 남긴다.

**갈린 항목의 상호 재질문은 후속 실험으로 둔다.** A1이 반복해서 사람에게 이관한 유형이 확인되면, 해당 유형에 한해 현재의 A1 원문 대조 경로와 재질문 한 차례를 추가한 경로를 짝 비교한다. 두 조건에 같은 원본 A0·C 답변, 자료 범위와 A1 설정을 적용한다. 재질문에는 각 역할이 원래 볼 수 있는 근거만 넣는다. C의 가림을 지킬 수 있는 범위에서 달라진 근거를 재확인하고, 결론이 가까워진 것과 근거가 실제로 해소된 것을 구분한다. 추가 호출, 사람 이관, 자연 중대 쟁점 누락을 함께 기록하고, 누락이 허용 범위 안에 있으면서 추가 비용 대비 이관이 줄어든 유형에만 확대를 검토한다.

## 6. 검증 사례와 작업 단위

| 사례 | 기대하는 처리 |
|---|---|
| 둘 다 수용했으나 한 응답이 인용한 중요한 반대 근거를 해소하지 못함 | 원문이 해당 질문을 실제로 약화하는지 보고 사람 검토 후보로 올림 |
| 두 판단이 다르지만 사용 용어와 전제가 둘 다 설명됨 | 양쪽 근거와 남은 조건을 보존하고 중대한 차이의 유무를 판단 |
| A0와 C가 같은 기간·분모를 확인한 뒤에도 사업 적합성 해석이 갈림 | A1이 양쪽 근거를 원문에서 대조. 선정·산정에 영향이 남으면 사람 검토 질문을 기록 |
| A1이 갈린 이유를 공개 원문으로 해소함 | 인용과 해소 이유를 보관하고 사람 기준표로 이관 감소와 중대 누락을 대조 |
| 숫자가 같아도 한쪽은 전년도·별도, 다른 쪽은 당해연도·연결 | 비교 조건 상이로 표시하고 같은 기간·범위 근거를 확인 |
| 두 AI가 같은 자료를 재인용, 또는 같은 문서의 복제본을 각각 인용 | 원출처를 하나로 연결하고 별도 확인값을 따로 기록 |
| 근거 ID가 유효하나 해당 페이지의 다른 회사 행임 | 구조 검사와 내용 대조 결과를 나눠 기록. 원문 일치 재확인 |
| 한 AI가 중요한 쟁점을 말했고 다른 AI의 답변이 누락됨 | 쟁점과 미확인을 동시에 보존. 자료 누락과 모델 응답 누락을 구분 |
| B가 명시된 산식을 재현했고 기간 선택의 타당성은 남음 | B 통과 기록과 A1의 판단 요청을 함께 보존 |
| A1이 적격 항목을 검토량보다 더 많이 찾음 | 상위 항목을 사람 검토로 보내고, 나머지 적격 항목은 검토 대기로 기록 |
| 양쪽이 변형 시험을 통과했지만 사람 기준표에서 중요한 반대 근거를 확인함 | 초기 비교에서 보류 대상의 중대 쟁점으로 기록하고 보류 조건을 재점검 |
| 나(C)가 볼 수 없는 주관사 기준을 알아야 하는 항목 | 역할상 비교 불가를 기록하고 A1에 배정. B로 해당 수치 조건을 확인 |

실행 준비 작업은 **항목·근거 사전 고정 → A0·C 응답 연결과 J2 변형 확인 → A1 전수 검토에서 갈림 해소·조치를 사람 기준표와 대조 → 보정 조건을 동결한 뒤 같은 K의 순위와 실제 이관량 평가** 순서다. 실제 모델 성능과 검토시간은 [실행 기록](../ipo_agent_eval/reports/a1_development/진행과_3회_점검.md)에 남긴다.
