## 0. 한눈에 보기

- **연구 질문.** 두 AI가 최초 증권신고서의 공모가 산정에 동의했을 때, 그중에서 사람이 다시 봐야 할 판단을 더 잘 골라낼 수 있는가?
- **실험 조건.** A0는 원래 프로젝트의 개선 전 에이전트다. A1은 이 A0에 사실·계산 검사, 두 번째 검토자 B, 시험용 오류 검사(카나리)를 붙인 조건이다. A1은 A0 보고서에 검증 결과와 사람 확인 대상을 표시한다.
- **카나리의 역할.** 실제 신고서의 복사본에 연구팀이 미리 정의한 문제를 하나 넣는다. 비교기업 카나리는 업종은 비슷하지만 사업모델이 다른 기업처럼 실제로 놓치기 쉬운 사례를 사용한다. 명백한 이종업종 예시는 기본 작동 확인에 쓴다.
- **파일럿의 처리 규칙.** 두 AI가 실제 항목을 모두 수용했는데 유효한 카나리도 둘 다 놓쳤다면, 그 항목의 사람 검토 우선순위를 높인다. 카나리에서 한쪽 또는 양쪽이 문제를 발견한 결과는 기록한다.
- **자동 통과를 검토할 조건.** 같은 수의 실제 항목을 사람이 본다는 가정 아래, 카나리를 추가한 방식이 카나리 없이 두 AI를 비교한 방식보다 중요한 쟁점을 덜 흘려보내는지 평가한다. 이 비교에는 사람 검토 목록 밖의 실제 항목도 포함한다.
- **[v3] 신호의 단위와 검정력.** 카나리 결과는 항목 하나가 아니라 **(기업, 오류 유형)** 단위의 신호다. 평가 기업이 12곳 안팎이면 이 신호의 관측 단위도 그만큼이고, 실제 중대 쟁점은 드물 수 있다. 그래서 자연 쟁점 비교를 주 분석으로 두되, 같은 유형의 **평가용 심은 쟁점**을 따로 만들어 검정력을 보강한다(7.5절). 파일럿에는 계속·중단 기준을 둔다(11절).

## 1. 배경과 연구 범위

### 1.1 어느 시점의 무슨 판단을 검토하는가

최초 증권신고서에는 발행사의 사업·재무자료와 주관사의 희망 공모가 산정근거가 함께 들어 있다. 실적 기반 PER 방식이라면 발행사 자체의 적용 이익과 주식 수, 비교기업 선정 과정과 적용 배수, 주당 평가가액, 희망 공모가 범위가 서로 연결된다. 이 연구는 **최초 신고서가 공개된 때부터 기관 수요예측 전까지** 그 산정근거를 검토하는 상황을 가정한다.

| 검토 대상 | 예시 | 이번 설계의 처리 |
|---|---|---|
| 원문으로 확인할 수 있는 사실·계산 | 주식 수의 기준일, 억 원과 원의 변환, 평균 PER과 주당 평가가액의 산식 | 원문 대조와 재계산 |
| 근거를 따져야 하는 판단 | 어느 기업을 비교기업으로 볼지, 어느 실적 기간을 적용할지, 이례적 이익을 어떻게 다룰지 | 두 검토자의 판단 비교, 시험용 오류 검사, 사람 검토 |
| 공모 이후에 관찰되는 결과 | 수요예측을 거쳐 확정된 공모가, 후속 정정, 상장 후 주가 | 후속 정정만 보조 자료로 활용 |

최초 신고서 제출 이후 기관 수요예측을 거쳐 최종 공모가가 정해지고 청약이 진행된다. 금감원의 공시 심사와 기관 수요예측은 흐름에서 구분한다. 희망 공모가 산정근거를 투자자가 검토하는 시점이 연구의 초점이다. 주 사용자는 수요예측 전에 여러 기업의 신고서를 보는 **기관 애널리스트**다. 운용사·증권사의 리스크 및 AI 도입 담당자에게는 **어떤 항목을 왜 사람이 다시 봐야 하는지**를 근거와 함께 보여준다.

### 1.2 기존 에이전트에서 무엇을 바꾸는가

| 구성 | 맡는 일 |
|---|---|
| **A0** | 원래 프로젝트의 개선 전 에이전트. 실제 신고서와 산정표를 읽고 적용 이익(J1)·비교기업(J2)·민감도(J3)·추가 확인(J4)에 대한 검토 보고서를 작성한다. |
| **기존 프로토콜의 A1** | A0에 자동 검사와 제한된 재검토를 붙여 필요한 경우 에이전트가 보고서를 다시 제출하도록 한 개선안이다. |
| **이번 A1 초안** | 같은 A0를 보고서 작성에 사용한다. 기존 규칙 검사에는 재계산 결과나 수정 제안을 기록하고, 새 검토자 B와 카나리로 실제 항목의 사람 검토 우선순위를 정한다. |

이번 실험은 동일한 A0 보고서를 각 비교 조건에 재사용한다. 계산 오류는 원문 위치, 독립 재계산 결과, 정정 제안을 별도 필드에 기록한다. 사람 검토 우선순위의 성능은 이 A0 원본과 추가 검증 기록을 기준으로 평가한다.

원래 프로토콜의 고정 절차 기준선에도 B라는 이름이 있다. 이 문서에서 **검토자 B**는 주관사의 선택을 가린 상태에서 산정근거를 독립적으로 재구성하는 두 번째 AI를 가리킨다.

## 2. 입력 자료와 접근 범위

| 자료 | A0에 제공 | 검토자 B에 제공 | 실험에서 하는 일 |
|---|---|---|---|
| 최초 증권신고서의 사업·실적·재무·주식 수 관련 자료 | 제공 | 근거 자료로 제공 | 신고서 최초 공개 시점을 입력 기준으로 고정 |
| 주관사의 최종 비교기업, 적용 이익, 배수 집계 방식, 산정표와 이를 드러내는 요약 문구 | 제공 | 가림 | B의 답을 받은 뒤 대조기가 읽음 |
| 비교기업 후보의 사업·재무·배수 자료 | 제공 | 최종 선정 여부와 선정 이유를 가린 후보 자료로 제공 | 후보별 판단의 이유를 확인 |
| 후속 정정 증권신고서·투자설명서 | 평가 입력에서 제외 | 평가 입력에서 제외 | 실제 정정 항목을 사후 보조 지표에 활용 |
| 시험용 변형본 | 산정표를 포함한 자료 제공 | 최종 선택을 가린 후보 자료 제공 | 원본 실행과 별개로 탐지 행동을 측정 |

B의 과제는 후보군과 재무자료를 근거로 **적용 이익, 비교기업, 배수 집계 방식을 제안하고 이유를 설명하는 것**이다. 동일한 공모가 산정 항목을 대조할 수 있도록 정해진 양식으로 받는다.

과거 사례는 최초 신고서 공개 시점까지 확보 가능한 자료를 기준으로 재구성한다. 원본의 주관사 선택이 드러나는 문구가 B의 후보 파일·검색 결과·문서명에 남아 있는지 파일럿에서 확인한다. 모델이 실제 최종 목록을 기억한 것으로 의심되는 사례는 따로 표시하고, 결과에 미치는 영향을 확인한다.

### 3.1 1층 — 사실·계산 검사

기존 프로토콜 8.4의 검사기를 사용한다. 원문 위치 및 재계산 결과를 함께 저장하고, 확인된 문제와 재확인이 필요한 신호를 구분한다.

| 검사 | 확인 신호 | 보고서에 붙일 결과 |
|---|---|---|
| 단위·산식·주식 수 | 원문과 입력값이 다르거나 결과가 재계산과 불일치 | 출처, 재계산 결과, 수정 제안 |
| 시점·기간·연결 범위 | 기준일, 연간·누적 실적, 연결·별도 기준이 섞임 | 충돌하는 필드와 재확인 대상 |
| 반올림 | 차이가 원문의 표시 정밀도 범위 안인지 대조 | 표시 정밀도에 따른 차이 여부 |
| 근거 연결 | 주장에 인용이 없거나 인용한 위치에 근거가 없음 | 다시 찾아야 할 자료 또는 주장 보류 사유 |
| 정정본 혼입 | 최초 신고서 시점 이후의 자료가 입력에 섞임 | 혼입 위치와 재검토 대상 |

### 3.2 2층 — 원본 판단 비교와 시험용 오류 검사

**① 원본에 대한 판단을 각각 받는다.** A0는 신고서의 실제 산정근거를 읽고 항목별로 수용 또는 문제 제기를 기록한다. B는 주관사의 선택을 가린 자료를 보고, 각 비교기업 후보에 **포함·추가 검토·제외**와 근거를 남긴다. 적용 이익 등 다른 항목도 제안값과 근거를 받는다.

**② B의 판단을 원본의 주관사 선택과 대조한다.** 예를 들어 주관사가 포함한 기업을 B가 제외하고 그 이유를 사업자료에서 찾았다면, 그 기업을 빼거나 B의 대안을 적용해 주당 평가가액 변화를 계산한다. 이 차이와 판단 근거를 사용해 A0와 B의 수용·문제 제기를 비교한다. 후보가 B의 최종 목록에서 빠졌다는 사실만으로는 문제 제기로 코딩하지 않는다. 근거가 없거나 영향 계산에 필요한 자료가 부족하면 별도 표시한다.

**③ 별도 실행에서 시험용 오류에 대한 반응을 받는다.** 원본과 변형본을 별도 실행으로 처리하고 실행 순서는 섞는다. 각 실행에는 이전 입력·출력을 이어주지 않는다. 두 검토자는 어느 실행이 원본인지, 어느 후보나 항목이 시험 대상인지, 다른 검토자가 어떻게 응답했는지 알 수 없다. B용 자료에는 시험 후보도 같은 형식으로 넣고, 최종 선정 표시는 가린다.

**④ 원본 검토 결과에 사람 확인 우선순위를 붙인다.** 아래 표에서 0·1·2명은 해당 유형의 유효한 카나리에서 근거를 제시하며 문제를 발견한 검토자 수다. 적용 가능한 시험이 없거나 응답이 유효하지 않은 경우에는 별도 상태를 사용한다. 원본 항목과 시험 유형의 연결 기준도 사전에 고정한다. 예를 들어 매출원·판매 방식의 유사성을 판단하는 원본 항목에 사업모델 불일치 시험을 연결한다.

| 원본 결과 | 같은 유형의 카나리 결과 | 파일럿 처리 |
|---|---|---|
| A0와 B의 판단이 갈림 | 전체 | 양쪽 근거와 가격 영향을 쟁점 목록에 기록. 중대한 불일치는 공통 필수 검토에 포함 |
| 둘 다 문제 제기 | 전체 | 합의된 지적을 기록. 중대한 지적은 공통 필수 검토에 포함 |
| 둘 다 수용 | 0명 탐지 | 해당 유형의 원본 항목을 사람 재검토 목록에서 상향 |
| 둘 다 수용 | 1명 또는 2명 탐지 | 두 경우를 따로 기록하고 기본 검토 우선순위 적용 |
| 둘 다 수용 | 시험 없음 또는 무효 | 탐지 상태를 미확인으로 기록하고 기본 검토 우선순위 적용 |
| 한쪽의 근거 또는 필수 정보 부족 | 전체 | 자료 부족·판정 보류 상태와 필요한 자료를 기록 |

기본 검토 우선순위는 실제 항목의 가격 민감도와 사전에 정한 중대 판단 기준에 따른다. 카나리 0명 탐지는 **두 검토자가 이번 시험에서 해당 유형의 문제를 함께 놓쳤다는 기록**이다. 자료 부족이나 시험 실패로 탐지를 채점할 수 없는 경우와 구별한다.

**[v3] ⑤ 신호의 단위와 정렬 규칙.** 한 기업의 비교기업 카나리 결과는 그 기업의 비교기업 항목 전체에 같은 값으로 붙는다. 따라서 카나리는 "어느 기업의 어느 유형 항목들을 먼저 볼지"를 정하고, 같은 묶음 안의 순서는 가격 영향이 정한다. 정렬 규칙을 다음처럼 고정한다.

~~~text
1순위: 공통 필수 검토 (실행 중 중대 판정을 받은 불일치·합의 지적)
2순위: 둘 다 수용 + 해당 유형 0명 탐지 → 묶음 안에서는 가격 영향 큰 순
3순위: 나머지 항목 → 가격 영향 큰 순
동순위: 가격 영향 미확인 항목은 같은 순위의 맨 뒤, 그 안에서는 사례 ID·항목 ID 순
~~~

카나리 없는 기준선(A0 + B)은 2순위가 없고 1순위 다음 바로 3순위 규칙을 쓴다. 두 조건의 차이는 2순위의 존재뿐이다.

**[v3] ⑥ 실행 중 "중대" 판정과 사람 기준표의 분리.** 실행 중에는 사람이 없으므로 "중대한 불일치"를 규칙으로 정한다. 기본안은 **해당 선택을 대안으로 바꿨을 때 주당 평가가액 변화의 절댓값이 사전 기준(예: 5%) 이상**이면 실행 중 중대로 본다. 사람 기준표의 "중대 쟁점"(7.1절)은 이 값과 별개로 평가자가 원문을 보고 판정한다. 두 기준이 같은 민감도 계산을 쓰더라도, 기준값은 규리가 A1 설계와 독립적으로 먼저 고정하고 실행 중 규칙은 그 값을 읽기만 한다. 실행 중 판정과 사람 판정이 어긋난 항목 수를 함께 보고한다.

### 3.3 최종 상태와 산출물

사람 검토로 보낸 항목에는 항목명, 원문 위치, 양쪽 판단, 평가가액 영향, 검토 우선순위의 이유를 붙인다. A0 보고서 원본과 추가 검증 기록은 같은 사례 ID로 연결한다.

~~~text
유효한 최종 제출 없음 → FAILED
해소되지 않은 중대 쟁점으로 사람 검토가 필요함 → HUMAN_REVIEW
필수 근거가 없어 판단을 계속할 수 없음 → PENDING_INFO
현재 규칙에서 별도 조치가 지정되지 않음 → READY
~~~

카나리 공동 놓침은 우선순위를 높이는 기록이다. 그 결과만으로 원본에 오류가 있다고 표시하거나 최종 상태를 바로 바꾸지 않는다. READY는 실행 절차의 상태이며, 실제 오류가 통과했는지는 7절에서 별도로 채점한다.

### 3.4 운영 모드와 비용

| 모드 | 방식 | 검토 실행 수 예시 |
|---|---|---|
| 정밀 | 원본 1건, 오류 변형본 3건, 정상 대조본 1건을 검토자 2명이 각각 처리 | 사례당 10회 |
| 절약 | 원본 1건과 사전에 고른 유형의 오류 변형본 1건을 검토자 2명이 각각 처리. 다른 유형은 시험 없음으로 기록 | 사례당 4회 |

각 검토 실행에 여러 모델 호출이 들어갈 수 있다. 비용 비교에는 실제 호출 수·토큰·시간을 별도로 기록한다. 기존 프로토콜의 공통 실행 상한을 넘는 구성은 조건별 실제 사용량을 함께 보고한다. 파일럿에서 기본 모드와 검토 대상 유형 수를 결정한 뒤 평가 전에 고정한다. 정밀 모드의 추가 비용이 크면 기존 문서의 **같은 비용의 A0 반복 실행**을 보조 기준선으로 둔다.

[v3] 7.5절의 평가용 심은 쟁점을 쓰면 평가 기업마다 A0·B 실행이 2회 늘어난다(정밀 12회, 절약 6회). 이 실행은 성능 검증용이라 실제 운영 비용에는 넣지 않고, 실험 비용으로 따로 적는다.

## 4. 카나리와 정상 대조본을 만드는 법

### 4.1 시험 자료의 세 종류

| 종류 | 무엇을 바꾸는가 | 무엇을 확인하는가 |
|---|---|---|
| 명백한 오류 | 무관한 업종의 기업을 비교기업에 포함하거나, 연결된 산식·단위에 원문으로 확인할 수 있는 오류를 추가 | 입력을 읽고 기본 문제가 드러나는지 확인 |
| 현실적인 오류 | 같은 업종 안에서 겉보기엔 그럴듯하지만 매출원, 고객, 판매 방식, 실적 정상화 등에 중대한 차이가 있는 선택을 삽입 | 실제 검토에서 놓칠 법한 중요한 차이와 그 근거를 지적하는지 확인 |
| 정상 대조 | 자료 형식과 변경량이 비슷하게 보이도록 후보를 바꾸되, 해당 시험 유형에서는 수용할 근거가 있는 선택을 삽입 | 바뀐 항목마다 경고하는 방식의 과잉 지적을 확인 |

명백한 오류는 기본 작동 확인에 사용한다. 원본의 판단 항목에 붙이는 우선순위 신호는 **해당 위험에 대응하는 현실적인 카나리**를 중심으로 평가한다. 정상 대조는 목표로 삼은 오류 유형에 한해 오경보를 채점한다. 별개 쟁점에 대해 근거 있는 지적을 하는 경우는 별도로 기록한다.

### 4.2 변형 규칙

1. **개발 사례의 실제 실패에서 출발한다.** 예를 들어 A0가 후보의 업종 코드만 보고 매출원 차이를 놓쳤다면, 그 실패를 ‘업종은 유사하지만 사업모델이 다른 비교기업’이라는 유형에 연결한다. 최초 파일럿은 비교기업 1개 유형으로 시작하고, 자료와 시간이 허용되면 적용 이익 유형을 추가한다.
2. **시험 대상 선택 하나를 바꾼다.** 비교기업 한 곳을 바꾸면 최종 목록, 후보 자료, 선정 설명, 적용 평균 배수, 관련 평가가액을 서로 맞춘다. 원본은 따로 보관하고, 바뀌기 전후의 원문·근거·가격 영향을 기록한다. 그래야 산술 불일치만 보고도 판단형 시험을 맞히는 일이 줄어든다.
3. **가격 영향과 목표 오류 유형을 함께 기록한다.** 정상 대조본도 가능하면 비슷한 양의 자료 수정과 유사한 배수 변화를 사용한다. 고PER 후보를 본 순간 경고하는 행동만으로 사업모델 차이를 맞혔다고 처리하지 않는다.
4. **시험 대상을 지목하는 표현을 막는다.** B에게는 같은 출력 양식으로 모든 판단 대상 후보의 근거를 받는다. A0와 B에 주는 파일명·요약·문항에서 시험 대상만 별도로 표시하지 않는다. 두 검토자에게 시험 대상의 판단에 필요한 사업·재무근거를 실제로 제공한다.
5. **채점 기준을 실행 전에 확정한다.** 시험본마다 목표 항목, 증거가 있는 위치, 중대한 이유, 탐지로 인정할 답변, 정상 대조의 허용 판단을 적는다. 사람이 자료로도 판단하기 어려운 변형이나 다른 오류가 섞인 변형은 시험 전 수정하거나 무효 처리한다.
6. **기업 단위로 기록한다.** 변형본은 같은 기업에서 만든 시험 자료다. 기업 수, 실제 판단 항목 수, 변형본 수, 반복 실행 수를 따로 집계한다.
7. **[v3] 가능하면 유형당 카나리를 2개 이상 둔다.** 카나리 1개는 실행 한 번의 우연(같은 입력에도 답이 바뀌는 모델 변동)에 크게 흔들린다. 유형당 2~3개를 두면 탐지 수를 0·1·2명 대신 **탐지 비율**로 볼 수 있다. 비용 때문에 1개만 쓰는 경우에는 파일럿에서 같은 카나리를 2회 실행해 결과가 얼마나 바뀌는지 먼저 잰다.
8. **[v3] 실제 기업 자료로 만든다.** 현실적인 비교기업 카나리(예: OEM·ODM 비중이 높은 화장품 기업)는 가상의 회사를 지어내지 않고, 같은 업종 상장사 중 사업보고서의 매출 구성으로 차이가 확인되는 실제 기업을 쓴다. PER 등 배수는 원본 신고서의 기준일과 같은 방식으로 맞춘다. 지어낸 회사는 B가 "자료가 이상하다"는 이유만으로 잡을 수 있고, 사람 평가자도 판정 근거를 원문으로 확인할 수 없다.

### 4.3 탐지와 오경보의 기준

- **사실·계산형.** 해당 항목을 특정하고 원문 값과 불일치를 근거로 지적하면 탐지다.
- **판단형.** 해당 후보나 산정 선택을 특정하고, 검토에 영향을 주는 구체적인 차이를 자료에 근거해 설명해야 한다. 그 차이를 이유로 추가 검토·제외를 요청하거나, 차이를 인정한 상태에서 포함 근거와 민감도를 제시하면 탐지로 기록한다.
- **후보 누락.** B가 해당 기업을 최종 목록에서 빼기만 하면 탐지로 세지 않는다. 판단 근거에서 시험이 겨냥한 차이를 확인할 수 있어야 한다.
- **정상 대조.** 근거가 충분한 후보에 대해 시험이 겨냥한 문제를 근거 없이 있다고 주장하면 오경보다.
- **채점 불가.** 필요한 자료가 빠졌거나 출력이 유효하지 않으면 탐지 여부를 미확인으로 둔다. 유효한 응답에서 문제를 놓친 경우와 따로 집계한다.

### 4.4 [v3] 현실적인 비교기업 카나리 제작 순서

| 단계 | 할 일 | 자료 | 남길 기록 |
|---|---|---|---|
| 1 | 원본 신고서의 비교기업 선정 기준(업종 코드, 재무 기준, 사업 유사성 설명)을 표로 옮김 | 원본 신고서 | 기준별 원문 위치 |
| 2 | 같은 업종 코드 상장사 중 1차 기준은 통과하지만 매출원·고객·판매 방식이 뚜렷이 다른 후보를 찾음 | 후보 기업의 사업보고서 매출 구성, 주요 제품·고객 | 차이를 보여주는 원문 위치 2곳 이상 |
| 3 | 원본 기준일과 같은 방식으로 후보의 배수 계산, 바꿨을 때 평균 배수와 주당 평가가액 변화 계산 | 기준일 주가·이익 | 가격 영향 (중대 기준 이상인지) |
| 4 | 같은 절차로 정상 대조 후보를 찾음. 사업 구조가 비슷하고 배수 변화량이 가능하면 비슷한 기업 | 같은 자료 | 수용 근거 원문 위치 |
| 5 | 최종 목록·후보 자료·선정 설명·평균 배수·평가가액을 함께 바꾼 변형본 작성 | 원본 사본 | 원본 대비 수정 내역 |
| 6 | 두 사람이 각자 "원문만 보고 이 차이를 지적할 수 있는가", "중대한가"를 판정. 둘 중 하나라도 아니라고 하면 수정 또는 무효 | 4.2의 채점 기준 | 판정과 무효 사유 |

카나리 한 개에 드는 시간은 파일럿에서 잰다. 이 값이 기업 수(멘토 P3)와 카나리 수 사이의 교환 관계를 정하므로, 11절 진행·중단 판단에 함께 쓴다.

## 5. 예시 — 가상 화장품 기업

발행사는 자체 브랜드로 화장품을 판매한다. 적용 순이익은 10억 원이고 적용 주식 수는 500만 주다. 세 비교기업의 PER이 12배, 15배, 18배라면 평균은 15배이고 주당 평가가액은 **3,000원**이다. 아래 기업·숫자는 모두 흐름을 설명하기 위한 예시다.

### 5.1 현실적인 카나리를 만드는 과정

1. **원본.** 발행사와 마찬가지로 자체 브랜드 비중이 높은 비교기업 Y가 15배로 들어 있다.
2. **변형본.** Y 대신 업종은 화장품이지만 매출의 80%가 OEM·ODM 위탁생산에서 나오는 Z를 넣는다. 이 시험에서 Z의 PER은 30배다. 바뀐 평균 PER은 20배, 주당 평가가액은 4,000원이므로 이 변경은 가격에도 영향을 준다.
3. **기대하는 응답.** “Z의 위탁생산 중심 매출 구조는 발행사의 자체 브랜드 사업과 다르고, 마진이나 성장성을 같은 기준에서 비교하기 어렵다. Z 포함·제외 시 주당 평가가액을 확인할 필요가 있다.” 이 수준의 지적을 탐지로 인정한다.
4. **정상 대조본.** Y 대신 자체 브랜드 매출과 판매 구조가 발행사와 유사한 다른 후보를 넣는다. 그 기업의 PER도 30배로 맞출 수 있다. 이 경우 높은 배수에 관한 합리적인 질문과 사업모델 불일치에 대한 근거 없는 경고를 구분한다.

### 5.2 시험 결과를 실제 원본에 적용하는 과정

| 원본에서 검토한 항목 | A0 | 검토자 B | 검토 우선순위와 처리 예시 |
|---|---|---|---|
| 18배 비교기업 X 포함 | 수용 | 근거를 들어 제외 | X를 빼면 원본 평가가액이 3,000원에서 2,700원으로 바뀐다. 불일치와 가격 영향으로 쟁점 목록에 올림 |
| 15배 비교기업 Y 포함 | 수용 | 근거를 들어 포함 | 두 검토자가 시험에서 Z의 사업모델 차이를 모두 놓쳤다면 Y의 검토 우선순위를 올림 |
| 발행사의 이익 정상화 | 문제 제기 | 문제 제기 | 두 AI가 함께 지적한 근거를 기록하고, 중요한 경우 사람에게 이관 |
| 적용 주식 수 | 수용 | 수용 | 원문과 산식은 규칙 검사로 확인하고, 해당 유형에 카나리가 없다면 시험 상태를 미확인으로 기록 |

**사람이 실제로 보는 대상은 원본의 X와 Y 같은 항목이다.** 시험용 Z는 두 AI의 검토 행동을 측정하는 자료다. 공동 놓침으로 Y의 검토 순서를 올렸더라도 Y의 적절성은 원본 근거를 봐야 결정할 수 있다.

## 6. 연구 질문과 선행연구에서 가져온 요소

이번 설계는 규칙 검사, 독립 검토, 통제된 오류 주입을 결합한다. 기존 초안의 오류 주입·판정자 감사 연구는 검토자의 놓침을 측정하는 발상에, 판정자 간 오류 상관 연구는 합의를 해석하는 문제의식에, 감사의 분석적 절차는 독립적인 기대치를 만드는 접근에 해당한다.

이번 프로젝트의 검증 대상은 **IPO 검토에서 실제로 두 AI가 함께 수용한 판단 가운데, 시험용 오류 결과를 이용해 사람이 봐야 할 항목을 더 잘 골라낼 수 있는가**다. 다음 질문을 구분해서 답한다.

1. 두 검토자가 함께 놓친 시험 오류는 어떤 유형에 몰리는가?
2. 검토자 B에게 주관사의 선택을 가리면 함께 놓치는 오류가 줄어드는가? 이 비교는 동일 모델·같은 자료에서 최종 선택의 공개 여부를 바꾼 보조 실험으로 확인한다.
3. 실제 검토 항목에서 **같은 사람 검토량**을 쓸 때 카나리를 추가하면 통과된 중대 쟁점이 줄어드는가?
4. 명백한 시험 문제와 현실적인 문제의 탐지 결과가 실제 신고서의 확인 필요 항목을 얼마나 잘 구분하는가?

**[v3] 선행연구 대비 위치 (발표용 한 문단).** 오류를 심어 AI 판정자를 시험하는 연구(FBI, AUDIT, BAJU, 클래스 다이어그램 변이 시험)와 여러 AI 판정자가 같이 틀린다는 연구(Kim 2025, Kohli 2026, Kuai 2026)는 모두 **정답이 있는 과제에서, 실행이 끝난 뒤, 판정자 전체를 진단**한다. 이 설계가 묻는 것은 다르다. **정답이 하나로 정해지지 않는 전문 검토에서, 이번 기업의 이번 유형에서 두 AI가 함께 놓친 시험 결과가, 실제로 함께 수용한 판단 가운데 사람이 봐야 할 것을 골라내는 데 쓸모 있는가**를 같은 사람 검토량으로 비교한다. 이번 검색(15회)에서 이 질문을 다룬 연구는 찾지 못했다. 다만 오류 심기, 두 검토자 비교, 독립 기대치는 모두 선례가 있으므로 장치 자체를 새롭다고 쓰지 않는다. 예전 초안의 "독립을 가정하지 않는 포획-재포획" 표현은 자동 통과를 전제로 한 것이라, 우선순위 조정으로 바뀐 지금은 쓰지 않는다.

기존 문헌 목록은 12절에 유지한다. 비교할 선행연구의 주장과 범위는 발표에서 인용하기 전에 원문과 발표 상태를 확인한다.

## 7. 성능 검증

### 7.1 원본의 사람 기준표

**개발 사례와 평가 사례를 발행기업 단위로 나눈다.** 개발 사례에서 나타난 문제로 카나리 유형·탐지 기준을 만든다. 평가에 적용할 우선순위 규칙과 중대 기준은 모델 결과를 보기 전에 고정한다. 평가용 사람 기준표는 모델 프롬프트, 검색 자료, 카나리 제작에 제공하지 않는다.

사람 평가자는 **원본 자료만 보고** 실제 판단 항목의 허용 근거, 확인해야 할 쟁점, 원문 위치를 기록한다. 이후 모델 결과와 대조할 때 검토 목록에 들어간 항목과 목록 밖 항목을 모두 채점한다. 평가표의 판단 항목은 다음과 같이 코딩한다.

| 사람 기준표 판정 | 구체적인 기준 |
|---|---|
| 수용 가능 | 원문의 사실과 어긋나지 않고, 선택을 뒷받침할 합리적인 근거가 있음 |
| 중대 쟁점 | 중요한 반대 근거가 빠졌거나 사실을 잘못 적용했고, 결론에 영향을 주거나 미리 정한 주당 평가가액 변화 기준을 넘음 |
| 판정 유보 | 공개자료만으로 적절성이나 중대성을 판정할 근거가 부족함 |

사실·계산 항목의 오류는 원문 대조와 독립 재계산으로 확인한다. 판단 항목에서는 가능한 비교기업이나 이익 기간을 하나로 고정하기보다 **여러 수용 가능한 판단과, 결론을 바꿀 수 있어 확인해야 하는 사항**을 기록한다. 중대 기준은 필수 판단 항목과 주당 평가가액 변화 폭을 함께 고려한다. 예를 들어 절대 변화율 5%는 검토할 후보값이다. 평가 전 팀이 결정한 실제 기준을 기록한다.

판정 유보는 건수와 사유를 남기고, 판정 가능한 항목을 분모로 주요 오류 지표를 계산한다. 여건이 되는 범위에서 판단 항목의 일부를 두 번째 사람이 시스템 결과를 가린 상태로 독립 검토한다. 두 판단이 갈린 경우와 해결 방식을 함께 기록한다.

### 7.2 기준선과 공정한 비교 방법

| 조건 | 원본 항목을 검토 목록에 보내는 방식 | 해석 |
|---|---|---|
| **A0 단독** | A0 자체 지적·이관 결과 | 개선 전 에이전트가 놓치는 쟁점 파악 |
| **A0 + B** | 두 검토자의 판단과 공통 규칙 검사로 정한 필수 항목을 보낸 뒤, 기본 우선순위에 따라 추가 항목 선택 | 독립 검토자를 붙인 효과 |
| **A0 + B + 현실적인 카나리** | 위와 같은 공통 필수 항목을 보낸 뒤, 두 AI가 모두 수용한 항목 중 시험에서 공동 놓침이 있었던 유형의 우선순위를 높여 추가 항목 선택 | 카나리가 검토 순위를 개선하는지 확인 |

**핵심 비교는 두 번째와 세 번째 조건이다.** 같은 기업, 같은 원본 A0 보고서, 같은 검토자 B의 원본 판단, 같은 1층 검사 결과를 사용한다. 필수 검토 항목을 양쪽에 똑같이 배정하고, 나머지에서 **같은 수 K개**를 추가 검토 대상으로 뽑는다. 기본 정렬 기준과 동순위 처리, 검토량 K는 평가 전에 정한다. 가격 영향이 미확인인 항목에는 일관된 보류·정렬 규칙을 적용한다.

예를 들어 공통 필수 검토 이후 두 조건에 각각 추가 검토 20개를 배정한다고 하자. 카나리 없는 조건이 목록 밖에 중대 쟁점 6개를 남기고 카나리 조건이 3개를 남겼다면, 이 표본에서는 **같은 검토량으로 중대 쟁점이 3개 덜 통과했다**고 해석할 수 있다. 평가에서는 이 건수와 함께 기업 수, 판정 가능한 항목 수, 조건별 추가 비용을 보고한다.

보조 비교로 명백한 오류만 사용한 방식, 같은 개수의 항목을 무작위로 고른 방식, 같은 모델 비용으로 A0를 반복 실행한 방식을 둘 수 있다. 원래 프로토콜의 완료율을 비교할 때는 READY 비율이 비슷한 조건도 함께 확인한다.

### 7.3 지표와 기록 단위

| 지표 | 계산·보고 방식 |
|---|---|
| **검토 목록 밖 중대 쟁점 수·비율** | 목록 밖 중대 쟁점 수 ÷ 사람이 판정한 전체 실제 중대 쟁점 수. 같은 검토량에서 비교하며 분자·분모를 함께 보고 |
| 목록 밖 실제 항목의 중대 쟁점률 | 목록 밖에서 중대 쟁점으로 판정된 수 ÷ 목록 밖의 판정 가능한 실제 항목 수 |
| 카나리 탐지 수별 실제 쟁점률 | 두 AI가 원본에서 모두 수용한 실제 항목을 해당 유형의 탐지 0·1·2명과 시험 미확인으로 나눠 실제 쟁점률 비교 |
| 유형별 공동 놓침률 | 유효한 해당 유형 시험 중 두 검토자 모두 놓친 비율. 표본이 적으면 건수 중심으로 보고 |
| 독립 가정 대비 공동 놓침 | 실제 공동 놓침률을 A0 놓침률과 B 놓침률의 곱과 비교. 한쪽 놓침률이 0이면 배수는 계산하지 않음 |
| 정합성 및 오경보 | 실제 쟁점과 카나리 유형이 연결되는 비율, 해당 유형의 정상 대조본에 붙인 근거 없는 경고 비율 |
| 검토 부담과 AI 비용 | 사례당 필수·추가 검토 항목 수, 모델 호출·토큰·실행 시간 |
| READY의 핵심 오류율 | 기존 프로토콜의 상태별 오류 지표로 보고 |
| 후속 정정 적중 | 실제 정정된 항목 중 쟁점·사람 확인 목록에 들어간 비율을 보조로 보고 |

같은 기업의 여러 항목에는 같은 시험 결과가 적용될 수 있다. 결과표에서 항목 수와 독립 기업 수를 함께 보여주고, 불확실성도 기업 단위로 해석한다. 중대 쟁점이 관측되지 않은 평가 묶음에서는 분모가 0임을 표시한다.

[v3] 실행 중 중대 판정(3.2절 ⑥)과 사람 기준표의 중대 쟁점이 어긋난 항목 수, 같은 카나리를 반복 실행했을 때 탐지 결과가 바뀐 비율도 이 표에 함께 넣는다.

### 7.4 자동 통과를 검토할 조건

파일럿에서는 **공동 놓침에 따른 우선순위 조정**을 적용한다. 탐지 1명과 2명은 별도 기록으로 남긴다. 카나리 성공을 통과 근거로 쓰는 규칙은 다음 내용을 확인한 뒤 검토한다.

- 같은 검토량에서 카나리를 붙인 쪽이 **실제 중대 쟁점을 덜 흘려보냈는지** 확인했다.
- 특정 기업 한 곳에 결과가 몰리지 않고, 관련 유형에서 탐지 0·1·2명의 차이를 판단할 만큼 자료가 있다.
- 정상 대조본의 오경보와 실제 미탐을 확인해, 탐지 성공이 쉬운 단서나 모든 항목에 경고하는 행동에서 나온 경우를 구분했다.

이 근거가 부족하면 우선순위 조정 방식으로 결과를 제시한다. 자동 통과 규칙을 새로 제안할 경우 개발 자료로 조건을 정하고, 본 실험과 구분되는 새 기업 사례에서 확인한다.

### 7.5 [v3] 표본 크기와 검정력 보강

**문제.** 7.2절의 핵심 비교는 "같은 검토량에서 목록 밖에 남은 실제 중대 쟁점 수"다. 그런데 ① 카나리 신호는 (기업, 유형) 단위라 평가 기업이 12곳이면 관측 단위도 12개 안팎이고, ② 예전 파일럿에서 판단 항목이 모두 만점이었듯 실제 중대 쟁점은 기업당 0~1개일 수 있다. 그러면 두 조건의 차이가 0~2건으로 나와 해석이 어렵다.

**보강 1. 파일럿에서 기저율부터 잰다.** 개발 기업에서 사람 기준표로 판정한 실제 중대 쟁점이 기업당 몇 개인지 센다. 이 값으로 평가 기업 수를 다시 정한다(멘토 P3의 "반복보다 기업 수"와 같은 방향).

**보강 2. 평가용 심은 쟁점을 따로 둔다.** 평가 기업마다 원본 사본에 같은 유형의 현실적인 오류를 하나 더 넣은 **평가용 원본**을 만든다. 이 오류는 신호용 카나리와 **다른 후보 기업**으로 만들고, 사람 평가자만 위치를 안다. 그 뒤 7.2절과 같은 방식으로 "같은 검토량에서 평가용 쟁점이 검토 목록에 들어갔는가"를 두 조건에서 비교한다.

| 구분 | 신호용 카나리 | 평가용 심은 쟁점 |
|---|---|---|
| 역할 | 두 AI가 이 유형을 함께 놓치는지 재는 시험 | 우선순위 규칙이 사람 검토량을 제대로 배정했는지 재는 정답 |
| 들어가는 곳 | 별도 변형본 | 평가용 원본 (실제 항목과 함께 섞임) |
| 만드는 후보 | 후보 풀에서 하나 | 다른 후보 하나 (같은 기업을 두 번 쓰지 않음) |
| 해석 한계 | 4절 | 같은 유형끼리 만든 것이라 자연 쟁점보다 결과가 좋게 나올 수 있음 |

평가용 심은 쟁점의 결과는 **자연 쟁점 결과와 합치지 않고 따로** 보고한다. 비용은 기업당 A0·B 실행 2회가 늘어난다.

**보강 3. 분석은 기업 단위 짝 비교로 한다.** 같은 기업에서 두 조건을 비교하므로, "카나리 조건이 더 적게 놓친 기업 수 / 더 많이 놓친 기업 수 / 같은 기업 수"와 총 건수를 함께 보고한다. 기업 12곳으로는 큰 효과만 구별할 수 있으므로, 결론은 "효과가 있다/없다"의 확정이 아니라 **효과 크기의 추정과 후속 검증 필요 여부**로 쓴다.

| 11.2, 11.3 | 같은 검토량의 두 기준선, 목록 밖 실제 항목의 채점, 공동 놓침·오경보·비용 지표 |
| 13 | 개발 실패와 카나리 유형 연결, 평가 기준표와 시험본·모델 입력 분리 |
| 3.4, 12 [v3] | 정렬 규칙(1~3순위, 동순위) 사전 고정, 실행 중 중대 판정 규칙, 평가용 심은 쟁점의 제작·보고 분리, 기업 단위 짝 비교 |

실행 기록에 사례 ID, 원본·변형본 구분, 변형 ID, 유형, 출처, A0·B 개별 판단, B의 후보별 근거, 탐지 판정, 가격 영향, 실제 항목의 이관 사유를 남긴다. 변형본 정답과 실제 항목 평가표는 실험 운영과 사후 채점에만 사용한다.

## 9. 멘토링 피드백 반영

| 피드백 | 반영 내용과 남은 일 |
|---|---|
| 기준표 작성·A1 설계·채점을 한 사람이 맡는 구조 | 역할 분리안은 규리가 원본 기준표와 1차 채점, 원준이 A1 설계와 2차 사실 검토다. 판단형 카나리의 근거·채점 기준은 모델 실행 전에 서로 확인하고, 원본 평가표는 구현·카나리 제작에 제공하지 않는다. 팀 확정이 남아 있다. |
| 사실·계산과 판단을 구분 | 1층 규칙 검사와 2층 판단 비교를 구분했다. 판단형 시험에서는 근거 있는 쟁점 발견을 채점한다. |

| 독립 단위와 주장 범위 명시 | 발행기업이 단위다. 한 기업의 원본·변형본·항목·반복은 사례 내 관측으로 취급한다. |
| 채점 완료된 파일럿 1건 제출 | 원본 기준표, A0·B의 출력, 시험용·정상 대조본 채점 결과를 한 사례 묶음으로 만든다. |
| [v3] 기업 수 우선 (P3 세부) | 카나리·평가용 심은 쟁점은 같은 기업의 변형이라 독립 기업 수를 늘리지 않는다. 파일럿에서 잰 카나리 제작 시간과 자연 쟁점 기저율로 평가 기업 수를 다시 정한다(7.5절). |
| [v3] 읽을거리 FinanceBench | 1층(사실·계산)은 FinanceBench처럼 정답이 있는 공시 질의와 같은 성격이다. 우리 연구의 질문은 정답이 하나로 정해지지 않는 2층에 있다(6절). |

## 11. 팀 결정과 파일럿 순서

### 팀이 정할 것

- 검토자 B의 모델과 A0·B가 공통으로 쓸 후보 자료 양식. 기존 A0 설정은 GPT-6.1 Terra이며, B는 다른 제공사의 모델을 쓰는 안을 파일럿에서 검토한다.
- 첫 시험 유형, 탐지 기준, 정상 대조 선정 기준.
- 가격 영향의 중대 기준, 검토 우선순위 기본 정렬과 추가 검토량 K.
- 정밀·절약 모드의 기본값과 비용 상한.
- 역할 분리, 판단 항목의 2차 평가 범위, 기존 영향 기반 되감기 관문의 후속 적용 여부.

### 파일럿 실행

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 개발 기업 한 곳에서 최초 신고서와 원문 위치를 확보하고 사실·판단 기준표 작성 | 수용 가능, 중대 쟁점, 판정 유보를 근거와 함께 기록 |
| 2 | 같은 기업으로 현실적인 카나리 1건과 정상 대조 1건 작성. 명백한 오류는 기본 작동 확인용으로 추가 가능 | 원본 대비 수정 내역, 관련 산식·근거, 예상 탐지·오경보 기준 사전 확정 |
| 3 | A0와 B를 원본·각 변형본에 별도 실행 | 두 모델의 판단·근거, 정보 차단 여부, 탐지·오경보를 기록 |
| 4 | 원본을 같은 검토량으로 재정렬해 A0+B와 A0+B+카나리 비교 | 누가 무엇을 잡았는지와 목록 밖 쟁점이 어느 조건에서 남았는지 확인 |
| 5 | 프롬프트·채점 기준·구성 비용을 검토하고, 새 기업에 적용할 규칙 고정 | 파일럿은 작동과 채점 가능성을 확인. 실제 쟁점 누락 감소는 후속 평가 기업에서 검증 |

멘토 공유 묶음에는 원본 기준표, 채점한 파일럿 1건, 현실적인 카나리·정상 대조의 설계 근거, 역할 분리안과 같은 검토량 비교표를 포함한다.

[v3] 2번에서 시간이 허락하면 현실적인 카나리를 **2개 이상**(가능하면 다른 개발 기업 하나에서 1개 더) 만든다. 카나리가 1개뿐이면 "파이프라인이 돌아간다"는 것만 알 수 있고, 아래 진행·중단 기준의 2번을 판단할 수 없다.

### [v3] 파일럿 진행·중단 기준

파일럿이 끝나면 아래 네 가지를 보고 본 실험으로 갈지, 설계를 바꿀지 정한다. 기준은 파일럿 결과를 보기 전에 팀이 확정한다.

| # | 확인할 것 | 진행 | 설계 변경 |
|---|---|---|---|
| 1 | 현실적인 카나리가 두 사람 판정(4.4절 6단계)을 통과하는가 | 대부분 통과 | 통과가 드물면 판단형 대신 적용 이익 같은 사실 쪽 유형부터 시작 |
| 2 | 탐지 결과가 한쪽으로 쏠리지 않는가 | 카나리에 따라 0·1·2명 탐지가 섞여 나옴 | 항상 둘 다 잡으면 카나리를 더 어렵게, 항상 둘 다 놓치면 유형·자료 제공 방식 재검토 |
| 3 | 정상 대조본의 오경보가 관리 가능한가 | 정상 대조에 근거 없는 경고가 드묾 | 경고가 잦으면 B 지시문과 탐지 기준(4.3절) 수정 |
| 4 | 비용과 자연 쟁점 기저율이 본 실험 규모에 맞는가 | 카나리 제작 시간 × 평가 기업 수가 일정 안에 들어오고, 자연 쟁점이 관측됨 | 절약 모드로 전환, 평가 기업 수 조정, 7.5절 보강 2 비중 확대 |

## 13. [v3] 이번 개정에서 바뀐 점

### v2(팀원 개정)에서 그대로 받은 것

v2의 방향은 모두 타당하다고 판단해 본문을 그대로 기준으로 삼았다.

- 카나리 성공을 자동 통과 근거로 쓰지 않고, 공동 놓침을 **사람 검토 우선순위 상향**으로만 쓴다(3.2 ④, 7.4).
- 명백한 이종업종 오류 대신 **현실적인 카나리**를 쓰고, **정상 대조본**으로 오경보를 잰다(4절).
- **같은 사람 검토량**에서 A0+B와 A0+B+카나리를 비교하고, 검토 목록 **밖의** 실제 항목까지 채점한다(7.2).
- 원본 사람 기준표를 수용 가능·중대 쟁점·판정 유보 세 가지로 판정한다(7.1).
- A0 원본 보고서는 고정하고 재계산값·수정 제안·검토 상태는 따로 기록한다(3.3).

v1에 있던 배경·선행연구 비교 절은 v2에서 빠졌다. v3는 이를 되살리지 않고 6절에 발표용 한 문단만 더했다.

### v3에서 더한 것

| 위치 | 바뀐 점 | 이유 |
|---|---|---|
| 0절, 3.2 ⑤ | 카나리 신호의 단위를 **(기업, 오류 유형)** 으로 명시하고, 1~3순위와 동순위 정렬 규칙을 미리 고정 | 공동 놓침이 나오면 그 기업의 같은 유형 항목이 한꺼번에 올라간다. 그 안의 순서가 정해져 있지 않으면 같은 검토량 비교에서 정렬 방식이 결과를 바꿀 수 있다 |
| 3.2 ⑥, 7.3 | 실행 중 "중대" 판정(가격 영향이 사전 기준 이상)과 사람 기준표의 중대 쟁점을 분리하고, 둘이 어긋난 수를 보고 | 같은 기준이 A1 규칙과 채점에 함께 쓰이면 A1이 채점 기준에 맞춰진 것처럼 보이는 순환이 생긴다. 기준값은 규리가 먼저 고정한다 |
| 3.4 | 평가용 심은 쟁점에 드는 실행 비용(기업당 +2회)을 실험 비용으로 따로 기록 | 7.5 보강 2의 비용을 운영 비용과 섞지 않기 위해 |
| 4.2 규칙 7 | 유형당 카나리 2개 이상, 어려우면 같은 카나리 반복 실행 | 카나리 1개는 실행 한 번의 우연에 크게 흔들린다 |
| 4.2 규칙 8, 4.4 | 실제 상장사 자료로 현실적인 비교기업 카나리를 만드는 6단계와 두 사람 판정 | 지어낸 회사는 비현실적인 단서가 되기 쉽다. 제작 시간을 파일럿에서 재야 본 실험 규모를 정할 수 있다 |
| 6절 | 선행연구 대비 위치 한 문단. "포획-재포획" 표현은 쓰지 않음 | v2에서 차별점 설명이 빠져 발표용 문장이 필요했다. 자동 통과가 빠졌으므로 포획-재포획 비유는 더 이상 맞지 않는다 |
| 7.5 | 자연 쟁점 기저율 측정, 평가용 심은 쟁점(신호용과 다른 후보로 제작, 결과 따로 보고), 기업 단위 짝 비교 | 평가 기업 12곳 안팎에 실제 중대 쟁점이 드물면 두 조건의 차이가 0~2건으로 나와 해석이 어렵다 |
| 8절 | 프로토콜 반영 항목 1행 추가 | 위 규칙들을 원래 프로토콜의 어느 절에 넣을지 표시 |
| 9절 | 멘토 피드백 2행 추가(기업 수 우선 세부, FinanceBench) | 카나리는 독립 기업 수를 늘리지 않는다는 점과, 정답 있는 1층과 우리 질문이 있는 2층의 구분을 명시 |
| 11절 | 현실적인 카나리 2개 이상 권고, 파일럿 진행·중단 기준 4개 | 파일럿 뒤 무엇을 보고 본 실험으로 갈지 결과를 보기 전에 정해 두기 위해 |

### 팀이 아직 정할 것 (v3에서 새로 생긴 것)

- 실행 중 중대 기준값(예: 주당 평가가액 5%). 규리가 A1 설계와 독립적으로 먼저 고정한다.
- 평가용 심은 쟁점을 본 실험에 넣을지 여부. 파일럿에서 잰 자연 쟁점 기저율을 보고 정한다.
- 진행·중단 기준의 구체적인 숫자. 표의 "대부분", "드묾"을 파일럿 전에 숫자로 바꾼다.
